# ADR-0009 家庭登录、安全参数与儿童持久会话

- 状态：已接受为实现基线（维护者要求结束 #15）；目标部署性能和正式认证验收待完成
- 日期：2026-11-04
- 相关需求：REQ-002、REQ-007、REQ-009
- 任务：[#15](https://github.com/juanchaopan/education/issues/15)
- 补充：[ADR-0004](0004-api-data-details.md)、[ADR-0006](0006-delivery-environments.md)
- 证据：[本地验证记录及来源](assets/0015-account-evidence.md)

## 背景与范围

试点为最多 10 家庭、约 3 名儿童同时学习。昵称可以跨家庭重复，六位 PIN 需要在线限流与家长恢复；注册 KEY、登录凭据和登录状态不能混为同一件事。维护者明确要求浏览器记住儿童登录，部署新版本后更新页面，并指示“wrap the spike#15 up, commit push and pr”。本 ADR 采用包含这些修订的设计作为实现基线，不将工程默认值表述为维护者逐项指定的数值。

本次交付只有文档和证据；不实现账号、不部署产品。部分本地性能判据未通过，目标资源未知，按 #15 验收要求保留明确复测门槛；结束设计探针不表示生产就绪。

## 候选与决策

| 候选                                 | 取舍                                                               |
| ------------------------------------ | ------------------------------------------------------------------ |
| 全局唯一儿童昵称，或扫描所有家庭 PIN | 不采用；昵称无全局唯一保证，不能通过 PIN 搜索账号                  |
| 家庭码 + 昵称/PIN，短期会话反复登录  | 不采用儿童每 7 天退出的默认值；不符合维护者持久登录要求            |
| 家庭码 + 昵称/PIN + 可撤销持久会话   | 采用；家庭码只定位，首次认证后由安全 cookie 恢复，家长可撤销       |
| 应用保存原始 PIN 并自动填充          | 不采用；应用保留随机会话，表单支持浏览器密码管理器，不保存明文 PIN |

### 注册与首次登录

| 项目     | 实现基线                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 家庭码   | 12 位随机 Crockford Base32（60 bit），唯一约束、分组显示；不授予访问、不列出儿童、不返回家庭资料                                                              |
| 昵称     | 家庭内唯一，允许跨家庭同名；NFKC、trim、Unicode lowercase 后校验唯一，1–12 个字母/数字 Unicode 码点，显示值与规范化字段分开                                   |
| 儿童 PIN | 已确认 6 位 ASCII 数字，允许前导 0，拒绝全相同及明显顺/逆序；用温和中文说明，不影响反复学习或作答                                                             |
| 注册 KEY | 16 位随机 Crockford Base32（80 bit），4 组显示；原文仅生成时显示，SHA-256 存储；未使用时有效 24h，单次消费，可撤销；每家庭最多 1 个未消费 KEY，重发撤销旧 KEY |
| 家长密码 | 15–128 Unicode 码点、最多 512 UTF-8 字节；允许空格、粘贴及密码管理器，不 trim/截断、不强制字符组合，使用本地常见密码拒绝清单                                  |
| 邮件令牌 | 邮箱验证 24h、密码重置 30min，均为 32 随机字节、哈希存储、单次使用；重发撤销同用途旧令牌，恢复申请通用回复；真实投递由 #16 验证                               |

已验证且近期重认证的家长生成 KEY；儿童用 KEY 创建账号并绑定家庭，之后首次/恢复登录用家庭码、昵称与 PIN。**注册 KEY 仅用于关联，账号、家庭关联和进度不因 KEY 或 cookie 到期而失效，不需要家长每 7 天重新发 KEY。**

### 哈希与密钥

采用异步 `argon2@0.45.2`（本地 Node 24、TS7 类型兼容已测），staging 起点 **Argon2id m=32768 KiB、t=3、p=1**，16 字节随机盐、32 字节输出，保留 PHC 参数。原生扩展的 Vercel 打包仍须 #20 验证，不使用阻塞请求线程的同步哈希。

六位 PIN 约 20 bit，Argon2id 不能消除离线穷举。先用独立 `PIN_PEPPER`（至少 32 随机字节）对版本、familyId、childId、PIN 的无歧义编码做 HMAC-SHA256，再 Argon2id；记录 pepper 版本，密钥不进入数据库/日志/仓库，缺失时不回退无 pepper。受控轮换可暂留旧版本、成功登录后迁移；泄漏时撤销相关儿童会话并由家长重置，丢失旧密钥只能重置。pepper 不防应用与密钥同时泄漏。高熵 KEY/会话/邮件令牌用 SHA-256，不额外消耗 Argon2 资源。

#20 在实际部署 Node 24 资源上重测串行/3 并发、排队、RSS、冷启动与数据库耗时：本地哈希 P95 目标 <500ms，3 请求/2 槽含排队 P95 <1s，完整普通操作目标 2s。保留所有慢样本。若 32 MiB 不达标，评审后选择已测的 19 MiB/t2/p1 最低配置之一或自有服务器，不能自动降级或把第二轮较快结果当作全部达标。

### 记住登录、重认证与撤销

| 对象     | 期限和恢复                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 儿童     | 默认保持登录，关闭浏览器/返回/部署刷新后恢复；180 天不活动期限、有效访问后顺延，不另设 7 天绝对退出。180 天是技术默认值，不是学习时间、账户或进度期限 |
| 家长     | 空闲 12h、绝对 7d；未验证家长仅 15 分钟受限会话，无 KEY、儿童或学习数据权限                                                                           |
| 敏感操作 | 最近 5 分钟家长密码验证才可生成/撤销 KEY、重置儿童访问、导出/删除；不只依赖 cookie 年龄                                                               |

使用 32 字节随机 opaque token，数据库仅存哈希；HTTPS `__Host-education_session`，Secure / HttpOnly / SameSite=Lax / Path=/，不设 Domain。儿童显式持久 Expires/Max-Age（180 天），与数据库有效期同步续期；PIN/会话不放 localStorage。正常部署不改变凭据版本、不清空会话，数据库及服务端密钥须跨部署保留。

登录/提权更换令牌，退出立即撤销，家长重置更新 credentialVersion 并撤销旧儿童会话；每次授权检查家庭、版本、期限、撤销状态。家长密码恢复增加家庭 epoch，撤销全家庭会话/有效 KEY。私密模式、浏览器主动清理 cookie、长期不活动或主动退出后需原昵称/PIN，不重新注册。共享设备切换用户先退出；家长可查看和撤销设备会话，实际界面/浏览器恢复待实现验收。

### 枚举、限流与资源准入

以下为小规模试点的可评审实现默认值，按真实误伤及资源测量调整；不是 OWASP 规定的具体数值。

| 范围                    | 上限                                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| 儿童家庭码 + 规范化昵称 | 5 次/滚动 15min、20 次/滚动 24h；哈希前预占每次验证，成功也计数，不以切换 IP 绕过                   |
| 家长规范化邮箱          | 10 次/15min、50 次/24h，恢复通道独立限流                                                            |
| 家庭                    | 认证合计 50 次/15min、200 次/24h                                                                    |
| 来源                    | 30 次/15min、200 次/24h；只信任受控入口的代理地址，IPv6 聚合 /64，验收共享出口误伤                  |
| 试点部署                | 100 次/15min、500 次/24h；未知身份也计入来源/总量                                                   |
| KEY 生成/兑换           | 每家庭生成 5 次/h、20 次/日；每 KEY 兑换 5 次/15min，兑换来源 10 次/15min、50 次/日，再应用全局上限 |
| 哈希                    | 每进程 2 执行 + 4 等待，等待最多 750ms，满/超时 429 + Retry-After；PostgreSQL 跨实例最多 4 个总租约 |

PostgreSQL 服务端时间、固定锁顺序、单个短事务原子预占所有预算/租约；哈希在事务外执行。结束释放租约，30s 过期只在部署能于 15s 内硬终止工作时成立，不能 Promise 超时即释放仍运行的原生任务。平台无法保证硬终止时须重新设计续租/故障回收并真实验证，不能宣称严格全局并发。认证数据库故障返回 503，不跳过授权或限流。

未知家庭/昵称/邮箱准入后执行同档 dummy hash，错误回复相同，不提供登录前孩子列表；不能据此声称已证明 HTTP 时序不可枚举。桶键用独立 HMAC 伪名化，计数最多保留 25h；先检查来源/全局预算，再建立账号桶，限制随机身份造成的存储膨胀。日志不含 PIN、KEY、cookie、原始邮箱或完整请求体。

限流可被用于耗尽他人登录额度；不永久封禁，允许家长经独立已验证恢复通道重置 PIN、撤销会话并清除该儿童计数，不能由儿童或客户端清零。不要求儿童处理困难验证码，登录次数限制不限制已登录后的学习时间。

### 事务和 HTTP 边界

- KEY 条件更新、家庭昵称唯一约束、儿童创建和消费必须同事务；冲突/失败回滚。幂等 ID 绑定原请求内容，重放不能创建第二个儿童或签发新会话；丢失响应后用家庭码/昵称/PIN 登录。
- 哈希完成后，签发会话还须事务核对最新 credentialVersion/家庭 epoch，避免重置与登录竞态留存旧凭据会话。
- 已登录写操作验证会话绑定随机 CSRF token（前端内存、自定义 header）及精确配置的同源 Origin；拒绝缺失/null/异常 Origin，不信任客户端 Host/代理头推导可信来源。登录/注册仅 JSON + 自定义请求头，拒绝跨源 CORS/简单表单，防登录 CSRF。GET/HEAD 不写业务数据；浏览器兼容性实际验证后再调整策略。

### 发布更新与草稿保护

用户要求部署后获取新页面。成功部署生成同一 releaseId 的 HTML、构建与公开 `/version.json`；git push/PR 本身不表示已发布，生产仍手动。

HTML `Cache-Control: no-cache` 重新验证；版本文件 `no-store`，客户端 `fetch cache:no-store`；内容哈希 JS/CSS 可长期 immutable 缓存，私人 API `no-store`。不引入 cache-first service worker。

可见页面每 60s、恢复可见/聚焦/网络时检查版本；相同/失败/无效响应不刷新，退避重试。新版本先确认草稿保存成功再完整 reload，无未保存输入直接更新；离线/保存失败/冲突时保留原输入，显示“更新已准备好，保存后将自动更新”，更新后保持登录。每个目标版本只自动刷新一次；版本/缓存不同步、旧 chunk 不可用或回滚时保留草稿和会话，显示可重试状态，不无限刷新。

## 证据、后果和后续验收

本机 17 组、1,020 次正式 hash/verify，19 个场景通过及 TS7.0.2 编译通过。32 MiB 首轮两槽 hash P95 **1,163.69ms** 超过 1s；确认轮为 254.10/246.77ms。64 MiB 亦超标；没有删去慢样本。本地 CPU/内存充足，不能代替 Vercel、数据库、浏览器或大陆测试。
