# ADR-0017 老师回答提问不配讲解动画

- 状态：不采用动画讲解；老师的回答只有文字和语音。
- 日期：2026-11-10
- 需求：REQ-003、REQ-004。
- 任务：[#173](https://github.com/juanchaopan/education/issues/173)
- 关系：模型与接入方式沿用 [ADR-0011](0011-openai-tutoring-model-spike.md)；逐题教学设计沿用 [ADR-0013](0013-per-problem-interactive-teaching.md)。

## 背景

孩子在每一幕都可以按住按钮问老师，老师回一句文字（`TeachingFeedback.instruction`）。维护者曾希望老师也能在题目画面上用动画讲解，例如圈出道具、再称一次给孩子看、演示一步。`/change` 定下的待验证方向是：题目作者为每一幕写一份讲解清单，模型只能挑一段或不挑；作答那一幕只放不泄露答案的讲解。#173 用菜园天平题验证这个方向挑得准不准、慢多少、贵多少。

## 决策

不在题目画面上为老师的回答演示动画。老师对每个提问都只用文字和语音回答：现在显示文字，语音回答随后续的实时语音需求再定。题目作者不为每一幕写讲解清单，模型的结构化输出也不加讲解 id。

维护者的理由：

- 孩子会问什么无法预料，一份写好的清单盖不住真实的提问。
- 题目会从 PDF 批量导入，没法为每道题的每一幕都写全、写对讲解清单。

## 被否决的方案

- **作者写清单、模型从中挑一段**：#173 实测准确率 76.7%，低于 85% 的标准；即使改进说明能提高准确率，清单的编写量和正确性也随题目数量增长，批量导入时做不到。
- **按固定顺序播放讲解**（不由模型挑，按幕依次放作者写好的动画）：同样要为每一幕写讲解，也不能回应孩子实际问的问题。

## 证据

[#173 证据](../evidence/173/README.md)：菜园天平七幕各写 4–5 段讲解，30 个合成提问（含跑题、听不清、要答案），用应用的真实网关和 `gpt-6-luna` 各跑一次讲解版和文字版，共 60 次调用。

- **准确率**：维护者判定挑对 23/30 = 76.7%（标准 ≥ 85%）。7 次错里 4 次是模型把提问当成看不懂的作答，只反问不挑讲解；另有 6 次讲解挑对了，文字却是反问。根源是复用了作答反馈的说明（「看不懂时用 uncertain，只问一个澄清问题」）。作答那一幕 9 次里 7 次挑了清单第一项，有偏向第一项的迹象。
- **泄露**：作答那一幕 9 条回答连同讲解都没有说出或确认答案，达标。严格 schema 下没有出现清单外的 id；30 次里有 1 次回复不合格式。
- **耗时**：完整回复 p95 讲解版 2074 ms、文字版 1887 ms；同一问题两版配对相差 p95 +770 ms，在 1 秒的标准内。
- **费用**：输入 token 多 63%，每次费用多约 45%（约 0.11 美元/千次对 0.077 美元/千次）。
- **原型**：在真实菜园舞台上做了两段可点的讲解（依次圈出三组黄瓜、重播一个苹果和三根黄瓜的称量），录屏在证据目录。探针代码只在 `spike/173-teacher-demos` 分支，没有合入 `apps/`、`libs/`。

同一次测量还发现，应用现有的文字回答在孩子问「答案是九对不对？」时开头说「对」，确认了孩子猜的答案。这与动画讲解无关，另开 bug issue 处理。

## 后果

- 题目插件和题目定义不增加讲解清单；导入新题时不需要为每一幕编写动画讲解。
- [逐题设计互动教学与验收手册](../design/interactive-lesson-authoring.md) 写明老师的回答不配讲解动画。进题后随时开口、和老师用语音对话仍是后续需求，按原计划先评估实时语音。
- 以后若重新考虑画面讲解，需要先解决讲解内容怎样随题目自动生成且可验收，不能依赖逐幕手写清单。
