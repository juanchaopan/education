# ADR-0004 API、账号与数据库细节

- 状态：主要选择已接受；账号安全基线见 ADR-0009，实际部署/事务验收待完成
- 日期：2026-11-04
- 相关需求：REQ-002、005、006、008、009

## 背景与候选

Fastify 适合输入 schema 校验与接口测试；NestJS 提供更重的模块约定；托管认证减少密码管理工作但增加大陆网络依赖。PostgreSQL 适合事务、唯一约束和未来多实例；SQLite 更适合已有持久磁盘的单服务器。Drizzle 接近 SQL，没有单独查询引擎。

## 决策

用户已选择 Fastify、TypeBox、PostgreSQL、Drizzle，应用管理家长邮箱/密码、儿童昵称/PIN 和安全 cookie 会话。TypeBox 提供边界 schema，所有授权由后端执行；数据库迁移由受控发布步骤单独运行，不由每个 API 实例启动时同时运行。

建议 routes → services → repositories → domain 分层。应用服务定义事务边界，domain 不依赖数据库。跨模块交互通过启动时注入的显式能力接口，业务模块不直接导入彼此仓储；接口在 shared/contracts 定义、实现由组合根组装，避免绕过规范库的功能隔离。

KEY 兑换使用哈希与事务条件更新，一次兑换只产生一个儿童；有重复请求 ID 时返回原结果或明确状态，不创建第二个儿童。PIN 不能全局搜索匹配，先确定家庭或设备上下文；首次使用家庭码、昵称与 PIN 认证，之后默认用可撤销持久 cookie 恢复儿童登录。家庭码本身不是访问授权；KEY 不作为后续登录密码。

[ADR-0009](0009-account-security-spike.md) 接受异步 Argon2id 32 MiB/t3/p1 作为 staging 起点，并以独立 pepper 保护低熵 PIN；具体参数仍须按实际部署资源复测，哈希任务必须限制并发，防止低成本机器被登录尝试耗尽。KEY、会话、邮箱验证和密码重置令牌使用安全随机值并哈希存储；邮箱是否存在不通过登录或重置响应泄露。短 PIN 依赖服务端按家庭、账号与来源限流及渐进延迟，不依赖哈希强度弥补低熵。

建议用数据库保存会话、限流窗口和用量预留，避免扩容时进程内状态失效。低规模试点不引入 Redis。导出与删除、家长 PIN 重置需近期家长身份验证；重置撤销旧儿童会话。邮箱验证、密码恢复与邮件投递真实可用后才称账号链路就绪。

## 证据与后果

技术选择已获用户确认；#15 的设计结论、1,020 次本地哈希测量、19 个规则/哈希场景和 TS7 编译见 [ADR-0009](0009-account-security-spike.md)。32 MiB 首轮排队超标，没有目标部署/事务/真实邮件验收；不能把探针当作正式认证实现。应用自管账号意味着我们承担密码恢复、限流、会话撤销和依赖升级。测试工具已确认：Vitest 与 Playwright；具体采用 Fastify inject、真实隔离 PostgreSQL 验证接口和数据语义；真实数据库覆盖并发 KEY、家庭越权、幂等、重置与删除，不用 mock 查询证明事务正确。
