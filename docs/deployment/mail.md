# 家长账号邮件

实现/证据与边界见 [#21](../evidence/21/README.md)。应用默认关闭真实发信；当前隔离 staging 已启用并完成真实验证登录，详见验收记录。注册回执明确未发送，登录后才能主动发送验证邮件。

## 启用前

1. 核实并记录实际 Google 账号用途/资格、当前额度、超额及风控恢复、应用密码要求。2026-11-05 维护者提供了[个人 Gmail 发信限制](https://support.google.com/mail/answer/22839)和[应用密码](https://support.google.com/accounts/answer/185833)的展开正文，核对结果见 [#21 供应商说明](../evidence/21/README.md#gmail-供应商说明)。开发环境访问官方帮助页仍被代理拒绝，来源为维护者复制的正文，不声称独立抓取或获得 Google 业务批准；[Google 条款](https://policies.google.com/terms)仍适用。
2. 使用专用个人 Gmail 发件地址，启用两步验证并创建新的应用密码。权限不是只允许发送的细粒度凭据，账号发件箱及供应商留存仍受 Google 条款影响。
3. 在 GitHub Actions 配置以下值。密码和密钥仅保存在 Secrets，不进入前端、仓库、聊天或日志：

| 名称                         | 位置      | 内容                                                            |
| ---------------------------- | --------- | --------------------------------------------------------------- |
| `STAGING_GMAIL_USER`         | Variables | 完整的专用 `@gmail.com` 发件地址                                |
| `STAGING_GMAIL_APP_PASSWORD` | Secrets   | 新的 16 位应用密码，去掉显示空格                                |
| `STAGING_MAIL_PAYLOAD_KEY`   | Secrets   | 密码管理器生成的 64 位十六进制随机值（32 字节），独立于其他密钥 |

4. 供应商核实完成后，设置 Actions Variables `STAGING_MAIL_PROVIDER_APPROVED=true` 和 `STAGING_MAIL_ENABLED=true`，手动运行 main 的 staging workflow。缺配置或核实开关会拒绝候选发布；不能为了部署成功跳过校验。生产不自动启用。

发布脚本只向候选服务端环境传递必要配置；应用使用 `MAIL_ENABLED`、`MAIL_PROVIDER_APPROVED`、`GMAIL_USER`、`GMAIL_APP_PASSWORD`、`MAIL_PAYLOAD_KEY`。候选的随机 `@example.invalid` 账号冒烟不会发送邮件，因为注册和登录本身不会发信；验证邮件须登录后显式请求，恢复邮件由 `/family/recover` 的显式申请触发。

## 验收与恢复

用维护者控制的家长邮箱在稳定 staging 注册、登录、发送、查收，并点击正式确认按钮。确认邮箱状态和重新登录权限；重复使用、重发旧链接、冷却和服务故障均有明确恢复说明。只记录合成编号、状态、耗时和收件人确认，不记录真实地址、链接令牌、邮件原文或密码。

`accepted` 不代表已送达。授权失败时恢复 Google 授权/更新应用密码后重新部署；明确暂时拒绝可在冷却后安全重试，最多三次。unknown 请先查看收件箱，没有收到时由家长明确重发，旧链接失效。没有后台隐式发送或内存队列。

每小时 `staging-mail-retention` workflow 清理过期加密载荷；查看 Actions 是否持续成功，故障恢复后可手动运行。定时工作可能延迟，不能承诺精确物理 TTL。所有权限和到期判定由数据库强制，与维护频率无关。自管服务器需以同等频率运行相同清理逻辑并监控失败。

该任务也清理到期的学习草稿。草稿在最后一次成功保存有效编辑的 168 小时后即无法读取，即使定时清理延迟。任务只记录清除条数。其他部署环境应在对应数据库中定期运行 `cleanupExpiredDrafts` 并监控失败。

关闭：将 `STAGING_MAIL_ENABLED=false` 后重新部署，原账号/进度不删除，页面显示尚未开放。禁用时验证 POST 也关闭。`MAIL_PAYLOAD_KEY` 跨部署保持稳定；更换会让旧的待重试载荷不可解密，现有已发链接仍按哈希有效期工作，家长可以明确重发生成新意图。不要将更换密钥作为每次部署步骤。

## 回退

可关闭发信并回退应用。迁移仅新增验证/尝试表，旧程序不使用它们；不删除父账号或回滚数据库来撤销发信。需要撤销链接时仅撤销对应验证意图，不能清空所有家庭。数据库恢复与已删除资料的处理仍由后续备份任务负责。

## 家长密码恢复（#22）

复用上表全部配置。`MAIL_ENABLED=false` 时验证与恢复都关闭；未增加秘密或付费服务。恢复申请无需登录，只向数据库中与申请邮箱对应的家长发信，不接受独立收件人、模板、Origin 或链接地址。真实 staging 恢复闭环已获维护者确认，精确部署、CI/清理任务与未手工重测的边界见 [#22 记录](../evidence/22/README.md)。

1. 登录页点“忘记密码”，输入注册邮箱，点“发送恢复邮件”。所有合法邮箱申请都返回相同 `requested` 回执，包括不存在、冷却中、达到限额和投递失败；这不表示邮件送达。
2. 申请采用统一 20 秒最短响应时间，这是当前工程隐私折中而非 Gmail/Vercel 要求，即使邮件已先到达也会等满；覆盖健康 SMTP 的常见耗时差异，不占用数据库连接/哈希准入槽等待补齐时间。客户端等待最多 30 秒，Vercel 函数上限维持 30 秒。异常数据库延迟可能超出最短时间；这不是所有故障下严格恒定时间或普通操作 2 秒目标的达标证据。普通登录、退出和最终重置没有这段等待。
3. 邮件按钮和备用链接均可点击。令牌为 32 随机字节，放 URL fragment，页面挂载后清除地址中的 fragment，仅在内存保存。GET/HEAD/打开页面不改账号。重新打开邮件可恢复尚未提交的令牌，刷新后需从邮件重开。
4. 提交符合现有 15–128 字符、最多 512 字节策略的新密码，并确认两次输入一致。服务端只信任随机令牌，不信任客户端提供账号。30 分钟到期/已使用/被重发替代的链接不能修改账号。成功后不自动登录，清除当前 cookie 和前端账号缓存，使用新密码重新登录；未验证账号不会因此自动获得已验证权限。
5. 未收到时先查收件箱/垃圾箱，至少等 60 秒。“重试同一封邮件”只适用于服务商明确暂时拒绝且载荷仍有效的情况，保留同一令牌，含首次最多三次。授权失败、永久拒绝或未知结果不盲目重试；确定需要新链接时点“重新发送（旧链接失效）”。同一有效申请的重复初次请求不会重复发送。页面不披露真实账号/投递状态，因此按钮出现不表示服务端一定可重试。

验证与恢复分别有每家长 5 次/滚动 24 小时、60 秒冷却，共用全站 50 次/滚动 24 小时、10 次/15 分钟邮件预算和同一数据库事务锁；实际预留、重试和中断发送都计数。恢复请求的全站/来源/邮箱尝试预算与登录分开，但共用已有的有界本机及跨实例资源准入，不让恢复请求耗尽所有数据库连接。短期 HMAC 尝试记录不保存原始邮箱/IP。

确认重置在同一事务中更换 Argon2id 密码、增加家长凭据版本与家庭 epoch、删除全家庭家长旧会话和未使用注册 KEY、使全家庭未消费验证/恢复令牌失效。登录签发会核对最新密码哈希、版本和 epoch，旧密码验证与重置竞态不能签出可用旧会话。儿童会话接口尚未实现，后续必须同样核对家庭 epoch；这里不声称已验证儿童登录。

待投递令牌使用已有独立密钥 AES-256-GCM 保护。SMTP 接受、未知/永久/授权失败、重试耗尽、重置和过期清理会清除载荷。临时拒绝最多保留至 30 分钟有效期，读取/重试会拒绝过期，小时维护清除到期载荷（物理清理可能晚于有效期最多一个调度间隔，调度故障另计）。令牌哈希/最后意图行仅用于账号安全状态，不长期保存明文令牌、密码或邮件正文。

运维诊断只查看 `password_resets` 的聚合状态/数量，不输出邮箱、原始链接或载荷。授权失效时更新应用密码并发布；配额受限遵循 Gmail 恢复说明，不能以重试绕过额度。受控 SMTP 的授权/4xx/5xx/超时/DATA 后断连是本地故障证据，未对真实 Gmail 故意耗尽额度或撤销凭据。

回退：关闭邮件开关可停止两类发信；回退应用需重新构建并按原发布流程验证。迁移 0004 只加表，旧版本可继续运行，保留新表/哈希/epoch 和现有数据库，不回滚密码或已撤销会话。回退旧应用时恢复邮件计数不再参与旧版验证预算，必要时关闭邮件到修复发布，避免额度交叠。
