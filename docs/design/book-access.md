# 孩子只学安排的书，访客看不到题目

- 状态：草稿，待维护者确认。规则是维护者 2026-11-12 在 [#221](https://github.com/juanchaopan/education/issues/221) 定下的：没有自由复习，孩子只能学家长安排给自己的书，没登录的访客什么都看不到。需求文字、接口的回答和每张样稿都还要维护者确认。
- 需求：REQ-001、REQ-009（改动见[需求改动](#需求改动)），REQ-002、REQ-010。样稿见 [#221 记录](../evidence/221/README.md)，变更原因见 [变更记录](../changes/2026-11-12-book-access.md)。
- 涉及：`libs/contracts`（题库和拒绝的回答）、`apps/api`（题库、题目和题目下面全部接口的访问检查）、`apps/web`（首页、题目页、孩子登录后回到题目、家长书架的空状态）、`e2e`、`visual`。书、书的状态和安排沿用 [家长书架与按书安排练习](bookshelf.md)。

## 为什么要改

现在首页 `/` 是公开题库，谁都能浏览全部题目；题目页对访客也打开，访客能看完短片，只是不保存进度。题目详情接口 `GET /api/v1/problems/:id/:version` 和题库接口 `GET /api/v1/problems` 不看登录。作答、草稿和提问这些接口要孩子登录，但不看这道题所在的书有没有安排给这个孩子。

之后：

- **访客**（没登录孩子账号，包括只登录了家长账号的浏览器）在首页只看到家长注册、家长登录和孩子登录的入口；打开题目链接只看到「登录后才能打开这道题」。
- **孩子**只看到、只能打开安排给自己的书里的题。没安排的书和题由服务端拒绝，不只是页面上不列。
- **暂时不可用的书**：孩子看到置灰的书，写「暂时不可用」，题打不开，和家长书架一致。
- 家长取消安排后，这本书从孩子的题库里消失；进度不清零，重新安排后接着原来的进度（#179 的规则不变）。

## 谁能打开什么

| 谁                               | 首页 `/`                                 | 题目链接 `/problems/:id/:version`                       |
| -------------------------------- | ---------------------------------------- | ------------------------------------------------------- |
| 访客                             | 入口页：孩子登录；家长登录、创建家长账号 | 「登录后才能打开这道题」，孩子登录后回到这道题          |
| 只登录了家长账号                 | 入口页，家长那一块换成「进入家长空间」   | 「请孩子登录后打开这道题」，孩子登录后回到这道题        |
| 登录的孩子                       | 「我的题目」：安排给自己的书里的题       | 按[服务端的检查](#服务端的检查)打开，或说明为什么打不开 |
| 同一个浏览器里孩子和家长都登录着 | 按孩子                                   | 按孩子                                                  |

家长账号不打开题目：家长书架这一版不列书里的题（#179），家长要看题就请孩子登录。

## 服务端的检查

### 一道题能不能打开

孩子会话确认以后，按下面的顺序判断，第一条成立就停：

| 顺序 | 情况                             | 结果          |
| ---- | -------------------------------- | ------------- |
| 1    | 题目或这个版本不在题目清单里     | `missing`     |
| 2    | 这道题所在的书没有安排给这个孩子 | `unassigned`  |
| 3    | 书暂时不可用                     | `unavailable` |
| 4    | 其余                             | `open`        |

- 「安排给这个孩子」只看会话里的孩子在 `book_assignments` 里有没有这本书的一行，不看兄弟姐妹，也不看家长；孩子的接口里没有孩子 id，跨孩子、跨家庭只能落到 `unassigned`。
- 没安排又暂时不可用的书算 `unassigned`：没人安排过的不可用书，孩子本来就看不到。
- 题目的版本仍按题目清单：清单里有的版本都能打开，书里列的是最新版本。
- 判断是不依赖数据库的纯函数（`apps/api/src/learning/domain/problem-access.ts`），输入是题目清单里的题和书、这个孩子安排了的书 id；安排由现有的 `readBookAssignments` 读，不加新表、不加迁移。

### 哪些接口检查什么

| 接口                                                                                                       | 没有孩子会话 | CSRF 不对 | `missing` | `unassigned` | `unavailable` | `open` |
| ---------------------------------------------------------------------------------------------------------- | ------------ | --------- | --------- | ------------ | ------------- | ------ |
| `GET /api/v1/problems`（孩子的题库）                                                                       | 401          | —         | —         | 不列         | 列出，带状态  | 列出   |
| `GET /api/v1/problems/:id/:version`（题目详情）                                                            | 401          | —         | 404       | 403          | 403           | 200    |
| `GET`、`POST /api/v1/problems/:id/:version/answer`、`/draft`                                               | 401          | 403（写） | 404       | 403          | 403           | 照现在 |
| `POST /api/v1/problems/:id/:version/question`、`/feedback`、`/transcription`（向老师提问、讲解、语音转写） | 401          | 403       | 404       | 403          | 403           | 照现在 |

- 检查顺序：先孩子会话和 CSRF（照现在），再判断这道题能不能打开，最后才是各接口自己的逻辑；`missing`、`unassigned`、`unavailable` 时不读写草稿、作答和用量，也不调用 AI。
- 只登录家长账号时和访客一样回答 401：这些接口只认孩子会话。
- 题库和题目详情的回答都带 `Cache-Control: no-store` 和 `Vary: Cookie`，不让浏览器或中间的缓存把一个孩子的回答给另一个人。
- 家长的书架、安排、导出和删除接口不变（#179 里已经按家长会话和家庭检查，别的家庭的孩子回答 404）。

### 回答

| 状态 | 回答体                                                            | 什么时候                       |
| ---- | ----------------------------------------------------------------- | ------------------------------ |
| 401  | `{ message: '登录已失效，请重新登录。' }`（和现在的孩子接口一样） | 没有孩子会话、会话过期或被撤销 |
| 403  | `{ message: '请刷新页面后重试。' }`（照现在）                     | 写请求的 CSRF 不对             |
| 403  | `{ message: '这本书还没有安排给你。', reason: 'unassigned' }`     | 书没安排给这个孩子             |
| 403  | `{ message: '这本书暂时不可用。', reason: 'unavailable' }`        | 书安排了但暂时不可用           |
| 404  | `{ message: '这道题或这个版本暂时不可用。' }`（照现在）           | 题目或版本不存在               |

- `reason` 只在拒绝打开一道题时出现，契约是 `libs/contracts` 里的 `ProblemAccessDenied`；页面按 `reason` 选提示，不靠比较文字。`RequestError` 多一个可选的 `reason`，错误处理把它放进回答体。
- 拒绝时不说明书名，也不说明这本书安排给了谁。
- 访客在服务端先落到 401，题目存不存在都一样，访客不能用接口一道道试出题目清单。

### 孩子的题库

`GET /api/v1/problems` 只回答登录的孩子：

```text
{
  problems: [ProblemSummary],                 // 安排给这个孩子的书里的题，每道题最新版本，按书再按 sequence
  categories: [{ grade, subject, category, status }]   // 安排给这个孩子、有已发布题目的书，status 是 available 或 unavailable
}
```

- 暂时不可用的书和它的题也列出来，页面置灰；排在可用的书后面。
- 还没有安排时 `problems` 和 `categories` 都是空的。
- `categories` 每项多了 `status`，`CatalogCategory` 的契约随之改变；题目摘要不变。

### 深链接

- 题目链接（例如家长转发给孩子的）对谁都可以打开，打开以后按上面的表画。
- 「孩子登录」去 `/child?next=<这道题的地址>`；孩子登录成功后，`next` 合乎 `/problems/<题目 id>/<版本>` 的写法就换到那里（替换历史记录），否则留在孩子空间。`next` 只接受站内的题目地址，其他地址一律忽略，不会把孩子带到别的网站。
- 孩子登录后回到题目，再由服务端判断能不能打开；没安排就是「这道题不在你的书里」。
- 「第一次来？用家长给的 KEY 注册」也带上 `next`：注册成功后回到孩子登录时照样带着。

### 家长书架

书库为空时，现在靠题库接口区分「书在路上」（题目清单里一本书也没有）和「书库里的书都安排出去了」。题库接口只回答孩子以后，改成看我的家庭：书库和我的家庭都是 0 本才是「书在路上」。只改页面，接口不变。

## 不受保护的部分

课堂的代码（台词、分镜规则、画法）和绘景是网站的静态文件，按需下载，不经过登录检查；直接猜到文件地址的人能下载它们。访问规则管的是页面和接口：页面不给访客画题目，接口不给访客和没安排的孩子题目、作答、草稿和 AI。判对错的规则和提示只在服务器上，不在静态文件里。要连静态文件也挡住，需要让 API 带着登录检查发课堂代码，部署方式要变，不在本次范围里。

## 实现要点

- `apps/api`：先做一个不改行为的重构，让题目下面的接口（作答、草稿和三个 AI 接口）都从同一个「孩子 + 题目」的入口进来（`child-problem-transaction.ts`），现在它只确认孩子会话；之后访问检查只加在这个入口里，题库和题目详情也从它进来。`catalog` 功能不依赖 `learning`，由外层的组装文件把带检查的读取函数交给题库路由。
- `libs/contracts`：`ProblemAccessDenied`；`CatalogCategory` 加 `status`。
- `apps/web`：`features/library` 的首页按会话分成访客入口和孩子的题库两个页面组件；`ProblemPage` 先看会话，再按回答选提示；孩子登录读 `next`；课堂请求的 403 交给题目页重新请求详情。`LessonScreen` 的 `csrf` 变成必有。
- 题目页的 `LessonRoute` 和 #210 的课堂记录都改这一带，合并时按顺序处理。

## 测试

- 判断能不能打开：上面顺序表的每一行一条单元测试，加上「没安排又暂时不可用」算 `unassigned`。
- 接口，不连数据库的路由测试：题库和题目详情没有会话时 401；回答带 `no-store` 和 `Vary: Cookie`；403 的回答体合乎 `ProblemAccessDenied`。
- 接口，真实数据库（CI 的 `test:db`）：
  - 孩子的题库只有安排了的书；暂时不可用的带状态排在后面；没安排时为空。
  - 题目详情：安排了 200；同一家庭另一个孩子安排的书 403 `unassigned`；别的家庭的孩子安排的书 403 `unassigned`；暂时不可用 403 `unavailable`（测试注册表）；不存在 404；只登录家长 401。
  - 作答、草稿和三个 AI 接口：`unassigned`、`unavailable` 时 403，不写作答、草稿和用量，不调用 AI（测试替身记录调用次数）。
  - 取消安排后 403，重新安排后 200，进度不变。
- 网页：访客入口、家长已登录的入口、孩子题库（可用、暂时不可用、没有安排）的 story 和测试；题目页每种情况的测试，包括课堂中途收到 403；`next` 的校验（站内题目地址、别的地址、坏的写法）。
- e2e（服务器的回答由测试代答，不需要数据库）：访客打开首页只看到入口，不请求题库；访客打开题目链接看到登录入口，不下载这道题的课堂代码和绘景；从题目页孩子登录后回到这道题。现在按访客身份打开题目的用例改成用登录并安排了这本书的孩子（`e2e/assigned-child.ts` 代答孩子会话、题库和题目详情），#126 等后来的题目用例也用它。
- 视觉基准：首页的访客（白天、晚上）、家长已登录、孩子题库（可用、暂时不可用、没有安排）；题目页的四种提示。现在的「探索」一组基准换成这些。

## 考虑过但没采用

- **访客首页保留题库，只是题目打不开**：维护者要求访客什么都看不到。
- **只在页面上隐藏没安排的书**：直接请求接口仍能拿到题目和作答，不算访问控制。
- **没安排的书回答 404**：和「题目不存在」分不开，页面没法告诉孩子去找家长；书名和安排给谁都不说，403 不泄露别人的信息。
- **家长账号也能打开题目预览**：#179 定了家长这一版不看书里的题；以后要做家长预览再单独设计。
- **孩子登录后的首页直接换成「我的练习」**：会改掉题目页返回题库分类的规则（REQ-010），孩子首页的正式改版由 #141 做。
- **把课堂代码放到登录以后才发**：部署方式要变，见[不受保护的部分](#不受保护的部分)。
