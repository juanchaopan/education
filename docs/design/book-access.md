# 孩子只学安排的书，访客看不到题目

- 状态：草稿，待维护者确认。规则是维护者 2026-11-12 在 [#221](https://github.com/juanchaopan/education/issues/221) 定下的：没有自由复习，孩子只能学家长安排给自己的书，没登录的访客什么都看不到；首页改成登录页，孩子的书按学没学完和最近学习排，家长能预览题目，题目链接登录后回到这道题，题目页按情况分开提示。需求文字、预览的细节和每张样稿还要维护者确认。
- 需求：REQ-001、REQ-009、REQ-010（改动见[需求改动](#需求改动)），REQ-002。样稿见 [#221 记录](../evidence/221/README.md)，变更原因见 [变更记录](../changes/2026-11-12-book-access.md)。
- 涉及：`libs/contracts`（打开一道题的回答、拒绝的回答、预览作答、孩子的书）、`apps/api`（题目和题目下面全部接口的访问检查、预览作答、孩子的书的排序；去掉题库接口）、`apps/web`（登录首页、孩子首页、题目页、预览、家长书架的空状态）、`e2e`、`visual`。书、书的状态和安排沿用 [家长书架与按书安排练习](bookshelf.md)。

## 为什么要改

现在首页 `/` 是公开题库，谁都能浏览全部题目；题目页对访客也打开，访客能看完短片，只是不保存进度。题目详情接口 `GET /api/v1/problems/:id/:version` 和题库接口 `GET /api/v1/problems` 不看登录；作答、草稿和提问这些接口要孩子登录，但不看这道题所在的书有没有安排给这个孩子。孩子登录在 `/child`，家长登录藏在 `/family` 的注册页下面，入口分散。

之后：

- **访客**打开首页看到的是登录页：孩子登录和家长登录两个页签。打开题目链接只看到「登录后才能打开这道题」，看不到题目的任何内容。
- **孩子**登录后首页是「我的书」：安排给自己的书，没学完的在前、学完的在后，暂时不可用的置灰放在最后。只能打开安排给自己的书里的题，没安排的书和题由服务端拒绝。
- **家长**登录后能打开题目的预览：课照常走、答案照常判，什么都不记录，画面上一直标着「家长预览」。
- 家长取消安排后，这本书从孩子的首页消失；进度不清零，重新安排后接着原来的进度（#179 的规则不变）。

## 谁在哪个地址看到什么

| 谁                               | 首页 `/`                                               | 题目链接 `/problems/:id/:version`                       | `/child`                      |
| -------------------------------- | ------------------------------------------------------ | ------------------------------------------------------- | ----------------------------- |
| 访客                             | 登录页，默认孩子登录页签                               | 「登录后才能打开这道题」，登录后回到这道题              | 去首页的登录页（带着 `next`） |
| 登录的孩子                       | 「我的书」                                             | 按[服务端的检查](#服务端的检查)打开，或说明为什么打不开 | 孩子空间：昵称和退出          |
| 登录的家长（没有孩子会话）       | 登录页，孩子登录页签照常；家长页签换成「进入家长空间」 | 预览                                                    | 去首页的登录页                |
| 同一个浏览器里孩子和家长都登录着 | 按孩子                                                 | 按孩子                                                  | 按孩子                        |

孩子和家长都登录着时按孩子，是因为孩子用的设备上更可能留着家长的会话；家长要预览就先让孩子退出。

### 首页：登录页

照家长账号页面（`/family` 没登录时）的样子：铺满整屏、不带网站顶栏，一半是傍晚的画室和小兔（`app/account-art.ts`），一半是卡片；手机和竖放的平板上画在上、卡片压在下沿。卡片顶上是品牌，下面一组两个页签，读屏是页签组「登录」：

| 页签             | 内容                                                                                                                                                                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 孩子登录（默认） | 现在孩子登录的三个字段：「我的家庭码」（下面一行「家长空间里随时可查看。」）、「我的昵称」、「我的六位 PIN」；开关「在这台设备上记住家庭码和昵称」；主按钮「进入我的空间」。底部一行：左边「第一次来？注册」（去 `/join`），右边「忘了 PIN？请家长帮忙」（去 `/family`） |
| 家长登录         | 现在家长登录的两个字段：「登录邮箱」「登录密码」；主按钮「登录」。底部一行：左边「还没有账号？注册」（去 `/family` 的注册），右边「忘记密码」（去 `/family/recover`）                                                                                                    |

- 选中的页签写进地址（`/?tab=parent`），刷新和返回后还在；默认孩子登录。
- 孩子登录成功后留在首页，换成「我的书」；带着合法的 `next` 时换到那道题（见[深链接](#深链接)）。家长登录成功后去 `/family`（邮箱没验证的家长在那里看到验证卡片，和现在一样）。
- 已经登录家长账号时，家长页签写「已经登录家长账号」和主按钮「进入家长空间」，不再显示登录字段；孩子页签照常，方便孩子在家长的设备上登录。
- 字段、校验、错误提示、限流的提示和「记住」的规则都照现在孩子登录和家长登录的组件，不改。孩子注册成功后现在去 `/child` 并带上家庭码和昵称，改成去首页的孩子页签并带上同样的两项。
- 登录页没有家庭，白天和晚上按这台设备的本地时间切换（#164 的家庭时区只用在家庭的页面上）。
- 首页不请求任何题目接口，也不下载任何题目的绘景。地址里旧的 `?grade=&subject=&category=` 不起作用。

### 首页：登录的孩子

网站顶栏照旧，导航第一项「探索题目」改成「首页」，图标是房子。下面一张「我的书」卡片，右上角「n 本」，每本书一组，样子沿用 #179 孩子「我的练习」：封面缩略图（没有封面时是默认封面）、书名、「年级 · 科目」；右边是进度胶囊「n / m」，学完是绿色带勾的「学完」，暂时不可用是「暂时不可用」；进度下面一行小字说什么时候学过（「今天学过」「3 天前学过」），没学过的写什么时候安排的（「昨天安排」）。下面按顺序列出书里的全部题，做完的题后面一个勾，题名链接到题目页。

书的顺序：

| 组           | 哪些书                           | 组里的顺序                                                       |
| ------------ | -------------------------------- | ---------------------------------------------------------------- |
| 1 没学完     | 可用、还没学完的书               | 学过的按最近学习从近到远；从没学过的排在这一组最后，新安排的在前 |
| 2 学完       | 可用、学完的书（n = m 且 m > 0） | 按最近学习从近到远                                               |
| 3 暂时不可用 | 安排了但暂时不可用的书           | 按最近学习从近到远，从没学过的在最后、新安排的在前               |

- **最近学习**是孩子在这本书里任何一道题最近一次提交作答的时间（`progress` 表的 `updated_at`，#217 的变化题作答也算）；只看了短片、没有作答不算学过。读取时算，不另存。
- 从没学过的放在没学完一组的最后：孩子正在做的书在最上面，新安排的书紧跟在后面，不会被埋到学完的书下面。
- 暂时不可用的书题名不是链接，变成次要文字色，做完的照样打勾。
- 还没有安排时是空状态「家长还没有给你安排书」「请家长在家长空间的书架上，给你安排一本书。」。
- 每页 10 本，翻到底时加载下一批（沿用 #179 的分页）。
- 孩子空间 `/child` 只留昵称和退出；「我的练习」卡片搬到首页成为「我的书」。

### 深链接

- 题目链接（例如家长转发给孩子的）对谁都可以打开，打开以后按上面的表画。
- 「去登录」去 `/?next=<这道题的地址>`，首页的登录页打开孩子页签。孩子登录成功后，`next` 合乎 `/problems/<题目 id>/<版本>` 的写法（题目 id 和版本的写法与 `ProblemParams` 一样）就换到那里，替换历史记录；不合乎写法或指向别处的一律忽略，留在首页。家长在这一页登录成功后同样回到这道题，以预览打开。
- 已经登录的孩子打开带 `next` 的首页，直接换到那道题。
- 回到题目以后由服务端判断能不能打开，没安排就是「请家长安排这本书」。
- `/child?next=` 转到 `/?next=`，旧的孩子登录入口也能回到题目。

### 家长预览

家长不用让孩子登录，就能看到孩子会看到的整节课：安排之前看看这本书合不合适，安排之后看看孩子卡在哪里。

| 预览里                     | 做什么                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 短片、旁白、字幕、道具     | 和孩子一样，从片名卡开始                                                                            |
| 作答（包括变化题）         | 用点选作答，服务器照样判对错，画面照样给出答对或再想想的反馈；结果旁边写「预览不记录」              |
| 作者写的提示               | 照样能看                                                                                            |
| 话筒、语音作答、向老师提问 | 不出现：语音转写和提问要调用 AI，花费按孩子的家庭授权和用量记账，家长的预览不用                     |
| 草稿和进度                 | 不保存。离开或刷新就从片名卡重新开始                                                                |
| 学习记录、进度、导出       | 都不出现预览，孩子的 n / m 不变                                                                     |
| 标记                       | 画面左上角返回露珠旁边一块烟色玻璃「家长预览 · 不记录」，一直在，全屏时也在；读屏在进入页面时读一次 |
| 离开                       | 返回露珠：从站内点进来的回到上一页，直接打开链接的回到 `/family`                                    |

- **能预览哪些书**：家长书架上看得到的书，也就是可用、有已发布题目的书，不论有没有安排给自己家的孩子；暂时不可用的书不能预览，显示「这本书暂时不可用」。
- **入口**：这一版只有题目链接。家长书架不列书里的题（#179），总览「值得再练」和学习记录里的题名改成预览链接放在后续工作里，免得和 #164 的总览改动撞在一起。
- 邮箱没验证的家长和没登录一样，看到登录提示。

## 服务端的检查

### 一道题能不能打开

先认会话：有孩子会话按孩子判断；没有孩子会话、有已验证邮箱的家长会话按家长判断；都没有回答 401。然后按下面的顺序，第一条成立就停：

| 顺序 | 孩子                             | 家长         | 结果                               |
| ---- | -------------------------------- | ------------ | ---------------------------------- |
| 1    | 题目或这个版本不在题目清单里     | 同左         | `missing`                          |
| 2    | 这道题所在的书没有安排给这个孩子 | —            | `unassigned`                       |
| 3    | 书暂时不可用                     | 书暂时不可用 | `unavailable`                      |
| 4    | 其余                             | 其余         | `learn`（孩子）、`preview`（家长） |

- 「安排给这个孩子」只看会话里的孩子在 `book_assignments` 里有没有这本书的一行，不看兄弟姐妹，也不看家长；孩子的接口里没有孩子 id，跨孩子、跨家庭只能落到 `unassigned`。
- 没安排又暂时不可用的书算 `unassigned`：没人安排过的不可用书，孩子本来就看不到。
- 题目的版本仍按题目清单：清单里有的版本都能打开，书里列的是最新版本。
- 判断是不依赖数据库的纯函数（`apps/api/src/learning/domain/problem-access.ts`），输入是谁在看、题目清单里的题和书、孩子安排了的书 id；安排由现有的 `readBookAssignments` 读，不加新表、不加迁移。

### 哪些接口检查什么

| 接口                                                                                   | 谁能用     | 没有会话 | CSRF 不对 | `missing` | `unassigned` | `unavailable` | 能打开 |
| -------------------------------------------------------------------------------------- | ---------- | -------- | --------- | --------- | ------------ | ------------- | ------ |
| `GET /api/v1/problems/:id/:version`（打开一道题）                                      | 孩子、家长 | 401      | —         | 404       | 403          | 403           | 200    |
| `GET`、`POST .../answer`、`.../draft`，#217 的 `GET`、`POST .../variation`             | 孩子       | 401      | 403（写） | 404       | 403          | 403           | 照现在 |
| `POST .../question`、`.../feedback`、`.../transcription`（向老师提问、讲解、语音转写） | 孩子       | 401      | 403       | 404       | 403          | 403           | 照现在 |
| `POST .../preview`（预览作答和提示）                                                   | 家长       | 401      | 403       | 404       | —            | 403           | 200    |
| `GET /api/v1/children/assignments`（孩子的书）                                         | 孩子       | 401      | —         | —         | 不列         | 列出，带状态  | 列出   |

- 「谁能用」以外的会话一律 401：家长调孩子的接口、孩子调预览接口都是 401，页面不会这样调。
- 检查顺序：先会话和 CSRF（照现在），再判断这道题能不能打开，最后才是各接口自己的逻辑；不能打开时不读写草稿、作答和用量，也不调用 AI。
- 题目下面所有孩子的接口都从同一个「孩子 + 题目」入口进来（`apps/api/src/child-problem-transaction.ts`），检查只写在这一处；#217 合并后它的变化题接口也改从这个入口进来。
- 打开一道题和预览作答的回答都带 `Cache-Control: no-store` 和 `Vary: Cookie`。
- `GET /api/v1/problems`（公开题库）删除：孩子首页用孩子的书，家长书架有自己的接口，没有别的调用方。
- 家长的书架、安排、导出和删除接口不变（#179 里已经按家长会话和家庭检查，别的家庭的孩子回答 404）。

### 回答

| 状态 | 回答体                                                            | 什么时候               |
| ---- | ----------------------------------------------------------------- | ---------------------- |
| 200  | 题目摘要加 `mode: 'learn' \| 'preview'`                           | 打开一道题             |
| 401  | `{ message: '登录已失效，请重新登录。' }`（和现在的孩子接口一样） | 没有能用这个接口的会话 |
| 403  | `{ message: '请刷新页面后重试。' }`（照现在）                     | 写请求的 CSRF 不对     |
| 403  | `{ message: '这本书还没有安排给你。', reason: 'unassigned' }`     | 书没安排给这个孩子     |
| 403  | `{ message: '这本书暂时不可用。', reason: 'unavailable' }`        | 书暂时不可用           |
| 404  | `{ message: '这道题或这个版本暂时不可用。' }`（照现在）           | 题目或版本不存在       |

- 契约在 `libs/contracts`：`ProblemOpening`（题目摘要加 `mode`）、`ProblemAccessDenied`（`message` 和 `reason`）。页面按 `mode` 和 `reason` 选画法，不比较文字。`RequestError` 多一个可选的 `reason`，错误处理把它放进回答体。
- 拒绝时不说明书名，也不说明这本书安排给了谁。
- 没有会话时先落到 401，题目存不存在都一样，访客不能用接口一道道试出题目清单。页面没登录时也不请求题目详情，不消耗登录的限流额度。

### 预览作答

`POST /api/v1/problems/:id/:version/preview`，家长会话，校验来源和 CSRF 令牌，和其他家长写接口一样；请求体上限和作答一样。

| 请求体                                        | 回答             |
| --------------------------------------------- | ---------------- |
| `{ action: 'submit', input }`                 | `{ outcome }`    |
| `{ action: 'hint', hintId }`                  | `{ hint }`       |
| `{ action: 'variation', ... }`（#217 合并后） | 变化题的判定结果 |

- 用和孩子作答同一个判定规则（`AnsweringPolicy`），在服务器上判，判定规则不进静态文件。
- 不写任何表：没有作答轮次、作答记录、帮助记录和进度；`input` 的写法和孩子作答一样。
- `outcome` 只有判定结果（独立完成、答错、无法判定），预览里没有「提示后完成」：没有轮次，就不记帮助。
- 限流沿用家长会话的接口限流。

### 孩子的书

`GET /api/v1/children/assignments` 的回答（#179）每本书多一个 `studiedAt`（最近学习时间，没学过是 `null`），排列改成[孩子首页的顺序](#首页登录的孩子)。读取时一次查出这个孩子在这些书里每道题的最近作答时间，不按书逐本查。

## 不受保护的部分

课堂的代码（台词、分镜规则、画法）、旁白录音和绘景是网站的静态文件，按需下载，不经过登录检查；猜到文件地址的人能下载它们。本次的访问规则管的是页面和全部接口：页面不给访客画题目，接口不给访客和没安排的孩子题目、作答、草稿和 AI。判对错的规则和提示只在服务器上，不在静态文件里。把课堂代码、录音和绘景也放到会话和安排的检查后面，是单独的后续 issue。

## 实现要点

- `apps/api`：先做一个不改行为的重构，让题目下面的孩子接口（作答、草稿和三个 AI 接口）都从同一个「孩子 + 题目」入口进来，现在它只确认孩子会话；之后访问检查只加在这个入口里。打开一道题由外层的组装文件按会话选孩子或家长的判断，再交给 `catalog` 的路由；`catalog` 不依赖 `learning`。预览作答放在 `learning` 里，和孩子作答共用判定。
- `libs/contracts`：`ProblemOpening`、`ProblemAccessDenied`、预览作答的请求和回答；`PracticeBook` 加 `studiedAt`；去掉 `CatalogResponse`。
- `apps/web`：首页按会话选登录页或「我的书」，登录页复用 `AccountLayout`、孩子和家长的登录组件；`ProblemPage` 先看会话，再按 `mode` 和 `reason` 选画法；课堂页面收到的不再是可有可无的 `csrf`，而是「孩子（带 CSRF）」或「预览（带家长的 CSRF）」两种之一：孩子照现在，预览用同一个画面，作答和提示走预览接口，不放话筒、提问和草稿，加上预览标记。
- 题目页的 `LessonRoute` 和 #210 的课堂记录都改这一带，合并时按顺序处理。

## 测试

- 判断能不能打开：上面顺序表的每一格一条单元测试，加上「没安排又暂时不可用」算 `unassigned`、孩子和家长都登录着时按孩子。
- 孩子的书的顺序：每组里的顺序、从没学过的位置、学完后加了新题回到第一组、暂时不可用放在最后，各一条单元测试。
- 接口，不连数据库的路由测试：没有会话时 401；回答带 `no-store` 和 `Vary: Cookie`；403 的回答体合乎 `ProblemAccessDenied`；预览接口的请求体校验和来源检查。
- 接口，真实数据库（CI 的 `test:db`）：
  - 打开一道题：安排了 200 `learn`；同一家庭另一个孩子安排的书 403 `unassigned`；别的家庭的孩子安排的书 403 `unassigned`；暂时不可用 403 `unavailable`（测试注册表）；不存在 404；家长 200 `preview`、暂时不可用 403；没验证邮箱的家长 401。
  - 作答、草稿、变化题和三个 AI 接口：`unassigned`、`unavailable` 时 403，不写作答、草稿和用量，不调用 AI（测试替身记录调用次数）；家长会话 401。
  - 预览作答：判对、判错、提示；调用前后所有学习表的行数不变；孩子会话 401。
  - 取消安排后 403，重新安排后 200，进度不变。
  - 孩子的书：`studiedAt` 和顺序。
- 网页：登录页两个页签（孩子、家长、家长已登录）、孩子首页（顺序、暂时不可用、没有安排）的 story 和测试；题目页每种情况的测试，包括课堂中途收到 403；`next` 的校验（站内题目地址、别的地址、坏的写法、`/child?next=` 转过来）；预览模式不放话筒、提问和草稿，作答走预览接口，标记一直在。
- e2e（服务器的回答由测试代答，不需要数据库）：访客打开首页只看到登录页，不请求题目接口；访客打开题目链接看到登录提示，不下载这道题的课堂代码和绘景；从题目页登录后回到这道题；家长预览走完片名卡到作答，不请求草稿和作答接口。现在按访客身份打开题目的用例改成用登录并安排了这本书的孩子（`e2e/assigned-child.ts` 代答孩子会话和打开一道题），#126 等后来的题目用例也用它。
- 视觉基准：登录页两个页签（白天、晚上、手机）；孩子首页（白天、晚上、手机、没有安排）；题目页的三种提示；预览的片名卡和作答。现在的「探索」一组基准换成这些。

## 考虑过但没采用

- **访客首页保留题库，只是题目打不开**：维护者要求访客什么都看不到。
- **只在页面上隐藏没安排的书**：直接请求接口仍能拿到题目和作答，不算访问控制。
- **没安排的书回答 404**：和「题目不存在」分不开，页面没法提示请家长安排；书名和安排给谁都不说，403 不泄露别人的信息。
- **孩子首页保留年级、学科、分类三个选择**：选择框表达不了「没学完的在前、最近学过的在前」；按书排成一列和 #179 的「我的练习」一致。
- **预览不判答案、只看短片**：家长看不到孩子在作答那一步会遇到什么；判定在服务器上、不记录，代价是一个只读的接口。
- **预览里也能语音作答和提问**：要调用付费的 AI，家庭授权管的是孩子的输入；预览用点选就够看清这一步。
- **只能预览安排给自家孩子的书**：家长最需要预览的时候是安排之前。
- **把课堂代码放到登录以后才发**：部署方式要变，作为后续 issue。
