# 孩子只学安排的书，访客看不到题目

- 状态：需求已由维护者 2026-11-12 确认，写进 [REQ-001、REQ-009、REQ-010](../product/requirements.md) 和 [vision.md](../product/vision.md)。登录页、题目页和预览模式的样稿维护者已看过；孩子首页按第四轮意见重画，等维护者确认。
- 需求：REQ-001、REQ-009、REQ-010（2026-11-12 修改），REQ-002、REQ-011。样稿见 [#221 记录](../evidence/221/README.md)，变更原因见 [变更记录](../changes/2026-11-12-book-access.md)。
- 涉及：`libs/contracts`（打开一道题的回答、拒绝的回答、预览作答、孩子的书）、`apps/api`（题目和题目下面全部接口的访问检查、预览作答、孩子的书的筛选、排序和新书标记；去掉公开题库）、`apps/web`（登录首页、孩子首页和顶栏、题目页、预览模式、凸起的公共部件、家长书架的空状态）、`e2e`、`visual`。书、书的状态和安排沿用 [家长书架与按书安排练习](bookshelf.md)。

## 为什么要改

现在首页 `/` 是公开题库，谁都能浏览全部题目；题目页对访客也打开，访客能看完短片，只是不保存进度。题目详情接口和题库接口不看登录；作答、草稿和提问接口要孩子登录，但不看这道题所在的书有没有安排给这个孩子。孩子登录在 `/child`，家长登录藏在 `/family` 的注册页下面；孩子登录后顶栏还有「探索题目」「孩子空间」「孩子注册」「家长空间」四个入口，首页的题库和孩子空间的「我的练习」列的是重叠的东西。

之后：

- **访客**打开首页看到登录页：孩子登录和家长登录两个页签。打开题目链接只看到「登录后才能打开这道题」，看不到题目的任何内容。
- **孩子**登录后首页就是自己的空间「我的书」：新安排的书在最上面，「在学」上的红点告诉孩子有几本新书；每本书是一块能展开的凸起卡片，书名、进度条和「全部 n 道」在一起，展开才看到书里的题。只能打开安排给自己的书里的题，没安排的由服务端拒绝。顶栏只有品牌和自己的头像，头像菜单里退出登录。
- 一道题有两种模式：**做题模式**给孩子，作答、进度和草稿照常记录；**预览模式**给家长，课照常走、答案照常判，什么都不记录。
- 家长取消安排后，这本书从孩子的首页消失；进度不清零，重新安排后接着原来的进度（#179 的规则不变）。

## 地址和谁看到什么

| 谁                               | 首页 `/`                                               | 题目链接 `/problems/:id/:version`                                 |
| -------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------- |
| 访客                             | 登录页，默认孩子登录页签                               | 「登录后才能打开这道题」，登录后回到这道题                        |
| 登录的孩子                       | 「我的书」                                             | 按[服务端的检查](#服务端的检查)以做题模式打开，或说明为什么打不开 |
| 登录的家长（没有孩子会话）       | 登录页，孩子登录页签照常；家长页签换成「进入家长空间」 | 预览模式                                                          |
| 同一个浏览器里孩子和家长都登录着 | 按孩子                                                 | 按孩子                                                            |

- 孩子和家长都登录着时按孩子：孩子用的设备上更可能留着家长的会话；家长要预览就先让孩子退出。
- `/child` 不再是单独的页面，转到 `/`（带着 `next`）：孩子的空间就是首页，昵称和退出在顶栏的头像菜单里，孩子空间原来的「我的练习」就是首页的「我的书」。
- `/join`（孩子注册）、`/family`（家长注册和家长空间）、`/family/recover`（找回密码）照现在的样子用，改版由 #141 和[后续工作](#后续工作)做。

## 立体感和统一的按钮

维护者要整个网站和课堂的画面一样有立体感，孩子首页尤其如此；按钮和部件全站一个样式。本设计画的页面都按下面的做法，家长空间的改版另开 issue：

- **页面顶上是一幅有景深的画**：绘景库里的场景铺满宽度，下沿淡进页面底色，讲课角色站在画里；卡片压在画的下沿上，像放在画里的桌面上。
- **能按的东西都是同一种凸起**：一层纸色或主色的面、下面一道 3px 的深色边、一层柔和的投影；按下时往下沉 2px、边变成 1px；不能按（加载中、暂时不可用）时变平，没有边和投影。

  | 级别         | 用在哪里                                           | 尺寸                          |
  | ------------ | -------------------------------------------------- | ----------------------------- |
  | 课堂里的露珠 | 题目页的返回、提示、话筒、开始短片                 | 52px 以上，烟色玻璃           |
  | 主按钮       | 每页最要紧的一步：登录、「去登录」、「回到我的书」 | 高 48px，主色                 |
  | 次按钮       | 「加载更多」、「再试一次」                         | 高 48px，纸色                 |
  | 筹码         | 筛选、登录页签的滑块                               | 高 44px，选中主色、没选中纸色 |
  | 卡片和列表块 | 孩子首页的书和书里的题、头像菜单里的「退出登录」   | 每行高 48–54px，纸色          |

  课堂里的按钮可以更大，课堂以外的按钮彼此一样；这些做成 `shared/ui` 的公共部件和令牌，[网站视觉语言](visual-language.md) 随之补上这一节。

- **输入框和进度条的槽是凹下去的**：内侧上沿一道浅投影。
- **书是立体的**：封面往里转一点角度，左边一道书脊的明暗，右边露出书页的边。
- **画面上的字和按钮是烟色玻璃**：顶栏的品牌和头像、角色的对白气泡、题目页的提示卡都用 `--dew-*` 令牌，和课堂里的控件一样。
- 打开「减少动态效果」时只去掉动效，凸起、投影和景深都保留。

### 首页：登录页

照家长账号页面的样子：铺满整屏、不带顶栏，一半是傍晚的画室和小兔（`app/account-art.ts`），一半是凸起的卡片；手机和竖放的平板上画在上、卡片压在下沿。卡片顶上是品牌，下面一组两个页签（凹槽里一块凸起的滑块），读屏是页签组「登录」：

| 页签             | 内容                                                                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 孩子登录（默认） | 现在孩子登录的字段：「我的家庭码」（下面一行「家长空间里随时可查看。」）、「我的昵称」、「我的六位 PIN」；开关「在这台设备上记住家庭码和昵称」；主按钮「进入我的空间」。底部一行：左边「有 KEY？去注册」（去 `/join`），右边「忘了 PIN」 |
| 家长登录         | 现在家长登录的字段：「登录邮箱」「登录密码」；主按钮「登录」。底部一行：左边「创建账号」（去 `/family` 的注册），右边「忘记密码」（去 `/family/recover`）                                                                                |

- 孩子登录只用家庭码、昵称和 PIN；KEY 只在注册时用一次（REQ-002）。
- 「忘了 PIN」不离开这一页：点了在它下面展开一行「请家长在家长空间帮你重置。」，再点收起。
- 选中的页签写进地址（`/?tab=parent`），刷新和返回后还在；默认孩子登录。
- 孩子登录成功后留在首页，换成「我的书」；带着合法的 `next` 时换到那道题（见[深链接](#深链接)）。家长登录成功后去 `/family`（邮箱没验证的家长在那里看到验证卡片，和现在一样）。
- 已经登录家长账号时，家长页签写「已经登录家长账号」和主按钮「进入家长空间」，不显示登录字段；孩子页签照常，方便孩子在家长的设备上登录。
- 字段、校验、错误提示、限流提示和「记住」的规则都照现在孩子登录和家长登录的组件，不改。孩子注册成功后现在去 `/child` 并带上家庭码和昵称，改成去首页的孩子页签并带上同样的两项。
- 登录页没有家庭，白天和晚上按这台设备的本地时间切换（#164 的家庭时区只用在家庭的页面上）。
- 首页不请求任何题目接口，也不下载任何题目的绘景。地址里旧的 `?grade=&subject=&category=` 不起作用。

### 首页：登录的孩子

**顶栏**：叠在画的上沿，左边是品牌（烟色玻璃胶囊里的图标和「小小探索家」，手机上只有图标），点了回到首页顶部；右边是孩子的头像和昵称（烟色玻璃胶囊，带向下的箭头），点了弹出一张凸起的菜单，只有一项「退出登录」。退出后回到首页的登录页，换一个孩子就在那里登录。不放「孩子注册」（已经注册并登录了）、「家长空间」（家长从登录页的家长页签或 `/family` 进去，孩子的屏幕上不需要）和「孩子空间」（首页就是）。

**画**：白天是玩具教室（`toy-classroom-day`），晚上是雨夜的图书角（`library-corner-rainy`），小兔站在右边，旁边一个烟色玻璃气泡「小米，今天学哪本？」（孩子的昵称）。

**「我的书」卡片**压在画的下沿，标题左边是一排立着的书的图标。卡片里从上到下是筛选、书、加载更多。

#### 筛选

一排凸起的筹码，单选，读屏是单选组「筛选」：

| 筹码         | 哪些书                         | 数字                                                 | 什么时候出现       |
| ------------ | ------------------------------ | ---------------------------------------------------- | ------------------ |
| 全部（默认） | 安排给这个孩子的全部书         | 本数，小字                                           | 一直               |
| 在学         | 可用、没学完的书，包括新安排的 | 本数，小字；有新书时右上角一个红色实心圆和新书的本数 | 一直               |
| 学完         | 可用、学完的书                 | 本数，小字                                           | 一直               |
| 暂时不可用   | 安排了但暂时不可用的书         | 本数，小字                                           | 有暂时不可用的书时 |

- 默认「全部」（维护者确认）：新书就排在最上面，孩子一打开就看到；「在学」上的红点在孩子换到别的筛选、或者新书被翻到下面时仍然提醒。
- 红点读屏是「n 本新书」；没有新书时不出现。
- 选中的筹码写进地址（`/?books=learning|finished|unavailable`），刷新、从题目页返回后还在。
- 选中的筛选里没有书时（例如还没有学完的书）是一行「这里还没有书」和次按钮「看全部的书」。
- 手机上筹码放不下时折到第二行，不横向滚动。

#### 书的顺序

| 组           | 哪些书                           | 组里的顺序                                                         |
| ------------ | -------------------------------- | ------------------------------------------------------------------ |
| 1 新安排     | 可用、孩子还没打开过其中的题的书 | 新安排的在前                                                       |
| 2 在学       | 可用、没学完、打开过的书         | 按最近学习从近到远；打开过但没作答过的排在这一组最后，新安排的在前 |
| 3 学完       | 可用、学完的书（n = m 且 m > 0） | 按最近学习从近到远                                                 |
| 4 暂时不可用 | 安排了但暂时不可用的书           | 按最近学习从近到远，没作答过的在最后、新安排的在前                 |

- **最近学习**是孩子在这本书里任何一道题最近一次提交作答的时间（`progress` 表的 `updated_at`，#217 的变化题作答也算）。读取时算，不另存。
- 新安排的书已经学完（以前做完、取消后又安排）时也排在第 1 组，直到孩子打开其中一道题。
- 「全部」按上表四组排；其他筛选是上表里的一部分，顺序不变。

#### 新书

- 家长给孩子安排一本书时，这本书对这个孩子是**新书**：封面右上角一枚红色「新」字，计入「在学」上的红点。
- 孩子以做题模式**打开这本书里任何一道题**以后，这本书不再是新书（维护者确认）：服务器在打开这道题时记下（见[数据](#数据)），「新」字和红点里的这一本消失，书移到第 2 组。
- 只是在首页看到这本书、切换筛选或者展开它的题目列表，都不算：孩子总要先展开、再打开一道题，打开题才算真的开始做这本书。
- 家长取消后再安排，这本书又是新书。
- 暂时不可用的书不算新书，不进红点：孩子打不开它。

#### 一本书

每本书是一块凸起的卡片，**收起时整块就是一个按钮**（`aria-expanded`）：

- 左边立体的封面（没有封面时是默认封面）。
- 右边书名，下面一行小字「年级 · 科目 · 什么时候」（「今天学过」「3 天前学过」，新书写「刚刚安排」「昨天安排」，打开过没作答的写「还没做」）。
- 再下面一条**进度条**：凹下的槽里一段凸起的主色，右边写「5 / 12」；学完时整条变成绿色，右边是带勾的「学完」。
- 最下面「全部 n 道」和向下的箭头。点卡片上任何地方都展开，书里的题不会在收起时露出来，哪一道都不比别的更显眼。

**展开时**卡片在页面上原地变长：

- 头部的「全部 n 道」换成「收起」和向上的箭头，头部仍然是收起的按钮。
- 下面一行一道，列出书里的全部题，所有屏幕上都是一列，题名完整显示、太长就折行；每行是序号、题名，做完的后面一个勾，最右一个向右的箭头，高 54px，整行都能点，点了以做题模式打开这道题。
- 最后一行再放一个「收起」，长的书翻到底也能收起。
- 不用下拉框或弹出层：手指在页面上上下滑就能看完，点哪一行就进哪一道题。
- 一次只展开一本书：展开另一本时，前一本收起，页面保持刚点的那本书的书名在屏幕里。
- 展开的是哪本书写进地址（`&open=<书 id>`），从题目页返回时还展开着、停在原来的位置。

**暂时不可用的书**：

- 卡片变平（没有凸起的边），封面变灰；书名、小字和右边的「暂时不可用」都是同一种灰色、正常字重；进度条变灰，不是主色也不是绿色。
- 照样能展开，看到书里有哪些题、做完的打勾。展开后列表最上面一行写「这本书暂时不可用，里面的题先打不开。」，题目行变平、灰色、没有向右的箭头，点了没有反应：理由已经写在列表最上面，不用再弹提示。

#### 加载更多

每批 6 本（维护者确认）。

| 设备                                        | 怎么加载                                                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 手机和平板（触摸为主，`(pointer: coarse)`） | 滑到离底部约一屏时自动加载下一批：底部一张骨架书卡和三颗跳动的圆点「加载中…」                           |
| 电脑（鼠标为主）                            | 底部一个凸起的次按钮「加载更多」；点了按钮沉下去、变平，换成三颗圆点和「加载中…」，不能再点；加载完恢复 |

- 都加载完时底部一行「都在这里了」。
- 加载失败时一行「这一批没加载出来」和次按钮「再试一次」，手机上也一样。
- 电脑上的「加载更多」和手机上的「再试一次」都能用 Tab 走到。

#### 没有书

还没有安排时，卡片里是空状态「家长还没有给你安排书」「请家长在家长空间的书架上，给你安排一本书。」，没有筛选。

### 题目页

画框和返回露珠照现在的 `FullscreenFrame`，题目页不随白天和晚上变化。提示画在一幅虚化的画室绘景上（不是这道题自己的背景，没登录时不透露题目），小兔站在左边，旁边一块烟色玻璃提示卡，按钮是金色凸起的胶囊。每种情况只给一种提示：

| 情况                     | 图标 | 标题                  | 说明                                                 | 按钮                                     | 返回露珠去哪里         |
| ------------------------ | ---- | --------------------- | ---------------------------------------------------- | ---------------------------------------- | ---------------------- |
| 没登录                   | 锁   | 登录后才能打开这道题  | 请先登录自己的账号。                                 | 「去登录」                               | 首页                   |
| 孩子，书没安排           | 书   | 请家长安排这本书      | 这本书还没有安排给你，家长在书架上安排好以后就能做。 | 「回到我的书」                           | 首页                   |
| 孩子或家长，书暂时不可用 | 时钟 | 这本书暂时不可用      | 里面的题先打不开，过一阵再来看看。                   | 「回到我的书」（家长是「回到家长空间」） | 首页（家长是家长空间） |
| 题目或版本不存在         | 嫩芽 | 这道题暂时不可用      | 照现在                                               | 照现在                                   | 首页                   |
| 孩子，能打开             | —    | 做题模式，照现在      |                                                      |                                          | 首页，回到原来的位置   |
| 家长，能打开             | —    | [预览模式](#预览模式) |                                                      |                                          | 家长刚才的页面         |

- 没登录时只有登录提示：不请求题目详情，不加载这道题的课堂代码和绘景，标题和书名都不显示。
- 课堂进行中，题目下面的任何接口回答带 `reason` 的 403（家长刚取消安排，或者新部署把书改成暂时不可用），题目页重新请求题目详情，换成上表对应的提示。草稿留在服务器上照常 7 天过期，期间重新安排就接着做。
- 课堂里「没登录也能看短片」和右下角的「登录后能保存进度」提示条去掉：课堂只画给做题模式的孩子和预览模式的家长。
- 做题模式返回首页时回到原来的位置（筛选、展开的书和滚动位置）；直接打开链接进来的，回到首页、展开这本书并滚到它。

### 深链接

- 题目链接（例如家长转发给孩子的）对谁都可以打开，打开以后按上面的表画。
- 「去登录」去 `/?next=<这道题的地址>`，登录页打开孩子页签。登录成功后，`next` 合乎 `/problems/<题目 id>/<版本>` 的写法（题目 id 和版本的写法与 `ProblemParams` 一样）就换到那里，替换历史记录；不合乎写法或指向别处的一律忽略，留在首页。家长在这一页登录成功后同样回到这道题，以预览模式打开。
- 已经登录的孩子打开带 `next` 的首页，直接换到那道题。
- 回到题目以后由服务端判断能不能打开，没安排就是「请家长安排这本书」。
- `/child?next=` 转到 `/?next=`，旧的孩子登录入口也能回到题目。

### 预览模式

家长不用让孩子登录，就能看到孩子会看到的整节课：安排之前看看这本书合不合适，安排之后看看孩子卡在哪里（维护者确认）。

| 预览模式里                 | 做什么                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 短片、旁白、字幕、道具     | 和做题模式一样，从片名卡开始                                                                                   |
| 作答（包括变化题）         | 用点选作答，服务器按做题模式同样的规则判对错，画面给出和做题模式一模一样的反馈（例如「答对了」）               |
| 作者写的提示               | 照样能看                                                                                                       |
| 话筒、语音作答、向小兔提问 | 不出现：语音转写和提问要调用 AI，花费按孩子的家庭授权和用量记账，预览不用                                      |
| 草稿和进度                 | 不保存。离开或刷新就从片名卡重新开始                                                                           |
| 学习记录、进度、新书       | 都不受预览影响，孩子的 n / m 和新书标记不变                                                                    |
| 标记                       | 画面左上角返回露珠旁边一块烟色玻璃「预览」（眼睛图标），一直在，全屏时也在；读屏在进入页面时读一次「预览模式」 |
| 离开                       | 返回露珠：从站内点进来的回到上一页，直接打开链接的回到 `/family`                                               |

- **能预览哪些书**：家长书架上看得到的书，也就是可用、有已发布题目的书，不论有没有安排给自己家的孩子；暂时不可用的书不能预览，显示「这本书暂时不可用」。
- **入口**：这一版只有题目链接。家长页面里的预览链接（总览「值得再练」、学习记录的题名）放在后续工作里，免得和 #164 的总览改动撞在一起。
- 邮箱没验证的家长和没登录一样，看到登录提示。

## 服务端的检查

### 一道题能不能打开

先认会话：有孩子会话按孩子判断；没有孩子会话、有已验证邮箱的家长会话按家长判断；都没有回答 401。然后按下面的顺序，第一条成立就停：

| 顺序 | 孩子                             | 家长         | 结果                                  |
| ---- | -------------------------------- | ------------ | ------------------------------------- |
| 1    | 题目或这个版本不在题目清单里     | 同左         | `missing`                             |
| 2    | 这道题所在的书没有安排给这个孩子 | —            | `unassigned`                          |
| 3    | 书暂时不可用                     | 书暂时不可用 | `unavailable`                         |
| 4    | 其余                             | 其余         | `practice`（孩子）、`preview`（家长） |

- 「安排给这个孩子」只看会话里的孩子在 `book_assignments` 里有没有这本书的一行，不看兄弟姐妹，也不看家长；孩子的接口里没有孩子 id，跨孩子、跨家庭只能落到 `unassigned`。
- 没安排又暂时不可用的书算 `unassigned`：没人安排过的不可用书，孩子本来就看不到。
- 题目的版本仍按题目清单：清单里有的版本都能打开，书里列的是最新版本。
- 判断是不依赖数据库的纯函数（`apps/api/src/learning/domain/problem-access.ts`），输入是谁在看、题目清单里的题和书、孩子安排了的书 id；安排由现有的 `readBookAssignments` 读。
- 孩子以做题模式打开一道题（`practice`）时，同一个事务里把这本书标成打开过（见[新书](#新书)）；这是新书唯一被消掉的地方，不另设接口。

### 哪些接口检查什么

| 接口                                                                                   | 谁能用     | 没有会话 | CSRF 不对 | `missing` | `unassigned` | `unavailable` | 能打开 |
| -------------------------------------------------------------------------------------- | ---------- | -------- | --------- | --------- | ------------ | ------------- | ------ |
| `GET /api/v1/problems/:id/:version`（打开一道题）                                      | 孩子、家长 | 401      | —         | 404       | 403          | 403           | 200    |
| `GET`、`POST .../answer`、`.../draft`，#217 的 `GET`、`POST .../variation`             | 孩子       | 401      | 403（写） | 404       | 403          | 403           | 照现在 |
| `POST .../question`、`.../feedback`、`.../transcription`（向小兔提问、讲解、语音转写） | 孩子       | 401      | 403       | 404       | 403          | 403           | 照现在 |
| `POST .../preview`（预览模式的作答和提示）                                             | 家长       | 401      | 403       | 404       | —            | 403           | 200    |
| `GET /api/v1/children/assignments`（孩子的书）                                         | 孩子       | 401      | —         | —         | 不列         | 列出，带状态  | 列出   |

- 「谁能用」以外的会话一律 401：家长调孩子的接口、孩子调预览接口都是 401，页面不会这样调。
- 检查顺序：先会话和 CSRF（照现在），再判断这道题能不能打开，最后才是各接口自己的逻辑；不能打开时不读写草稿、作答和用量，也不调用 AI。
- 题目下面所有孩子的接口都从同一个「孩子 + 题目」入口进来（`apps/api/src/child-problem-transaction.ts`），检查只写在这一处；#217 合并后它的变化题接口也改从这个入口进来。
- 打开一道题和预览作答的回答都带 `Cache-Control: no-store` 和 `Vary: Cookie`。
- `GET /api/v1/problems`（公开题库）删除：孩子首页用孩子的书，家长书架有自己的接口，没有别的调用方。
- 家长的书架、安排、导出和删除接口不变（#179 里已经按家长会话和家庭检查，别的家庭的孩子回答 404）。

### 回答

| 状态 | 回答体                                                            | 什么时候               |
| ---- | ----------------------------------------------------------------- | ---------------------- |
| 200  | 题目摘要加 `mode: 'practice' \| 'preview'`                        | 打开一道题             |
| 401  | `{ message: '登录已失效，请重新登录。' }`（和现在的孩子接口一样） | 没有能用这个接口的会话 |
| 403  | `{ message: '请刷新页面后重试。' }`（照现在）                     | 写请求的 CSRF 不对     |
| 403  | `{ message: '这本书还没有安排给你。', reason: 'unassigned' }`     | 书没安排给这个孩子     |
| 403  | `{ message: '这本书暂时不可用。', reason: 'unavailable' }`        | 书暂时不可用           |
| 404  | `{ message: '这道题或这个版本暂时不可用。' }`（照现在）           | 题目或版本不存在       |

- 契约在 `libs/contracts`：`ProblemOpening`（题目摘要加 `mode`）、`ProblemAccessDenied`（`message` 和 `reason`）。页面按 `mode` 和 `reason` 选画法，不比较文字。`RequestError` 多一个可选的 `reason`，错误处理把它放进回答体。
- 拒绝时不说明书名，也不说明这本书安排给了谁。
- 没有会话时先落到 401，题目存不存在都一样，访客不能用接口一道道试出题目清单。页面没登录时也不请求题目详情，不消耗登录的限流额度。

### 预览作答

`POST /api/v1/problems/:id/:version/preview`，家长会话，校验来源和 CSRF 令牌，和其他家长写接口一样；请求体上限和孩子作答一样。

| 请求体                                        | 回答             |
| --------------------------------------------- | ---------------- |
| `{ action: 'submit', input }`                 | `{ outcome }`    |
| `{ action: 'hint', hintId }`                  | `{ hint }`       |
| `{ action: 'variation', ... }`（#217 合并后） | 变化题的判定结果 |

- 用和做题模式同一个判定规则（`AnsweringPolicy`），在服务器上判，判定规则不进静态文件；页面拿到结果后用做题模式同一套反馈画出来。
- 不写任何表：没有作答轮次、作答记录、帮助记录、进度和打开标记；`input` 的写法和孩子作答一样。
- 没有轮次就不记帮助，`outcome` 只会是 `independent`、`incorrect` 或 `uncertain`；页面上答对就是「答对了」，和做题模式一样。
- 限流沿用家长会话的接口限流。

### 孩子的书

`GET /api/v1/children/assignments?books=&offset=`（#179 的接口）：

| 参数     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| `books`  | 可选，`learning`、`finished`、`unavailable` 之一；不写是全部 |
| `offset` | 可选，从第几本开始，0 起；每批 6 本                          |

回答：

```text
{
  counts: { all, learning, finished, unavailable, fresh },   // 每个筛选各几本；fresh 是新书的本数，红点用它
  books: [{ id, name, grade, subject, cover, status, problems, done, studiedAt, assignedAt, fresh,
            items: [{ id, version, title, done }] }],
  hasMore
}
```

- `studiedAt` 是最近学习的时间，没作答过是 `null`；`fresh` 表示还是新书；排列按[书的顺序](#书的顺序)。
- `items` 是书里现在的全部题；一本书的题最多几十道，一次给全，展开时不用再请求。
- 一次查出这个孩子的安排、每本书里每道题的最近作答时间和做完的题，不按书逐本查；筛选、计数和分页在内存里做（一个孩子的书只有几十本）。
- `books` 不合乎写法是 400。

## 数据

`book_assignments` 加一列，迁移只加不删：

```text
book_assignments
  opened_at  timestamptz  可以为空；孩子第一次以做题模式打开这本书里任何一道题的时间，没打开过是空
```

- 打开一道题时 `UPDATE ... SET opened_at = now() WHERE child_id = $1 AND book_id = $2 AND opened_at IS NULL`，只写一次，重复打开不变。
- 取消安排删除这一行，再安排插入新的一行，`opened_at` 是空，所以又是新书。
- 不写进家庭导出：它只决定首页上的新书标记，不是学习记录。删除家庭时跟着这一行一起删除；备份的逐表行数不变。
- 迁移的编号排在 #217、#164 的迁移之后，合并时按顺序重排。

## 不受保护的部分

课堂的代码（台词、分镜规则、画法）、旁白录音和绘景是网站的静态文件，按需下载，不经过登录检查；猜到文件地址的人能下载它们。本次的访问规则管的是页面和全部接口：页面不给访客画题目，接口不给访客和没安排的孩子题目、作答、草稿和 AI。判对错的规则和提示只在服务器上，不在静态文件里。把课堂代码、录音和绘景也放到会话和安排的检查后面，是单独的后续 issue（维护者 2026-11-12 同意）。

## 实现要点

- `apps/api`：先做一个不改行为的重构，让题目下面的孩子接口（作答、草稿和三个 AI 接口）都从同一个「孩子 + 题目」入口进来，现在它只确认孩子会话；之后访问检查只加在这个入口里。打开一道题由外层的组装文件按会话选孩子或家长的判断，再交给 `catalog` 的路由；`catalog` 不依赖 `learning`。预览作答放在 `learning` 里，和孩子作答共用判定。孩子的书的筛选、计数、新书和排列是 `learning/domain/bookshelf.ts` 里的纯函数。
- `libs/contracts`：`ProblemOpening`、`ProblemAccessDenied`、预览作答的请求和回答；孩子的书的 `counts`、`studiedAt`、`fresh` 和 `books` 参数；去掉 `CatalogResponse`。
- `apps/web`：凸起的按钮、筹码、卡片、列表块、进度条和立体封面做成 `shared/ui` 的公共部件；首页按会话选登录页或「我的书」，登录页复用 `AccountLayout`、孩子和家长的登录组件；孩子的顶栏替换现在的网站导航，`/child` 转到首页；书的卡片头部是展开按钮（`aria-expanded`、`aria-controls` 指向题目列表）；加载方式按 `(pointer: coarse)` 选自动加载或按钮；`ProblemPage` 先看会话，再按 `mode` 和 `reason` 选画法；课堂页面收到的不再是可有可无的 `csrf`，而是「做题模式（孩子的 CSRF）」或「预览模式（家长的 CSRF）」两种之一：预览模式用同一个画面和同一套反馈，作答和提示走预览接口，不放话筒、提问和草稿，加上「预览」标记。
- 题目页的 `LessonRoute` 和 #210 的课堂记录都改这一带，合并时按顺序处理。

## 考虑过但没采用

- **访客首页保留题库，只是题目打不开**：维护者要求访客什么都看不到。
- **只在页面上隐藏没安排的书**：直接请求接口仍能拿到题目和作答，不算访问控制。
- **没安排的书回答 404**：和「题目不存在」分不开，页面没法提示请家长安排；书名和安排给谁都不说，403 不泄露别人的信息。
- **孩子首页保留年级、学科、分类三个选择**：选择框表达不了新书在前、最近学过的在前；按书排成一列和 #179 的「我的练习」一致。
- **孩子的顶栏保留孩子空间、孩子注册和家长空间**：首页就是孩子的空间，孩子已经注册，家长空间不是孩子要去的地方；只留头像菜单里的退出。
- **单独一个「新安排」筛选**：维护者不要；新书就是在学的书，排在最上面，红点放在「在学」上。
- **展开题目列表就算不新了**：孩子展开看一眼就消掉了提醒；要打开一道题才算开始做这本书（维护者确认），也就不需要单独的「标成打开过」接口。
- **收起时露出第 1 道题**：第 1 道题因此比别的题更显眼；收起时只有书名、进度和「全部 n 道」。
- **把书里的题全部摆在页面上**：几本书就把页面拉得很长，题名还被挤成几个字。
- **用下拉框或弹出层列题目**：手机上下拉框的选项小、不好滑，弹出层盖住书架；在页面上原地展开，一行一道，手指滑和点都顺手。
- **暂时不可用的书点题时弹提示**：理由已经写在展开的列表最上面，再弹一次是重复的打扰。
- **手机上也用「加载更多」按钮**：手机上滑到底自然就该接着出现；电脑上滚轮停下来常常是还在看，按钮让孩子自己决定。
- **预览不判答案、只看短片**：家长看不到孩子在作答那一步会遇到什么；判定在服务器上、不记录，代价是一个只读的接口。
- **预览里也能语音作答和提问**：要调用付费的 AI，家庭授权管的是孩子的输入；预览用点选就够看清这一步。
- **只能预览安排给自家孩子的书**：家长最需要预览的时候是安排之前。
- **把课堂代码放到登录以后才发**：部署方式要变，作为后续 issue。
