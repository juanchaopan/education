# 题目的版本：孩子的版本、按题和按版本的学习摘要

- 状态：规则由维护者 2026-11-15 在 [#219](https://github.com/juanchaopan/education/issues/219) 定下；页面的样稿还没画，每个改页面的 issue 先出桌面和手机的样稿给维护者确认。标着「默认」的几条是写设计时取的默认做法，维护者可以改，见[变更记录](../changes/2026-11-15-problem-versions-summary.md#决定)。
- 需求：REQ-005、REQ-009（2026-11-15 修改）。代码结构的调整见 [题目版本的代码结构](refactor/problem-versions.md)。
- 涉及：`libs/problems`（按题列出全部版本）、`libs/contracts`（打开一道题、选版本、按题的学习摘要、按版本的详情）、`apps/api` 的 `learning`（孩子的版本、选版本、学习摘要、详情）、`apps/web` 的题目页（问要不要试新版本）、孩子的书和家长空间的学习记录。书、安排和 n / m 进度照 [家长书架](bookshelf.md)，访问检查照 [孩子只学安排的书](book-access.md#服务端的检查)，变化题的判定和记录照 [变化题作答记录](variation-records.md)。

## 为什么这样设计

题目会出新版本：讲法换了、台词改了、变化题加上了。孩子在旧版本上做到哪里，就是做到了哪里，新版本不能让做完的题看起来又没做完，也不能把做到一半的课突然换掉。所以新版本不动孩子的进度，只在孩子打开这道题时问一句要不要试试，孩子自己决定。

家长要看的是一道题孩子做到了什么，不是每个版本各几次。所以学习摘要按题列，每道题一项，只说独立完成、提示后完成还是还没完成；想看每个版本时点进这道题。不同的课堂流程留下的证据不一样（逐幕探究有原题和变化题），所以两页上显示什么按流程设计。

## 用到的词

| 词               | 意思                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 版本             | 题目清单里一道题的一个版本，编号从 1 起。题目清单里还有的版本叫在清单里，不在的叫已下架                                                                            |
| 最新版本         | 题目清单里这道题编号最大的版本                                                                                                                                     |
| 孩子做过一个版本 | 孩子在这个版本上提交过最终作答、要过提示或在作答时向老师提问（记为帮助的那种）、交过变化题的猜数或理由，或者选了这个版本（默认）。只打开题目、看短片、存草稿都不算 |
| 孩子的版本       | 孩子做过的、还在清单里的版本里编号最大的那个；孩子在这道题上没做过任何还在清单里的版本时，就是最新版本                                                             |
| 新版本           | 比孩子的版本编号大的最新版本。孩子的版本就是最新版本时，没有新版本                                                                                                 |

孩子的版本只往上走：孩子选了新版本以后，回不到旧的版本。

## 孩子这边

### 打开哪个版本

| 孩子在这道题上                             | 书里这道题打开的版本 | 打开时问不问             |
| ------------------------------------------ | -------------------- | ------------------------ |
| 没做过                                     | 最新版本             | 不问                     |
| 做过的最高版本就是最新版本                 | 最新版本             | 不问                     |
| 做过旧版本，还没选新版本（做完或做到一半） | 孩子的版本（旧的）   | 每次打开都问             |
| 选了新版本                                 | 新版本               | 不问，直到再出新版本     |
| 做过的版本都已下架（默认）                 | 最新版本             | 不问：原来的版本打不开了 |

- 不点进题目时，孩子看到的一切都不受新版本影响：书卡上的勾、进度条的 n / m、「在学」「学完」的分组、新书标记和「最近学过」都照常。n / m 仍是「任何版本做完都算」（[进度](bookshelf.md#进度)）。
- 孩子的书里每道题的链接指向孩子的版本，题名也取孩子的版本的题名。
- 孩子从别的链接（例如家长转发的）打开了这道题的另一个版本时，题目页换成孩子的版本的地址（替换历史记录里的这一条），再按上表问不问。孩子只在一个版本上做这道题。
- 草稿按版本存（[ADR-0005](../adr/0005-data-consistency.md)）。孩子选了新版本以后，旧版本的草稿留在服务器上，照常在最后编辑 7 天后过期，选的时候不删。
- 家长的预览模式打开地址里的版本，从来不问。

### 问要不要试新版本

孩子以做题模式打开一道有新版本的题，片名卡上先不出「开始」，画面虚化，小兔站在左边，旁边一块烟色玻璃卡片，和题目页的其他提示卡一样（[题目页](book-access.md#题目页)）：

| 部分   | 内容                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------- |
| 小兔说 | 「这道题有新版本了，要试试吗？」字幕里写这一句，同时放这一句的录音（公共题目页的录音，和旁白同一个声音） |
| 主按钮 | 「试试新版本」，金色凸起的胶囊                                                                           |
| 次按钮 | 「接着做原来的」，透明玻璃胶囊                                                                           |

- 只说「新版本」「原来的」，不说「版本二」「第 2 版」这样的编号。
- 读屏进入页面时读这一句；焦点在主按钮上。录音放不出来时字幕照样显示，按钮照样能按。
- **试试新版本**：按钮变平、圆点代替文字，页面发选版本的请求（见[接口](#接口)）；成功后换成新版本的地址（替换历史记录），新版本从片名卡开始，以后打开都不问。没成功时按钮恢复，下面一行「没换成，再点一次。」，孩子也可以点「接着做原来的」。
- **接着做原来的**：卡片收起，片名卡照常；有草稿时照常出「从上次的地方继续」和「从头做」。什么都不记，下次打开这道题还问。
- 返回露珠照常在左上角，孩子可以什么都不选就回到「我的书」。
- 课堂进行中出了新版本（例如新部署），这一次不打断，下次打开时再问。

## 家长这边

### 结果只有三种

一个版本里，原题和变化题的每一项都只给三种结果之一，不给次数：

| 结果       | 胶囊的样子                                         | 意思                                   |
| ---------- | -------------------------------------------------- | -------------------------------------- |
| 独立完成   | 绿                                                 | 这个版本里有一次没用帮助就做到了       |
| 提示后完成 | 蜜黄                                               | 没有独立做到，有一次用了帮助以后做到了 |
| 还没完成   | 素色                                               | 做过这个版本，这一项还没做到           |
| 没做过     | 虚线框、透明底、次要文字色；只在按版本的详情页上用 | 孩子没做过这个版本，整个版本一枚       |

胶囊的样子是维护者在 [#219 的样稿](../evidence/219/README.md) 里选的 B，和「这段时间」卡片里每道题右边的徽章一样；颜色只是呼应，字写明了结果。

一个版本的每一项怎样得出（做到过一次就算做到，后来哪一次做差了不改变结果，和[变化题每道题的状态](variation-records.md#每道题的状态)一样）：

| 项         | 独立完成               | 提示后完成                     | 还没完成                                                 |
| ---------- | ---------------------- | ------------------------------ | -------------------------------------------------------- |
| 原题       | 最终作答有一次独立完成 | 没有独立完成，有一次提示后完成 | 其余：只答错过、只判不出、只要过提示，或者只选了这个版本 |
| 变化题猜数 | 有一轮猜数独立答对     | 没有独立答对，有一轮提示后答对 | 其余，包括原题还没答对、还没开始变化题                   |
| 变化题理由 | 有一轮理由最后独立说清 | 没有独立说清，有一轮提示后说清 | 其余，包括还没说理由就离开                               |

### 按课堂流程显示什么

两页上一个版本显示哪几项，由这个版本的课堂流程决定。设计一种新的课堂流程时，要在这张表里加一行（[手册的课堂流程清单](interactive-lesson-authoring.md#课堂流程清单)）；代码里这张表是一个按流程取的对象，加了流程没加这一行时类型检查不通过。

| 流程                                   | 显示的项                                   | 例子                                                         |
| -------------------------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| 逐幕探究，声明了变化题                 | 原题；变化题的猜数和理由                   | 「原题 独立完成」「变化题　猜数 独立完成 · 理由 提示后完成」 |
| 逐幕探究，没有变化题                   | 原题                                       | 「原题 提示后完成」                                          |
| 列式求解                               | 原题（变化题怎样显示等维护者决定，见下面） | 「原题 还没完成」                                            |
| 没有课堂内容的题；已下架的版本（默认） | 原题：只看得出最终作答                     | 「原题 独立完成」                                            |

**待维护者决定。** 手册的[列式求解](interactive-lesson-authoring.md#列式求解)写着它有变化题，数轴追及的变化题记录由 [#248](https://github.com/juanchaopan/education/issues/248) 接上；维护者 2026-11-15 说只有逐幕探究有原题和变化题。列式求解的变化题记下来以后，学习摘要是照逐幕探究显示猜数和理由，还是只看原题，由维护者决定；决定以前它只显示原题。

### 学习摘要（按题）

家长空间「学习记录」页的学习摘要卡片（[家长总览](family-overview.md#学习记录familylearning)）：

- 最上面一行全部记录的累计「一共做过 38 道题 · 学了 6 小时 20 分」，和它下面的一行提示「当前记录不足以判断是否掌握。」照常。
- **每道题一项**，孩子做过的每道题都在（包括已经不在清单里的题），按题目 id 排，每页 20 道，底部加载更多。
- 一项显示的是**孩子做过的编号最大的版本**，不论它在不在清单里：孩子在第 1 版做完、答应试新版本以后，这里显示第 2 版，第 2 版还没做完就是还没完成。这一项不写版本号，孩子在哪个版本上只在详情页看得到。
- 一项从上到下：
  1. 题名：显示的那个版本的题名；那个版本已下架时取最新版本的题名；整道题都不在清单里时写题目 id。
  2. 结果：按上一节的表，一行胶囊。原题是「原题」加一枚胶囊；有变化题时后面隔开是加粗的「变化题」，再是「猜数」「理由」各一枚。手机上按段换行，「猜数 独立完成」这样的一段不从中间断开。
  3. 建议复习时下面一条黄色的「优先复习 · 这道题答错过几次，还没有独立完成。可以和孩子回顾思路，再让孩子独立试一次。」规则：把孩子做过的这道题的所有版本合起来，答错两次以上、而且没有一次独立完成（REQ-005）。不写次数。
  4. 整项是一个链接，右边一个向右的箭头，读屏读「一棵青菜有多重，看每个版本」，去这道题的[按版本的详情](#按版本的详情)。
- 「怎么统计」（折叠）：「每道题显示孩子做过的最新的那个版本。孩子答应试新版本以后，这里显示新版本，新版本还没做完时是还没完成。一个版本里做到过一次就算做到。孩子说的话不保存，这里只有判定结果。」
- 没有记录时一行「还没有这位孩子的学习记录。」；读取中、没读出来和加载更多的样子照常。

### 按版本的详情

地址 `/family/learning/problems/:problemId?child=<id>`，从学习摘要的一项点进来。

- 顶上：返回「学习记录」（回到 `/family/learning?child=<id>`，地址里原来的日子照带），题名，孩子的头像和昵称。
- 下面列出这道题的版本，编号大的在上，每个版本一块卡片：
  - 标题「第 2 版」，旁边的小签：最新版本是「最新」；孩子的版本是「小米在做这一版」；已下架的是灰色的「已下架」。
  - 孩子做过的版本：按[流程](#按课堂流程显示什么)显示原题和变化题的胶囊，原题一行、变化题一行，分开写。
  - 孩子没做过的版本：一枚「没做过」。
- 列出的版本：清单里这道题的每个版本，孩子做没做过都列；再加上已下架、但孩子在上面有记录的版本。已下架、又没有记录的版本不列。
- 孩子在这道题上什么都没做过（例如从旧的链接进来）时，每个版本都是「没做过」，没有「在做这一版」。
- 读取中是两块卡片的骨架；没读出来时一行「这道题的记录没有读出来。」和「重试」；这道题既不在清单里、孩子也没有记录，或者孩子不在这个家庭，是空状态「找不到这道题的记录」和「回到学习记录」。
- 家长从这里看不到孩子说的话，只有判定结果。

### 总览的「值得再练」

规则照 REQ-005 按题判断。每一行打开**孩子的版本**（预览模式），题名取孩子的版本的题名；行里写「小米 · 还没独立完成」，不写答错的次数。

### 家庭导出

导出照原样（默认）：学习摘要按每个版本列出次数，格式和版本号都照 [家庭导出](family-overview.md#家庭导出和删除) 和 [变化题的导出](variation-records.md#家庭导出)。选版本的记录不导出：它只决定孩子打开哪个版本，和书的打开标记一样。

## 数据

**`child_problem_versions`**：孩子选过的版本，每个孩子每道题一行。

| 列           | 类型                      | 说明           |
| ------------ | ------------------------- | -------------- |
| `child_id`   | uuid，引用 `children(id)` | 随孩子级联删除 |
| `problem_id` | text                      | 题目 id        |
| `version`    | bigint，至少 1            | 孩子选的版本   |
| `decided_at` | timestamptz，默认 `now()` | 选的时间       |

- 主键是孩子加题目；开启行级安全，和其他学习表一样。
- 写入是插入或取较大的版本（`ON CONFLICT ... DO UPDATE SET version = GREATEST(...)`），版本变大时才更新 `decided_at`；孩子的版本只往上走，重发的请求也安全。
- 「接着做原来的」不写任何东西。
- 孩子做过哪些版本从 `progress`（最终作答）、`help_events`（提示和作答时的提问）、`variation_answers`、`variation_help` 和这张表合起来读出，不另存。
- 删除家庭时跟着孩子一起删除；不进家庭导出；备份的逐表行数自动包含它。
- 迁移只加一张表，编号按合并时的顺序取下一个。

## 接口

都在 `/api/v1` 下，鉴权、来源检查、CSRF 和不缓存照现有的孩子和家长接口。

### 打开一道题

`GET /problems/:id/:version` 的回答 `ProblemOpening`（[回答](book-access.md#回答)）在做题模式多两项：

| 字段    | 什么时候有           | 意思                                               |
| ------- | -------------------- | -------------------------------------------------- |
| `yours` | 做题模式             | 孩子的版本；和地址里的版本不同时，页面换成它的地址 |
| `newer` | 做题模式，有新版本时 | 新版本的编号；有它时页面先问要不要试试             |

预览模式两项都没有。`GET` 只读，不写选版本的记录（[ADR-0009](../adr/0009-account-security-spike.md)）。

### 孩子：选新版本

`POST /problems/:id/:version/choice`，孩子会话，请求体 `{}`，回答 204。地址里的版本就是孩子选的版本。

- 和题目下面其他孩子的接口一样从同一个「孩子 + 题目」入口进来，按[服务端的检查](book-access.md#服务端的检查)判断能不能打开：没安排 403 `unassigned`，书暂时不可用 403 `unavailable`，题目或版本不在清单里 404。
- 选的版本不比孩子的版本大时什么也不变，照样 204。
- 请求体里有字段：400。

### 孩子的书

`GET /children/assignments`（[孩子的书](book-access.md#孩子的书)）里每本书的 `items[].version` 和 `title` 是孩子的版本和它的题名；`done` 仍是任何版本做完都算。

### 家长：总览

`GET /parents/overview` 的 `review` 是 `[{ id, version, title }]`：`version` 和 `title` 是这个孩子的版本，不带答错的次数。

### 家长：学习摘要

`GET /parents/children/:childId/learning-summary?offset=` 回答：

```text
{
  childId,
  problems: [{                     // 每道做过的题一项，按题目 id 排，每页 20 道
    id, title,                     // title 取法见「学习摘要（按题）」，整道题都不在清单里时为 null
    result: VersionResult,         // 孩子做过的编号最大的版本的结果
    reviewSuggested                // 按 REQ-005 把所有版本合起来判断
  }],
  hasMore
}
```

### 家长：按版本的详情

`GET /parents/children/:childId/problems/:problemId/versions` 回答：

```text
{
  id, title,                       // 题名取最新版本的，整道题都不在清单里时取孩子做过的最大版本的，都没有时为 null
  yours,                           // 孩子的版本；孩子在这道题上什么都没做过时为 null
  versions: [{                     // 编号大的在前
    version,
    latest,                        // 是不是最新版本
    listed,                        // 在不在题目清单里；false 时页面写「已下架」
    result: VersionResult | null   // null 表示没做过
  }]
}
```

孩子不在这个家庭，或者这道题既不在清单里、孩子也没有记录：404。`problemId` 不合乎题目 id 的写法：400。

### 一个版本的结果

```text
Outcome = 'independent' | 'assisted' | 'not-yet'

VersionResult =
  | { flow: 'scene-by-scene', answer: Outcome, variation: { guess: Outcome, reason: Outcome } | null }
  | { flow: 'derive-and-solve', answer: Outcome }
  | { flow: null, answer: Outcome }      // 没有课堂内容的题、已下架的版本
```

`flow` 取这个版本的课堂内容里的流程。逐幕探究的 `variation` 在这个版本声明了变化题时才有。加一种课堂流程时，这里加一种，网页的显示表跟着加一行。

## 实现要点

- `libs/problems` 的注册表能按题列出清单里的全部版本，编号从小到大（`versionsOf`）。
- `learning/domain` 里是不依赖数据库的纯函数：孩子的版本（清单里的版本加孩子做过的版本，得出孩子的版本和新版本）、一个版本的结果（按流程，从这个版本的作答、帮助和变化题证据得出）、按题的一项（取做过的最大版本）。
- 仓储一次查出一个孩子一批题做过的版本和每个版本的证据，不按题逐道查；孩子的书、总览和打开一道题共用同一个「孩子的版本」的查询。
- 学习摘要和导出分开：导出用它自己的契约，学习摘要用按题的形状，导出的文件一个字也不变。
- 网页的学习摘要和详情页按 `flow` 从一张 `Record<LessonFlow | 'none', …>` 的显示表里取画法，展示组件只收数据。
- 问新版本的卡片放在公共题目页里，所有题共用，题目自己不写。

## 测试

- 测试注册表给一道题两个版本（只在测试里，不进入题目清单），所有版本的行为都用它测。
- 单元：孩子的版本的每一种情况（没做过、做过最新版本、做过旧版本、选了新版本、做过的版本都已下架、只做过一个已下架的旧版本而清单里还有更早的版本）；一个版本的结果的每一格；按流程的显示表（逐幕探究有和没有变化题、列式求解、没有课堂内容、已下架）。
- 接口，真实数据库：选版本写一次、重发不变、选更低的版本不变，没安排、暂时不可用 403，不在清单里 404，家长 401；打开一道题的 `yours` 和 `newer`，`GET` 不写；孩子的书和总览的版本跟着孩子的版本；学习摘要显示做过的最大版本、选了新版本还没做时是还没完成；详情页列出没做过和已下架的版本；别的家庭的孩子 404；导出的文件和改动前一样。
- 网页：问新版本的卡片的每个状态（问、正在换、没换成），换了以后地址变成新版本、以后打开都不问；从别的版本的链接进来换成孩子的版本；预览不问；学习摘要一项的每种结果和流程；详情页的每种小签和状态（Storybook、视觉基准，白天和晚上，桌面和手机）。
- e2e：孩子做过旧版本，打开时被问，留在原来的，下次再问；选新版本以后家长的学习摘要显示还没完成，详情页两个版本都在。

## 考虑过但没采用

- **出了新版本就把孩子挪过去**：做完的题会看起来又没做完，做到一半的课也会被换掉。
- **只问一次**：孩子点了「接着做原来的」以后再也不知道有新版本；每次打开都问，孩子随时可以换。
- **记下「留在原来的」**：记了也还要再问，记它没有用处。
- **对孩子说「版本二」**：孩子不需要知道编号，「新版本」「原来的」就够了。
- **学习摘要一行一个版本、列出次数**：家长要逐行对哪几行是同一道题，次数也说不清孩子做到了没有。
- **学习摘要取所有版本里最好的结果**：孩子在新版本上还没做到的事会被旧版本盖住；显示孩子做过的最大版本，家长看到的就是孩子眼下做的这一版。
- **变化题还没开始时写「最终答对以后才做」**：结果只有三种，没做到就是还没完成；变化题要在原题答对以后才做，课堂上本来如此。
- **把选版本的记录写进导出**：它只决定打开哪个版本，学习的证据都在作答记录里。
