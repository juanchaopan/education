# 视觉基准与可访问性检查

界面外观由经维护者评审的截图基准固定，可访问性由同一套测试自动检查。目标见 [架构总览的视觉验证](../architecture/overview.md#视觉验证已确认) 和 [ADR-0003](../adr/0003-web-details.md)。

## 固定环境

截图取决于浏览器版本和系统字体，所以测试只在官方 Playwright 镜像里运行：`mcr.microsoft.com/playwright:v<版本>-noble`，版本号取自 `package-lock.json` 里安装的 `@playwright/test`。镜像固定了 Chromium 和字体；中文由镜像自带的文泉驿正黑（WenQuanYi Zen Hei）渲染。升级 Playwright 会换镜像，基准要随之重新生成并评审。

本地和 CI 运行的是同一个命令 `npm run test:visual`（`scripts/visual.mjs`）：把仓库复制进容器（不带 `node_modules` 和构建产物），在容器里 `npm ci`、构建应用和 Storybook，再运行 `playwright.visual.config.ts`。本机需要 Docker 正在运行；本机的 `node_modules` 不会被改动，写回的基准和测试结果归仓库的所有者。环境变量 `CI` 会传进容器，CI 里因此禁止 `test.only`、失败重试一次。所有视口按 1 倍像素截图，基准只用来发现布局、换行和颜色的变化。

`--` 之后的参数原样交给 Playwright，例如用 `npm run test:visual -- -- --grep 孩子登录` 只比对部分测试，或在内存紧张时用 `-- -- --workers=2` 减少同时打开的浏览器。

## 覆盖范围

每个截图在桌面（1280×720）、平板（iPad 810×1080）和手机（iPhone 13 390×664）三个视口各有一张基准，放在 `visual/<测试文件>-snapshots/<视口>/`。

| 测试                    | 内容                                                                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stories.spec.ts`       | Storybook 里的每个 story：各组件的正常、空、加载中、失败、长文字和“再听一遍”等状态。截图后对 story 运行 axe                                                |
| `pages.spec.ts`         | 关键页面的整页截图：题库的空、加载中、失败和长标题，题目不可用，家长空间未登录、会话出错和注册关闭，孩子登录，孩子注册，找回密码，两个缺少链接的页面和 404 |
| `accessibility.spec.ts` | 键盘、减少动画、触摸和缩放，见下文                                                                                                                         |

页面测试不连数据库：每个 `/api` 请求都由测试按 `visual/api.ts` 和 `visual/pages.ts` 里的表固定回答，表里没有的请求会让截图测试和可访问性检查都失败。长标题等只是测试夹具，不进入题目清单。时钟固定在 2026-11-07 10:00（北京时间），语言为 zh-CN。

## 可访问性检查

| 方面        | 检查                                                                                                                                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WCAG 2.2 AA | 每个 story 和每个页面运行 axe（`wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22a`、`wcag22aa`），含对比度、名称和标签、链接不只靠颜色区分                                                                                       |
| 键盘        | 桌面视口逐个按 Tab：每个控件都能到达（一组单选按钮算一站），焦点处有至少 2px 的轮廓；第一站是“跳到主要内容”，按回车后焦点到主要内容                                                                                                |
| 减少动画    | 打开减少动画偏好后，页面上没有任何动画或过渡                                                                                                                                                                                       |
| 触摸        | 平板和手机视口里每个控件的宽和高都不小于设计令牌 `--touch-target`，也不小于 44 CSS 像素；包在标签里的控件量标签，句子里的链接按 WCAG 的行内目标豁免，独占一行的链接用 `StandaloneLink`。点按可以打开家长登录、勾选孩子的“记住”选项 |
| 缩放        | 320 CSS 像素宽（相当于 1280 屏幕放大到 400%）不横向滚动；640 像素宽、文字放大到 200% 时不横向滚动                                                                                                                                  |
| 不只靠颜色  | 告诉孩子或家长结果的状态（画板的区域反馈、AI 老师的反馈、没听清、声音没出来、PIN 或登录错误、KEY 无效）在状态或提示区域里有文字                                                                                                    |

## 更新基准

基准不会被普通运行写入：配置里 `updateSnapshots: 'none'`，缺少或不同的基准都让测试失败。外观有意改变时：

1. 运行 `npm run test:visual -- --update`。它运行全部测试、重新生成 `visual/*-snapshots/` 下的全部基准，已不存在的 story 或页面的旧基准随之删除。因为会整体替换基准，它只接受 `-- --workers=<n>`，不接受 `--grep` 之类的筛选。
2. 用 `git status` 和 `git diff --stat` 看哪些图变了，逐张对照新旧图；改动和代码放在同一个 PR。
3. PR 里写明哪些页面或组件的外观变了。`*-snapshots/**` 属于高风险路径，由维护者看过图后加 `human-reviewed`。

CI 的 `visual` job 失败时，下载 `visual-diff` 产物：每个失败的截图都有基准图、实际图和差异图。本地运行失败时，同样的文件在 `test-results/visual/`。

## 不能由截图代替的检查

截图和自动检查不能代替真实设备：手机和平板上的真实触摸、系统缩放、屏幕阅读器朗读、麦克风和声音，需要在真机上补充确认。
