# 逐题设计互动教学与验收手册

适用于接入真实题目的设计者、开发者和审核者。依据 [REQ-001、003、004、005](../product/requirements.md)、[#48](https://github.com/juanchaopan/education/issues/48) 的样例评审和维护者反馈。新题先完成内容与教法评审，再进入开发。每个题目版本都要独立过验收。

## 用户要求与实现方法

| 用户要求                                                     | 开发方法                                                                                                                                                       | 观察得到的证据                                                                                                           |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 一进来像有声动画。画面饱满，有 2.5D 或 3D 的空间和可操作对象 | 先编导本题场景。用前景、中景、背景和光影构造深度。把数学对象放在可交互的层，保留形状、触碰范围和运动因果。按年级调节密度与节奏                                 | 开场截图及首个操作录像。能从实际道具判断哪里可以点、拖、划线                                                             |
| 像短片一样一步步引导。每次只推进眼下的发现                   | 用本题的分镜和状态转移控制揭示。每幕写清孩子先想什么、动哪个对象、会看到什么、为什么现在能推到下一幕。跨幕保留关键对象或用动画交代它去了哪里                   | 分镜稿与从第一幕到最后一幕的录像。逐个说得出前一幕为下一幕提供了什么                                                     |
| 直接点、拖或划想操作的对象。下一步看得见                     | 把命中区覆到整个物体或整行。每次只重点高亮当前对象，用轮廓、轻晃、箭头或短声。保留点击或键盘替代动作、减少动态效果时的静态标记                                 | 鼠标、触屏和键盘验证。点对象边缘、行空白和标签也能触发。减弱动画时仍能找到目标                                           |
| 每次操作都在帮孩子理解，错了还能继续                         | 先提出能预测的问题，再让对象用平衡、变化、对照等方式反馈。提示给下一件可尝试的事。开放范围的控件设计越过、反向、误点、空拖、取消和停滞时的继续路径             | 正常路径及偏离路径录像。无精确像素、精确时刻或隐蔽热区阻塞；看到具体反馈后能再试                                         |
| 方程要从题目情境里推出来。“像积木”指对象的质感               | 先让孩子观察或操作量，再将动作与数学表示同步。每个数字、符号和项能指回图中一个量或关系。初级题按需用可见分组、比较和变化题呈现规律；高年级再逐段生成式子和分支 | 式子各部分与图中证据的对应清单。解释为什么选该运算、为什么有多个解。学生活动围绕量和关系，删去纯粹拼数字或符号的通关要求 |
| 旁白自然、有断句、能听清。声音结束后才走到对应的下一幕       | 按教学动作拆短句，给观察和作答留停顿。以媒体实际结束事件和动作完成为推进条件，时长不能靠固定延时猜。字幕同步；重听、静音或加载失败时仍有可见提示与继续路径     | 真人试听和屏幕录制。快点、慢点、重听、静音和音频故障逐项复核。机器能检测是否截断，不能替人判断声线和断句适合孩子         |
| 开放式语音问题应能问到当前这题、这一步                       | 正式接入时，经授权的 AI 只接收必要的题目版本、当前幕、对象与操作摘要、确认过的转写。模型给具体提示，确定数学判定交给题目规则。不确定则确认或请孩子换种表达     | 正常追问、识别不确定、权限拒绝、超时与静态提示降级证据。遵循 [ADR-0012](../adr/0012-browser-voice-touch-spike.md)        |
| 孩子能举一反三                                               | 用能区分理解与模仿的变化题，改变一个关键条件、位置或问法。先让孩子预测，再观察其解释或操作。记录首答、提示、理由和复试，分别报告独立与辅助完成                 | 题目与变化题对应关系、无提示试做记录。正确数字或看完动画只算有限证据                                                     |

技术实现可选。样例采用 2.5D 绘景、SVG 独立对象、CSS/浏览器动画、Pointer Events、显式分镜状态、内嵌短句录音与音效。正式方案可以换工具，需满足相同的体验和验收。共享候选是音画时序、提示、对象命中、重试和评估证据。题目自己的教学结构与表现形式由题目决定，等多个实际案例验证后再由 #31 决定共享边界。

## 开发流程

1. **核对原题。** 记录来源、页码、版本、适用年龄、正确答案、解法和歧义。区分题目素材与附带说明。缺关键题图、题意不明确或答案未校验时，先补资料。
2. **找思考障碍。** 写清孩子现在可能怎样想、在哪一步容易误解、学完要能解释什么。给每个典型错误写一句可执行的提示。
3. **画分镜并录短句。** 先做画面流和一张可点原型，再补全动画。每幕用下方卡片描述，标出对象怎样从上一幕来到这一幕。朗读先实际试听。
4. **实现并分层验收。** 先验证数学规则，再测儿童能否从画面中找到下一步，最后查音画和触屏。录一条完整路径，另外录一条包含误操作、停滞或重听的恢复路径。
5. **送审并返工。** 开发者填自查表，另一位评审者从空白状态试做。任何必过项缺证据、失败或只有实现者知道怎么继续，都退回该题修改并重跑相关路径。正式上线还需独立理解证据和可用语音的实际验收。

## 可复用的逐题自查卡

复制到每题的设计稿或 PR，逐项填入 `通过 / 失败 / 待验证` 和证据链接。可标记不适用，但要说明原因并由评审者认可。失败或待验证禁止标为通过或宣布达到验收。

```text
题号、版本、来源页、年龄
数学目标、标准答案、候选解法、需要维护者核对的歧义
最可能的误解
变化题、预期理由、独立成功判据

每幕填写一行
幕 | 想让孩子先想什么 | 此刻出现的对象 | 下一个高亮对象和动作
   | 看到及听到的反馈 | 这幕留下什么给下一幕 | 触发及音频完成条件
   | 误点/越过/停滞后的路径 | 首次提示与替代操作

E1 题意和问题在实际开场讲清楚，手机与桌面都能开始
E2 本题场景、道具和节奏能表现它的数学关系
E3 前后幕因果连续，关键中间关系实际出现
E4 每个要求的下一步有提示，整件对象命中，能按住、放下、取消或替代操作
E5 误操作、反向、拖过、停滞或重听后仍能继续
E6 正常和快速操作录屏均无抢话或字幕错位，试听者确认断句、语速、声线
E7 答案和每个数学符号能从画面解释，没有凑答案或盲猜过关
E8 变化题能观察理由，受提示结果单独记录
E9 开放追问、权限、转写不确定和降级已验证，或如实标记当前未接入
E10 实际浏览器、触屏、键盘、静音和减少动态效果已验证
每项填写：状态 | 检查输入/设备 | 预期与实测 | 证据 | 修复后复测

评审结论：通过 / 退回
```

## 三种样例的回归入口

- **菜园天平。** 确定第一个等量关系后，保留原秤逐个替换。每次替换要能看到秤仍然平衡。改变每组数量，问什么变了、什么没变。
- **彩铅。** 固定红，只找右侧，再移到橙。用已经保留的红橙卡解释跳过红色。最后各行完整可点，闪动框标出下一排。按任意速度完成，上一段旁白必须播完，重复点同行不会多记一份。
- **数轴追及。** 时间轮拖过关键时刻也能记录，卡住可沿轨道找到下一次。孩子依次从起点间隔、相对速度、跨过相遇点的方向和题目目标看出式子如何长出来。检查错误地只取正分支时会遗漏哪次。
