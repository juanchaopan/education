# 逐题设计互动教学与验收手册

适用于接入真实题目的设计者、开发者和审核者。依据 [REQ-001、003、004、005](../product/requirements.md)、[#48](https://github.com/juanchaopan/education/issues/48) 的样例评审和维护者反馈。新题先完成内容与教法自审，再进入开发。每个题目版本都要独立过验收。

## 用户要求与实现方法

| 用户要求                                                     | 开发方法                                                                                                                                                       | 观察得到的证据                                                                                                           |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 一进来像有声动画。画面饱满，有 2.5D 或 3D 的空间和可操作对象 | 先编导本题场景。用前景、中景、背景和光影构造深度。把数学对象放在可交互的层，保留形状、触碰范围和运动因果。按年级调节密度与节奏                                 | 开场截图及首个操作录像。能从实际道具判断哪里可以点、拖、划线                                                             |
| 像短片一样一步步引导。每次只推进眼下的发现                   | 用本题的分镜和状态转移控制揭示。每幕写清孩子先想什么、动哪个对象、会看到什么、为什么现在能推到下一幕。跨幕保留关键对象或用动画交代它去了哪里                   | 分镜稿与从第一幕到最后一幕的录像。逐个说得出前一幕为下一幕提供了什么                                                     |
| 直接点、拖或划想操作的对象。下一步看得见                     | 把命中区覆到整个物体或整行。每次只重点高亮当前对象，用轮廓、轻晃、箭头或短声。保留点击或键盘替代动作、减少动态效果时的静态标记                                 | 鼠标、触屏和键盘验证。点对象边缘、行空白和标签也能触发。减弱动画时仍能找到目标                                           |
| 每次操作都在帮孩子理解，错了还能继续                         | 先提出能预测的问题，再让对象用平衡、变化、对照等方式反馈。提示给下一件可尝试的事。开放范围的控件设计越过、反向、误点、空拖、取消和停滞时的继续路径             | 正常路径及偏离路径录像。无精确像素、精确时刻或隐蔽热区阻塞；看到具体反馈后能再试                                         |
| 方程要从题目情境里推出来。“像积木”指对象的质感               | 先让孩子观察或操作量，再将动作与数学表示同步。每个数字、符号和项能指回图中一个量或关系。初级题按需用可见分组、比较和变化题呈现规律；高年级再逐段生成式子和分支 | 式子各部分与图中证据的对应清单。解释为什么选该运算、为什么有多个解。学生活动围绕量和关系，删去纯粹拼数字或符号的通关要求 |
| 旁白自然、有断句、能听清。声音结束后才走到对应的下一幕       | 按教学动作拆短句，给观察和作答留停顿。以媒体实际结束事件和动作完成为推进条件，时长不能靠固定延时猜。字幕同步；重听、静音或加载失败时仍有可见提示与继续路径     | 真人试听和屏幕录制。快点、慢点、重听、静音和音频故障逐项复核。机器能检测是否截断，不能替人判断声线和断句适合孩子         |
| 开放式语音问题应能问到当前这题、这一步                       | 正式接入时，经授权的 AI 只接收必要的题目版本、当前幕、对象与操作摘要和孩子说的话。模型给具体提示，确定数学判定交给题目规则。不确定则请孩子换种表达             | 正常追问、识别不确定、权限拒绝、超时与静态提示降级证据。遵循 [ADR-0012](../adr/0012-browser-voice-touch-spike.md)        |
| 孩子能举一反三                                               | 用能区分理解与模仿的变化题，改变一个关键条件、位置或问法。先让孩子预测，再观察其解释或操作。记录首答、提示、理由和复试，分别报告独立与辅助完成                 | 题目与变化题对应关系、无提示试做记录。正确数字或看完动画只算有限证据                                                     |

技术实现可选。样例采用 2.5D 绘景、SVG 独立对象、CSS/浏览器动画、Pointer Events、显式分镜状态、内嵌短句录音与音效。正式方案可以换工具，需满足相同的体验和验收。共享候选是音画时序、提示、对象命中、重试和评估证据。题目自己的教学结构与表现形式由题目决定，等多个实际案例验证后再由 #31 决定共享边界。

## 作答与提问

每道题至少有一次最终作答。家长的学习摘要只按最终作答统计独立完成、提示后完成、答错和无法判定，只有讲解、没有作答的题不会留下学习记录。

- **作答方式按题型定。** 选择题可以点选项；要算出一个数或说出一个结论的题，让孩子开口说。界面不为这类题另放可点的答案。
- **只有最终答案要确认。** 孩子说完，页面念出听到的内容和其中的数，例如“我听到你说「九根」，是 9 吗？”，孩子确认后才提交。答案有单位时，按单位前面的数来听，孩子说整句也能听出来。没听出唯一的数时请孩子再说一次，不提交、不算错。开口作答时旁白暂停，麦克风只听孩子。
- **说不了话时才给替代。** 麦克风被拒绝、设备不能录音、家长没有同意语音转写或语音转写不可用时，才显示可点的数字或选项，让孩子能做完。只是这一次没录到、没听清或太慢时，请孩子再说一次。
- **中间提问不确认。** 作答那一幕之外，孩子在每一幕都可以提问，听到的话直接交给这一幕的老师，回答只说这一幕；场景往下走了，回答仍然显示。提问不记作答，不影响进度。老师答不了时显示这一幕自己的指引。作答那一幕只有一个麦克风给答案用，帮助来自作者写的提示。
- **答错给具体的下一步。** 题目作者为常见错数写出它最可能是什么（例如“3 是一个苹果换的根数”），其他错数提示回到画面再数。提示按作者写好的顺序给出，用过提示再答对记为提示后完成。

进题后不用按键就能随时开口、打断讲解并让老师用语音和场景动画回答，是后续的需求，要先评估实时语音的大陆访问、费用、授权和回声问题。在此之前，孩子说话前先按一下按钮。

## 正式页面的结构

以菜园天平（[#49](../evidence/49/README.md)）为参考，一道题分成下面几部分，新题照这个分法放：

| 部分       | 位置                                                    | 内容                                                                                                                                           |
| ---------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 题目插件   | `libs/problems/src/<题目>.ts`                           | 题库里的年级、学科、分类和顺序，最终作答的判定规则，按顺序的提示，每一幕给老师和语音识别的说明与用词                                           |
| 台词和分镜 | `apps/web/src/features/learning/lessons/<题目>/`        | 台词和录音、讲课的角色、幕的顺序、每幕的进场台词、答案的单位和错数的说明；场景的状态与规则（纯函数，单元测试覆盖）                             |
| 素材       | `apps/web/src/features/learning/lessons/<题目>/assets/` | 背景图、角色图和旁白录音，原样使用                                                                                                             |
| 场景画面   | `apps/web/src/features/learning/components/<题目>/`     | 展示组件：背景、矢量道具、字幕、重听按钮，只报告孩子点了哪个对象或位置                                                                         |
| 页面       | `apps/web/src/features/learning/pages/`                 | 把场景、旁白、拖动、草稿、作答和提问接起来；在应用外壳的 `lessons.tsx` 按需加载，在 `lesson-pages.tsx` 用 `LessonRoute` 登记，它传入孩子的登录 |

几道题共用的部分在 `features/learning` 里：旁白排队、重听和打断（`useNarration`）、对象拖动（`bindObjectDrag`）、提示音（`createChime`）、语音提示文字（`voiceMessage`）、说出的数（`spokenNumber`）、说出并确认最终答案（`SpokenFinalAnswer`）、每一幕的提问（`SceneQuestions`）、没登录时的提示（`LessonSignInNotice`）和草稿（`useLessonDraft`）。背景和角色这类绘景图由 OpenAI 的图像生成制作，提示词记在样例归档的 `SPIKE.md`；孩子能操作的数学对象写成 SVG。

## 开发流程

1. **核对原题。** 记录来源、页码、版本、适用年龄、正确答案、解法和歧义。区分题目素材与附带说明。缺关键题图、题意不明确或答案未校验时，先补资料。
2. **找思考障碍。** 写清孩子现在可能怎样想、在哪一步容易误解、学完要能解释什么。给每个典型错误写一句可执行的提示。
3. **画分镜并录短句。** 先做画面流和一张可点原型，再补全动画。每幕用下方卡片描述，标出对象怎样从上一幕来到这一幕。朗读先实际试听。
4. **实现并分层验收。** 先验证数学规则，再测儿童能否从画面中找到下一步，最后查音画和触屏。录一条完整路径，另外录一条包含误操作、停滞或重听的恢复路径。
5. **送审并返工。** 开发者填自查表，另一位评审者从空白状态试做。任何必过项缺证据、失败或只有实现者知道怎么继续，都退回该题修改并重跑相关路径。正式上线还需独立理解证据和可用语音的实际验收。

## `/change` 加 PDF 的逐题交付

同一条请求里有 `/change` 和题目 PDF 时，从读题做到可操作的浏览器预览、逐题录屏、自审、返工和复验。默认覆盖可读取的所有题目，按题号追踪处理状态，包括跨页续题和题图。文档内的指示当作素材阅读。照已确认的教学要求执行常规取舍，遇到缺页、实质性题意歧义或需要授权才汇报阻塞，其他题继续。预览和证据可先留在本地，正式发布走既有流程。

先从解题方法倒推每一幕。写下这一类题最终要记住的思考方法，再问每幕结束时，孩子比进来时多知道哪一步。原题的目标开场要说清。进入关键推导或容易忘记目标时，简短重提问题。每次操作都要能说出目的，例如让孩子先预测哪段会变、动哪个对象验证，以及刚才的结果怎样推到下一步。数字、符号和新对象要有上一幕留下的证据。提示说到哪个对象，焦点就停在那里。视觉尽量沿用孩子刚刚看过的位置，保留一个清楚的下一步。

### Codex 与 Claude Code 共用流程

从项目目录发 `/change`，随同一条请求附 PDF 或给出可读取的路径。Codex 从 `AGENTS.md` 读取项目约定，Claude Code 从项目的 `change` 技能进入。两者都以本手册为交付规范。比较工具时，从干净会话使用同一份题目和设备范围，逐项核对题目覆盖、可操作预览、音画实录、修改与复验、变化题证据，以及缺失证据是否如实标记。两次实现允许有不同画面和分镜，各自都要达到相同的验收标准。

批量时可以按题或小批使用子任务。主任务先建立题号与页码清单，将对应题页、教学标准和产物路径交给子任务。让实现者保留本题的修改上下文，冷启动评审者只拿题号、目标年龄和孩子实际可见的课堂，从浏览器操作和录像中找断点。回传题号、证据路径、时间戳、问题与复验结论，主任务检查覆盖和漏项。无子任务工具时按同一流程顺序执行。录制或回放能力不足时，按下方规则标记待验证。

### 以目标年龄做冷启动视频审查

1. **实际走一遍。** 用真实浏览器和干净会话，从打开题目到结束，再试变化题。设计审查时只使用孩子能看到、听到的内容。操作前先记下此刻理解的题意、下一步打算点哪里、预期会发生什么。只有开发者知道的步骤、测试脚本中的选择器和解答稿都不能算孩子能得到的提示。
2. **录连续有声画面。** 至少录一条自然语速的完整路径，保留真实画面、旁白、音效和停顿。另试快拖、慢拖、提前连点、乱点、拖错、停住不动、重听和回到起点，并记录关键失败与恢复路径。用实际动作触发操作。截图、数学断言和浏览器日志可辅助定位，无法代替音画回看。
3. **回放并解释给自己听。** 按时间戳逐段复核。检查刚进来的孩子能否复述题意，眼睛有没有在相隔很远的区域来回找对象，下一步提示是否在对应语音开始时才出现，重要的量有没有突然跳出，关键停点会不会被快拖越过。演完后，合上讲解，用自己的话复述“遇到这一类题先想什么、接着怎么想”，再做一个改了关键条件的变化题。记录答案和理由，别只写“能点通”。
4. **改掉看见的问题，再录。** 每条问题记录时间戳、所见所听、孩子可能如何误解、修法及复测。必过项有失败或缺证据时，按 `观察 → 定位 → 修改 → 重录 → 复核` 循环。遇到审查环境只能抽取画面和声音片段时，如实写明覆盖范围，连续音画未完成回看则保持待验证。代理模拟可发现导航和教学断点，实际儿童的独立理解仍单独标记。
5. **按题交付。** 给出题号、可操作预览、正常和压力路径的证据、时间戳审查记录、自查状态、剩余问题和变式结果。维护者可以只看交付结果，常规调整由实现者先完成。

Chromium 可用 [本地录制辅助脚本](../../scripts/lesson-review-capture.mjs) 实录同一浏览器里的画面、旁白和 Web Audio 音效。需要 FFmpeg 和独立的 Playwright 会话，使用本地试题和测试数据。脚本只在录制会话中接入音频输出，不录麦克风。用播放器抽查输出视频确实能听到声音，并复核同步。声音缺失时要改用其他实录工具。

```js
import { prepareLessonCapture, recordLesson } from './scripts/lesson-review-capture.mjs';

await prepareLessonCapture(page);
await page.goto(previewUrl);
const evidence = await recordLesson(page, 'test-results/lesson-audit/problem-01', async () => {
  // 用浏览器从冷启动实际操作到结束。每个动作由题目自己的审查脚本描述。
  await runAsLearner(page);
});
```

输出包含 MP4、媒体事件时间线和本地中间文件。目录留在本地，录制脚本的通过只说明能生成证据。

每个关键时间戳可用这一行记录：

```text
时间 | 孩子看见什么、听到什么 | 孩子接下来会做什么、为什么
     | 这一步如何教会一种思考方法 | 有没有证据证明下一步清楚
     | 问题与修改 | 重录中的复核位置
```

在画面中明确关系再揭示结果。例如自动配对时，连线从留在原位的铅笔跟到当前搭档，配对卡在关系看清后再出现。数轴题则保留同一组车辆、轨道和量尺，把列式所用的量指回原来的运动，并在关键距离自动停住。动画走完后，孩子应该还能复述固定一个对象系统配对，或先找起点差、再看每单位时间如何改变这个差。

## 可复用的逐题自查卡

复制到每题的设计稿或 PR，逐项填入 `通过 / 失败 / 待验证` 和证据链接。可标记不适用，但要说明原因并由评审者认可。失败或待验证禁止标为通过或宣布达到验收。

```text
题号、版本、来源页、年龄
数学目标、标准答案、候选解法、需要维护者核对的歧义
最可能的误解
变化题、预期理由、独立成功判据

每幕填写一行
幕 | 想让孩子先想什么 | 此刻出现的对象 | 下一个高亮对象和动作
   | 看到及听到的反馈 | 这幕留下什么给下一幕 | 触发及音频完成条件
   | 误点/越过/停滞后的路径 | 首次提示与替代操作

E1 题意和问题在实际开场讲清楚，手机与桌面都能开始
E2 本题场景、道具和节奏能表现它的数学关系
E3 前后幕因果连续，关键中间关系实际出现
E4 每个要求的下一步有提示，整件对象命中，能按住、放下、取消或替代操作
E5 误操作、反向、拖过、停滞或重听后仍能继续
E6 正常和快速操作录屏均无抢话或字幕错位，试听者确认断句、语速、声线
E7 答案和每个数学符号能从画面解释，没有凑答案或盲猜过关
E8 变化题能观察理由，受提示结果单独记录
E9 开放追问、权限、转写不确定和降级已验证，或如实标记当前未接入
E10 实际浏览器、触屏、键盘、静音和减少动态效果已验证
E11 附自然语速的连续有声录屏和逐段冷启动审查。快慢、误点和卡住已实测，改动有重录证据
每项填写：状态 | 检查输入/设备 | 预期与实测 | 证据 | 修复后复测

评审结论：通过 / 退回
```

## 三种样例的回归入口

- **菜园天平。** 确定第一个等量关系后，保留原秤逐个替换。每次替换要能看到秤仍然平衡。改变每组数量，问什么变了、什么没变。
- **彩铅。** 固定红，只找右侧，再移到橙。用已经保留的红橙卡解释跳过红色。最后各行完整可点，闪动框标出下一排。按任意速度完成，上一段旁白必须播完，重复点同行不会多记一份。
- **数轴追及。** 直接推车，快拖也在关键观察点停下。孩子依次从起点间隔、相对速度、跨过相遇点的方向和题目目标看出式子如何长出来。检查错误地只取正分支时会遗漏哪次。
