## 为什么要改

家长现在一次只能安排一道题：先在下拉框里选孩子，再在列出全部题目的下拉框里选一道，点「加入练习」。安排按「孩子 + 题目 + 固定版本」存，不能取消。题目多起来以后这样既慢又乱，下拉框也和家长空间的其他部件不一样。

之后家长按**书**安排：书架上一本本书，按年级和科目筛选，选一个孩子、点一本书就安排上，再点一下就取消。书里以后加的题直接出现在孩子的练习里；每本书显示这个孩子做到了哪里。

## 书

### 定义

一本书是「年级 + 科目 + 分类」的一个组合，例如「一年级 / 数学 / 学而思」。

- **书名就是分类名**（「学而思」），年级和科目作为标签显示在书名下面。
- **书里的题**：题目清单里属于这本书的全部题，每道题取最新版本，按题目的 `sequence` 排列。
- **稳定 id**：一个可读的短名，例如 `g1-math-xueersi`，写法和题目 id 一样（小写字母、数字和短横线，不超过 100 个字符）。id 在建书时定下，以后书改名、换年级或科目的写法都不变；安排和导出都只记 id。
- **封面**：可选，是封面库里一张图的 id，见[封面库](#封面库)。几本书可以用同一张封面。

### 写在哪里

书写在 `libs/problems/src/books.ts`，和题目清单放在一起，服务器读它：

| 内容       | 写法                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 年级表     | 按顺序列出的年级名称，例如一年级到六年级。筛选和排序都按这张表的顺序，中文排序排不对「一、二、三、六」。                                                     |
| 科目表     | 按顺序列出的科目名称，例如数学、语文、英语。加新科目时往表里加一行，代码里不写死某一科。                                                                     |
| 书单       | 每本书一行：`id`、`grade`、`subject`、`category`（书名）、可选的 `cover`。                                                                                   |
| 题目的归属 | 题目定义写 `book: '<书 id>'`，不再自己写年级、科目和分类；注册表从书上取这三项填进题目摘要，`/api/v1/problems` 的每道题多一个 `book`，题库地址里的三项不变。 |

注册表在加载时检查，不对就启动失败：书的 id 合乎写法且不重复；书的年级和科目在表里；同一组「年级 + 科目 + 分类」只有一本书；每道题引用的书都在书单里。

导入一份题目 PDF 时，`/change` 先问放进哪本书；是新书就在书单里加一行，再按[封面库](#封面库)问封面（见出题手册）。

### 没有题的书

书单里有、但还没有已发布题目的书，家长书架上不显示，也不能安排：安排一本空书，孩子什么也看不到。孩子题库首页怎么显示空书由 #141 按 REQ-001 的空状态决定。

## 封面库

封面只用在书架和孩子题库首页的书卡上，是页面上的一个元素。它和题目页的绘景是两套图、分开存放：题目页的背景仍是每道题从绘景库里选的绘景，封面不在题目里出现，绘景也不拿来当封面。

| 项目       | 规定                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 位置       | `apps/web/src/shared/media/covers/`，图片文件名就是封面 id，例如 `abacus-sprout.webp`；清单 `covers.ts`。放在 `shared/` 是因为家长空间和孩子题库首页两个功能都用它；和 `features/learning/media/backdrops/` 分开。 |
| 清单字段   | `id`、`file`、适合的科目（`subjects`）、适合的年龄段（`ages`，和绘景库一样分低、中、高年级）、画的主体（`motif`）、生成时用的提示词（`prompt`）。                                                                  |
| 比例和尺寸 | 竖版 3:4，交付 768×1024 的 WebP，每张不超过 80 KB。书卡上显示约 160–220px 宽，两倍屏也够清楚。                                                                                                                     |
| 风格       | 和绘景一样的 2.5D 黏土手作质感，中间一个主体，不画字。完整的风格说明、出图和交付步骤、每张图的提示词见 [风格说明](lesson-media.md#书的封面)。                                                                      |
| 由谁出图   | 维护者在 Codex 里用 ImageGen 生成；开发者写提示词、转成 WebP、入库、加 story 和视觉基准。不预先批量生成，新书用到时再出。                                                                                          |
| 加载       | 清单只取图片地址，图片在书卡真正显示时才下载（`loading="lazy"`），几百本书的书架只下载看到的封面。封面是装饰，`alt` 为空，书名就写在旁边。                                                                         |
| 检查       | 测试读题目清单（测试可以读题目插件），检查每本书的封面 id 都在封面库里，封面库的每个文件都在清单里。                                                                                                               |

### 没有封面时

书没有封面，或者封面 id 在库里找不到时，书卡画一张默认封面：科目色的纸纹底，中间是代码画的科目图标，下方一块纸签写年级。

| 科目           | 底色         | 图标                   |
| -------------- | ------------ | ---------------------- |
| 数学           | 嫩绿到苔绿   | 加、乘、减、等号四个号 |
| 语文           | 杏色到陶土橙 | 翻开的书               |
| 英语           | 天青到灰蓝   | 对话气泡里的 Aa        |
| 表里没有的科目 | 米色到麦色   | 一本合上的书           |

科目的颜色和图标在网页里按科目名称查（`shared/ui` 里书卡用的一张表），查不到时用最后一行。默认封面和图片封面一样，不随白天和晚上的主题变化。

## 安排和进度

### 规则

- **安排的单位只有整本书。** 书里暂不分单元；没有单题安排，总览「值得再练」里的题不再有「安排」按钮。
- **安排永久有效**，没有期限，也没有未开始、进行中、已完成这样的状态。一个孩子对一本书只有「安排了」和「没安排」。
- **安排和取消都只要点一下**，不弹确认框，也不需要「撤销」：取消不会丢任何东西，再点一下就重新安排。
- **孩子的练习就是安排给他的书里的全部题**，每道题用最新版本。书里以后加的题直接出现。一道题只属于一本书，所以孩子不会在练习里看到同一道题两次。
- **只有这个孩子看得到**：安排按孩子存，读写都由服务器从家长会话确认孩子属于这个家庭。

### 进度

每个孩子在每本书上有自己的进度，写成「已做 n / m」：

- m 是书里**现在**的题数；
- n 是其中孩子**有过独立完成或提示后完成**的作答的题数。一道题的任何版本做完都算；安排之前在题库里自由复习时做完的也算；
- n = m 且 m > 0 时，书卡上打勾，写「学完」。

进度只从作答记录算，和安排无关：没安排的书也有进度，取消安排不清零，重新安排时接着原来的进度。学习记录里独立完成和提示后完成仍然分开记，进度把两种都算做完，不表示掌握。

| 情况                                     | 显示                   |
| ---------------------------------------- | ---------------------- |
| 书里 12 道题，孩子做完了 5 道            | 已做 5 / 12            |
| 有一道题只答错过、或只看过没作答         | 这道题不算做完         |
| 一道题提示后完成                         | 算做完                 |
| 孩子做完的是这道题的旧版本，现在是新版本 | 算做完                 |
| 12 道都做完                              | 已做 12 / 12，学完的勾 |
| 学完以后书里加了 1 道新题                | 已做 12 / 13，勾去掉   |
| 书里撤下了 1 道题，剩下的都做完了        | 按剩下的题数算，学完   |
| 取消安排后再安排                         | 进度不变               |
| 安排之前就做完了几道                     | 安排的那一刻就算这几道 |
| 书从书单里撤下，安排还在                 | 「这本书暂时不可用」   |

进度每次读取时计算，不另存：一本书的题从题目清单来，做完的题从 `progress` 表来（独立完成或提示后完成的次数大于 0 的题），这两样一变，进度就跟着变。

## 数据

### 新表

```text
book_assignments
  child_id     uuid        不能为空，引用 children(id)，删除孩子时级联删除
  book_id      text        不能为空，书的稳定 id
  assigned_at  timestamptz 不能为空，默认 now()
  主键 (child_id, book_id)
  开启行级安全（RLS），和其他学习表一样
```

- 一个孩子对一本书最多一行；安排是插入（已有就不变），取消是删除。
- 不存进度，不存题目和版本：书里有哪些题、孩子做完了哪些，读取时再算。
- `book_id` 不引用别的表，书单在代码里。书从书单里撤下时行留着，页面显示「这本书暂时不可用」，家长可以取消。
- `assigned_at` 用来排列安排的书（新安排的在前），也写进导出。

### 迁移

按「先扩展后收缩」分两步，让每一步部署后都能回滚到上一个提交：

1. **第一个 PR 的迁移**新建 `book_assignments`。旧表 `assignments` 原样留着：这时网页还是旧的单题安排页面，旧接口照旧读写它。
2. **第二个 PR 的迁移**在新页面上线时删除旧表 `assignments`。迁移文件开头的说明写明：**已有的单题安排全部丢弃，不转成书的安排**（维护者 2026-11-12 批准）。孩子的学习记录、进度和草稿都不在这张表里，不受影响。

第一个 PR 合并到第二个 PR 合并之间新增的单题安排同样会被丢弃。

### 备份、恢复和删除

- 家庭删除：删除家庭时级联删除孩子，`book_assignments` 跟着删除，不用新写删除代码。集成测试补上「删除后这个孩子的安排为 0」。
- 备份和恢复：备份时的逐表行数（`tableCounts`）自动包含新表；恢复后按删除清单重放删除，同样级联。
- 删除清单库不变。

## 接口

都在 `/api/v1` 下。家长的接口由家长会话确认孩子属于这个家庭，别的家庭的孩子一律回答 404，不说明孩子是否存在；写请求校验来源和 CSRF 令牌，和现有的家长写接口一样。响应都带 `Cache-Control: no-store`。

### 家长

**书架的一页** `GET /parents/children/:childId/books?grade=&subject=&offset=`

| 参数      | 说明                                 |
| --------- | ------------------------------------ |
| `grade`   | 可选，年级名称；不写是全部年级       |
| `subject` | 可选，科目名称；不写是全部科目       |
| `offset`  | 可选，从第几本开始，0 起；每页 24 本 |

回答：

```text
{
  total: 46,                      // 这个筛选下一共几本
  assigned: 3,                    // 其中安排给这个孩子的本数
  grades: ['一年级', '二年级'],    // 有书的年级，按年级表顺序
  subjects: ['数学', '语文'],      // 所选年级里有书的科目，按科目表顺序
  books: [{ id, name, grade, subject, cover, total, done, assigned }],
  hasMore: true
}
```

- 书只包括有已发布题目的书，按年级表、科目表的顺序，再按书名排列。
- `cover` 是封面 id，没有时是 `null`；`total`、`done` 就是「已做 n / m」。
- 年级或科目的名称不在表里，或者这个组合下没有书，回答 `total: 0`、空的 `books`，页面显示「这里还没有书」。

**安排的书** `GET /parents/children/:childId/assignments?offset=`

回答 `{ books: [{ id, name, grade, subject, cover, total, done, assignedAt }], hasMore }`，每页 20 本，新安排的在前。书从书单里撤下时 `name`、`grade`、`subject`、`cover` 为 `null`，`total`、`done` 为 0。总览「已安排」读每个孩子的第一页，#164 的总览汇总也用它。

**安排** `PUT /parents/children/:childId/assignments/:bookId`，没有请求体，回答 204。

- 已经安排过的再安排一次什么也不变，`assigned_at` 保持原来的，所以连点、重试都安全。
- 书不在书单里，或者书里没有已发布的题：409，「这本书暂时不能安排，请刷新书架」。
- `bookId` 不合乎写法：400。

**取消** `DELETE /parents/children/:childId/assignments/:bookId`，回答 204。没安排过、已经取消过，或者书已经撤下，都回答 204。

### 孩子

**我的练习** `GET /children/assignments?offset=`

回答 `{ books: [{ id, name, grade, subject, cover, total, done, problems: [{ id, version, title, done }] }], hasMore }`，每页 10 本。

- 只列书单里还有的书；撤下的书孩子看不到。
- 没学完的书在前，学完的在后；同一组里新安排的在前。
- 每本书列出它现在的全部题，按书里的顺序，每道题是最新版本，`done` 表示这道题做完了。

### 题库

`GET /problems` 的每道题多一个 `book`（书的 id），其余不变。#141 的孩子题库首页需要的书单接口由 #141 加，复用这里按筛选分页的服务。

### 旧接口

`GET/POST /parents/children/:childId/practice` 和 `GET /children/practice` 在第一个 PR 里原样保留，给还没换掉的旧页面用；第二个 PR 换上新页面时删除。

## 家庭导出

导出格式升到 `version: 2`。每个孩子的 `practice` 换成 `books`，列出安排给他的书和导出时的进度：

```text
books: [{ id, grade, subject, name, assignedAt, done, total, finished }]
```

- `finished` 是导出时是否学完（`total > 0` 且 `done = total`）。
- 书从书单里撤下时 `grade`、`subject`、`name` 为 `null`，`done`、`total` 为 0，`finished` 为 `false`。
- 没安排的书不列；每道题的学习摘要本来就在 `learning` 里。
- `familyExportScope` 的「包括」把「家长安排的练习」改成「家长安排的书，以及导出时每本书已做的题数、题数和是否学完」，文件里的说明随之改变。

### 练习安排（`/family/practice`）

从上到下：

1. **给谁**：孩子头像排成一组单选（`radiogroup`），选中的描主色边。只有一个孩子时直接选中，写「为小米安排」，不能点。还没有孩子时整页是空状态和「邀请孩子」按钮（去孩子页的 KEY 卡片）。
2. **年级**：分段，第一项是「全部」，后面是有书的年级。
3. **科目**：带图标的筹码，第一项是「全部」，后面是所选年级里有书的科目。
4. 一行计数：左边「共 46 本」，右边「其中给小米安排了 3 本」。
5. **书架**：书卡网格，桌面一排 4–5 本（每本至少 11.5rem 宽），手机一排 2 本。
6. **翻到底**：上滑到离底部还有约一屏时自动加载下一批 24 本，加载时出现三颗跳动的圆点和两张骨架书卡；底部一直留一个「再看 24 本」按钮作后备，给键盘、读屏和自动加载失败时用。加载失败时一行「这一批没加载出来」，按钮变成主按钮。都加载完时写「一共 46 本，都在这里了」。

选中的孩子、年级和科目都写进地址（`?child=&grade=&subject=`），刷新和返回后还在原处；默认是第一个孩子、全部年级、全部科目。换孩子或筛选时从第一批重新加载。

**书卡**：封面（左边一道书脊的明暗），学完时左上角一枚绿色的「学完」勾；书名（最多两行）；「一年级 · 数学 · 12 题」；进度条和「已做 n / m」；最下面的按钮：

| 状态                   | 按钮                                         | 读屏                             |
| ---------------------- | -------------------------------------------- | -------------------------------- |
| 没安排                 | 次按钮，加号图标和「安排」                   | 「为小米安排《学而思》」，未按下 |
| 已安排                 | 主按钮，勾的图标和「已安排」                 | 「为小米安排《学而思》」，已按下 |
| 已安排，指针悬停或聚焦 | 描危险色边，叉的图标和「取消安排」           | 同上                             |
| 正在安排或取消         | 按钮保持原样、不能点，圆点代替图标           | 「正在安排」                     |
| 安排或取消没成功       | 按钮恢复，书卡下方一行「没安排上，再点一次」 | 提示条朗读                       |

按钮是一个切换按钮（`aria-pressed`），点了先等服务器回答再变，不先假装成功。

加载中是十张骨架书卡；书架打不开是空状态「书架没打开」和「再试一次」；筛选后没有书是「这里还没有书」、当前的筛选和「看全部的书」；题目清单里一本书也没有是「书在路上」。

### 总览

- 「值得再练」：和现在一样列出答错过、还没有独立完成的题，去掉每行的「安排」按钮。
- 「已安排」：每行是封面缩略图、书名、「孩子 · 年级科目」，右边是「n / m」胶囊，学完时是带勾的绿色「学完」。几个孩子轮流取，最多 5 行；右上角的加号图标按钮去练习安排页。没有安排时是空状态「还没有安排书」和「去书架安排」。书撤下时这一行写「这本书暂时不可用」，带「取消」按钮。

### 孩子「我的练习」

这一版只做最小改动，正式改版由 #141 做：「我的练习」卡片里按书分组，每组是封面缩略图、书名、年级和科目、「n / m」或「学完」，下面按顺序列出书里的全部题，做完的题后面一个勾，题名链接到题目页。没有安排时写「家长还没有给你安排练习」。

## 实现要点

- `libs/problems`：书单和两张表、注册表的检查、按书取题（`problemsOf(bookId)`）。题目定义从写年级、科目、分类改成写 `book`，先做一个不改行为的重构提交，题库接口的输出前后一样。
- `apps/api`：新功能目录里分层写，进度的计算是不依赖数据库的纯函数（书里的题加上做完的题号，得出 n、m 和学完）；仓储一次查出一批书的做完的题号，不按书逐本查。书架的筛选和分页在服务器内存里的书单上做，几百本书也只是遍历一次。
- `apps/web`：封面库和书卡放在 `shared/`（书卡是展示组件，只收数据和回调）；把绘景库的 `catalog()` 和年龄段搬到 `shared/lib`，绘景、角色和封面三个库共用，这是一个不改行为的重构提交。自动加载用 `IntersectionObserver` 看底部的按钮，TanStack Query 的 `useInfiniteQuery` 管分页。

## 测试

- 题目清单：书的 id、年级、科目、重复组合、题目引用不存在的书时注册表报错；按书取题的顺序和最新版本；每本书的封面都在封面库里。
- 进度：上面表里的每一行一条单元测试。
- 接口（真实数据库）：安排两次只有一行；并发安排；取消两次都是 204；撤下的书能取消；409、400；别的家庭的孩子 404；孩子的会话、没验证邮箱的家长 401；来源和 CSRF 不对时拒绝；筛选、计数、分页的边界（第一批、最后一批、超出范围）；安排之前做完的题算进进度；取消再安排进度不变；书里加题后学完变成没学完（测试注册表）。
- 迁移：从上一个迁移带数据升级后旧数据不受影响；删除旧表的迁移只删除 `assignments`。
- 导出和删除：导出 v2 的书和进度；删除家庭后安排为 0；恢复演练的行数包含新表。
- 网页：书卡每种状态的 story 和测试；书架页和数据访问配合的测试（换孩子、筛选、自动加载、加载失败后按钮重试、安排失败的提示）；总览和孩子的练习。
- 几百本书：e2e 和视觉基准用生成的 400 本书的测试注册表（只在测试里，不进入题目清单），检查上滑一直加载到底、计数正确、按钮还能用；书架截图基准包括白天和晚上。
- 可访问性：单选组、切换按钮的读屏标签，键盘能用「再看 24 本」一直翻到底。

## 考虑过但没采用

- **单题安排、期限和状态**（#179 的原稿）：维护者 2026-11-12 去掉。按书安排已经够用；期限和状态让家长和孩子多一层要管的事，进度「已做 n / m」已经说明做到了哪里。
- **只算安排之后的作答**：重新安排时进度从零开始，看起来像没做过；进度和安排无关更好懂。
- **把进度存进表**：每次加题、撤题都要改表，容易和真实记录对不上；读取时算更简单，量也不大。
- **在浏览器里筛选全部书**：几百本书要一次下载；服务器分页每次只给 24 本。
- **只用自动加载或只用页码**：只靠自动加载时键盘和读屏翻不到底，加载失败也没有入口；页码在手机上难点。两者结合。
- **封面放在 `libs/problems`**：图片是网页的资源，题目插件只在服务器上运行；书只记封面 id。
- **拿绘景当封面**：绘景是 16:9、中间留空地的整屏背景，缩成竖版书卡后主体不清楚，还会让孩子以为点进去就是这一幕。

## 待确认

本文里由开发者定下、需要维护者看一眼的取舍：

1. 总览「已安排」超过 5 本时，没有地方看全部安排的书。建议在练习安排页的科目筹码后面加一个「只看已安排」筹码；也可以让总览列出全部。
2. 孩子「我的练习」的排列：没学完的在前，同一组里新安排的在前。
3. 书架默认「全部年级、全部科目」。#164 给孩子加上年级以后，可以改成默认选这个孩子的年级。
4. 书架上学完的书不挪到后面，仍按年级、科目、书名排列。
5. 安排的按钮在安排后变成主按钮「已安排」，悬停或聚焦时显示「取消安排」；手机上没有悬停，点「已安排」就是取消。
6. 第一个 PR 合并到第二个 PR 合并之间，旧页面仍能做单题安排，这些安排在第二步也会被丢弃。
