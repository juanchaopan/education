# 家长总览：最近 7 天、学习时长和家庭时区

- 状态：AI 草稿，等维护者确认样稿。规则是维护者 2026-11-12 在 [#164](https://github.com/juanchaopan/education/issues/164) 定下的，调整后的验收标准记在 [#164 的评论](https://github.com/juanchaopan/education/issues/164#issuecomment-6836609940)。
- 需求：REQ-005、REQ-009、REQ-002、REQ-011（都有 2026-11-12 的澄清）。样稿见 [#164 记录](../evidence/164/README.md)，变更原因见 [变更记录](../changes/2026-11-12-family-overview.md)。
- 涉及：`libs/contracts`；`apps/api` 的 `learning`（总览汇总、每天的学习、学习计时）和 `identity`（家庭时区、注册、导出、删除）；`apps/web` 的家长空间（总览的孩子卡片、学习记录、孩子页的家庭时区）、题目页的计时和网站的白天晚上主题。「已安排」的书和进度照 [家长书架](bookshelf.md) 不变。

## 为什么要改

总览的孩子卡片现在只有按全部记录累计的题数、独立完成和提示后完成，网页要逐页读完每个孩子的整份学习记录再自己加，记录多了数字后面带「+」。#138 的样稿里还画了年级、本周数字、分钟数和七天柱状图，但这些都没有数据来源。

之后：

- 服务器一次给出总览要的汇总，网页不再逐页读学习记录。
- 卡片上是**最近 7 天**的题数、独立完成、提示后完成和学习分钟，加上 7 根柱子，柱高是每天的学习分钟。
- 学习时长有真实的来源：孩子在题目页上动手学的时间。
- 每个家庭有自己的时区，一天从这个时区的 0 点算起；家里的页面也按它换白天和晚上的样子。
- 家长在学习记录里可以一段一段往前翻，看更早的每个 7 天，以及全部记录的累计。

## 统计的规则

### 一天和最近 7 天

- **一天**从家庭时区的 0 点开始，到下一个 0 点结束。
- **最近 7 天**是到昨天为止的 7 个完整日。今天还没过完，不算在内：11 月 12 日看到的是 11 月 5 日到 11 月 11 日。维护者选了这个，没有选「今天加前 6 天」，因为一天没过完，数字和柱子会比别的天矮，看起来像学得少。
- 今天已经学了的分钟数单独写在卡片底部（「今天已学 12 分钟」），不进 7 天的数字和柱子；今天不到 1 分钟时不写。
- **往前翻**：学习记录里一次看一段 7 天。最新的一段是最近 7 天，再往前依次是它前面的 7 天，各段首尾相接、不重叠。翻到孩子最早有记录的那一段为止。

### 每个数怎么算

| 数             | 一段时间里的算法                                                                         | 累计的算法                        |
| -------------- | ---------------------------------------------------------------------------------------- | --------------------------------- |
| 道题           | 这段时间里提交过作答或要过提示的题，按题目 id 数，同一道题做几次、换了几个版本都只算一道 | 有过作答或提示的题，同样按题目 id |
| 次独立完成     | 这段时间里结果是独立完成的作答次数                                                       | 全部独立完成的次数                |
| 次提示后完成   | 这段时间里结果是提示后完成的作答次数；提示后完成不算独立完成                             | 全部提示后完成的次数              |
| 分钟、学习时长 | 这段时间里每天学习秒数的和，除以 60 向下取整                                             | 全部学习秒数的和                  |
| 每天的柱子     | 这一天的学习秒数；柱高按这 7 天里最多的一天定比例，没学的一天画一道细线                  | —                                 |

- 一次作答算在它提交的那一天，一次提示算在要提示的那一天，都按家庭时区。
- 变化题（#217）的结果不进这些数；家长怎样看变化题由 #219 决定。
- 数字只说做了多少，不说掌握了没有。学习记录里的「?」写明这些算法。

### 学习时长怎么计

- 只在**题目页**上计时：页面在前台可见，而且孩子在最近 2 分钟里动过手（点、按、拖、画、说话或打字）。别的页面、切到后台、锁屏、2 分钟没动手都不算。
- 计时由服务器根据心跳算：满足上面两个条件时，题目页每 30 秒发一次心跳，孩子从不动手到重新动手时马上发一次。服务器把这次心跳和这个孩子上一次心跳之间的时间加到今天（按家庭时区）的总数里；两次心跳隔了 90 秒以上，说明中间停过，这一段不算。
- 这样，重发的心跳和同时开着的两个标签页都不会多算，一天记下的时间不会超过墙上的钟走过的时间。断网时心跳发不出去，这段时间不算。
- 每个孩子每天存一个秒数，不存每次心跳。这项功能上线以前的学习没有时长；学习记录的说明里写「从 2026 年 11 月开始记」。

## 不加年级

#138 的样稿在孩子名字下面画了「一年级」，这是选风格时画的样子，没有哪项功能要用它。家长按书安排练习，书自己带着年级；孩子升了年级，去年的书照样留着，不需要孩子账号上再记一个年级。所以孩子账号不加年级，注册和总览都不问、不显示。

## 家庭时区

- 每个家庭存一个 IANA 时区名，例如 `Asia/Shanghai`。服务器只接受它认得的名字（`Intl` 能用来格式化时间的），长度不超过 64。
- **新家庭**：家长注册时网页带上浏览器的时区（`Intl.DateTimeFormat().resolvedOptions().timeZone`）。注册请求里这一项可以没有，例如更新前打开的旧页面；没有时和已有家庭一样处理。
- **已有家庭**：迁移后时区是空的。空着的时候，服务器用配置里的默认时区 `DEFAULT_TIME_ZONE`（默认 `Asia/Shanghai`）。家长下一次打开家长空间时，网页发现家庭时区还空着，就把这台设备的时区填进去，不打扰家长。家长登录会长期保持，等「下次登录」可能要等几个月，所以不放在登录时做。
- **修改**：家长在「孩子」页的「家庭时区」卡片里修改。总览底部的设置列表多一行「家庭时区」，右边写现在的时区名，点了去这张卡片。
- **用途**：统计按它分天；家里的页面按它换白天和晚上的样子（见下面「主题」）。

## 接口

### 家长：总览汇总

`GET /api/v1/parents/overview`，家长会话。回答：

```text
{
  timeZone, today,                          // 家庭时区和它的今天，例如 '2026-11-12'
  children: [{
    id,
    total:  { problems, independent, assisted, seconds },
    recent: { from, to, problems, independent, assisted, seconds,
              days: [{ date, seconds }] },  // 7 项，从早到晚
    todaySeconds,
    review: [{ id, version, title, incorrect }]
  }]
}
```

- `children` 是家里的每个孩子，顺序和孩子列表一样；一个孩子还没有任何记录时数字都是 0。
- `review` 是学习摘要标为建议复习的题（答错过、还没有独立完成），和现在「值得再练」的规则一样；题目清单里找不到的版本不列。
- 第一个 PR 只有 `id`、`total`（不含 `seconds`）和 `review`，页面不变；后两个 PR 再加时区、最近 7 天和时长。

### 家长：每天的学习

`GET /api/v1/parents/children/:childId/days?to=`，家长会话。`to` 是一段的最后一天（`YYYY-MM-DD`），不写就是昨天。回答：

```text
{ from, to, problems, independent, assisted, seconds,
  days: [{ date, seconds }],                // 7 项
  hasEarlier, hasLater,
  total: { problems, independent, assisted, seconds } }
```

- `from` 是 `to` 往前 6 天；`hasEarlier` 是 `from` 之前还有没有作答、提示或学习时长；`hasLater` 是 `to` 是否早于昨天。
- `to` 不是合法日子、晚于昨天：400。孩子不在这个家庭：404。

### 孩子：学习计时

`POST /api/v1/children/study-time`，孩子会话，请求体 `{}`，回答 204。按上面「学习时长怎么计」处理。没有孩子会话：401，页面停止发心跳。

### 家庭时区

- `GET /api/v1/parents/family/time-zone`：`{ timeZone, set }`，`set` 为 `false` 时 `timeZone` 是默认时区。
- `PUT /api/v1/parents/family/time-zone`：`{ timeZone }`，回答 204；名字不认得或有多余字段：400。
- `GET /api/v1/family/time-zone`：家长或孩子会话都能读，`{ timeZone }`，给网页决定主题用。孩子的登录和会话接口不变。
- 家长注册请求多一个可选的 `timeZone`，规则同上；名字不认得时当作没有。

## 家庭导出和删除

- 导出格式升一版（和 #217 同时合并时只升一次）。最外层加 `timeZone`（家庭时区，空着时写默认时区并注明）；每个孩子加 `studyTime: [{ date, seconds }]`，列出有学习时长的每一天，从早到晚。
- `familyExportScope` 的「包括」加上「家庭时区」和「每天的学习时长」；「不包括」加上「学习计时的心跳时刻」。
- 删除家庭时，`study_days` 和 `study_beats` 随孩子一起删除，家庭时区随家庭删除。删除卡片上的删除范围加上「每天的学习时长」。

## 页面

样稿和每张图对应的状态见 [#164 记录](../evidence/164/README.md)。

### 总览的孩子卡片

从上到下：

1. 头像和昵称，右边一行小字「最近 7 天」。
2. 四块数字：道题、次独立完成、次提示后完成、分钟。桌面一排四块，手机两排两块，数字在前、名称在后。
3. 7 根柱子，下面写星期，最后一根写「昨天」，用强调色；没学的一天是一道细线。柱子没有数字，读屏读一句「11 月 5 日周四 12 分钟，……」。
4. 底部一行：左边「今天已学 12 分钟」的胶囊（今天不到 1 分钟时不出现），右边「看学习记录」，去这个孩子的学习记录。

其他状态：

| 状态                    | 显示                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 还没有任何记录          | 一块浅底：「还没有学习记录」「孩子做完第一道题以后，这里会出现每天的学习。」和「给小米安排书」的链接（去这个孩子的书架） |
| 最近 7 天没学、以前学过 | 数字换成一块浅底「最近 7 天没有学习」「以前的记录都在学习记录里。」，柱子都是细线；底部照常                              |
| 正在读取                | 四块数字和柱子的骨架，读屏「正在读取小米的学习记录…」                                                                    |
| 没读出来                | 「学习记录没有读出来。」和「重试」；「看学习记录」照常                                                                   |

「值得再练」「已安排」和设置列表不变，设置列表在 AI 老师下面多一行「家庭时区」。

### 学习记录（`/family/learning`）

1. 最上面一行选孩子，和书架上选孩子的一行同样的胶囊（头像加昵称），换掉现在的下拉框。地址里 `?child=<id>`，往前翻时加 `&to=<日子>`，刷新和返回后还在原处。
2. **每天的学习**卡片：
   - 一行翻页：左边「前 7 天」、右边「后 7 天」两个圆按钮，中间是这一段的名字。最新一段写「最近 7 天」，下面一行小字是日子「11月5日 – 11月11日」；更早的段直接写日子。最早一段左边的按钮不能点，柱子下面一行「更早没有记录了」；最新一段右边的按钮不能点。
   - 这一段的四块数字，和总览卡片的算法一样；这一段没学时数字是灰色的 0。
   - 7 根大柱子，每根上面写分钟（「12分」，没学不写），下面写星期和几日，最新一段的最后一根写「昨天」。
   - 一道分隔线下面是「一共」：全部记录的道题、次独立完成、次提示后完成和学习时长（不到 1 小时写「45 分钟」，否则「6 小时 20 分」），右边小字「从加入家庭起的全部记录」。
   - 标题右边的「?」展开算法说明：一天从家庭时区的 0 点算起，最近 7 天到昨天为止；道题怎么数；提示后完成不算独立完成；学习时长怎么计、从 2026 年 11 月开始记。
3. 原来的**学习摘要**卡片放在下面，内容不变。

### 孩子页的家庭时区

「孩子」页现在有注册 KEY 和孩子两张卡片，家长空间没有单独的家庭设置页；家庭时区和家庭成员放在一起，在这两张卡片后面加一张「家庭时区」卡片（地址 `/family/children#family-time-zone`）：

- 标题右边保存成功后出现「已保存」徽章。
- 大字写时区的中文名（`Intl` 的 `longGeneric` 名称，例如「中国时间」），旁边小字「现在 20:15 · 晚上」。
- 一句说明：「每天的学习从这个时区的 0 点算起，家里每个人的页面也按它的时间换白天和晚上的样子。」这是做决定要看的，保留。
- 「时区」下拉框列出浏览器认得的全部时区，按 UTC 偏移再按名字排，每项写「UTC+08:00 中国时间 · Asia/Shanghai」。下面是「保存」，选的和现在一样时不能点。
- 这台设备的时区和家庭不同时，多一块提示「这台设备在北美东部时间，现在 7:15。」和次按钮「改成北美东部时间」，点了把下拉框换成它，再点保存。
- 保存时按钮不能点、圆点代替文字「正在保存」；没保存上时按钮右边一行「没保存上，再点一次。」。

### 主题

[视觉语言](visual-language.md) 的白天、晚上主题按**家庭时区**的钟点切换（6:00–18:00 白天），不再看设备的钟：

- 网页读到家庭时区（家长空间读家长的、孩子登录后读孩子所在家庭的）后，记在这台设备上；页面头部的首屏脚本用它决定第一屏的主题。
- 这台设备还没有登录过家长或孩子时（例如第一次打开孩子登录页），照旧看设备的钟。
- 题目页的画面本来就不跟着主题变，不受影响。

视觉语言和 REQ-011 里「按设备本地时间切换」的说法随家庭时区的 PR 一起改。

## 实现要点

- `learning/domain`：日子的计算（家庭时区的今天、一段的起止、按时区把时刻归到日子）、一段的汇总和柱子的数据都是不依赖数据库的纯函数。日子用 `Intl` 换算，不手写偏移，夏令时由它处理。
- 仓储一次查一个家庭全部孩子的汇总，不按孩子逐个查；按时区分天在 SQL 里用 `AT TIME ZONE` 做。
- 学习计时的事务锁住这个孩子的 `study_beats` 一行，再加到 `study_days`，并发的心跳排队，不多算。
- 网页的计时放在题目页的公共外壳里，所有题目共用，题目自己不写。
- 主题的计算 `themeAt` 接一个时区参数；页面开着时每分钟检查一次，跨过切换时刻就换。

## 测试

- 单元：日子的计算（时区边界、夏令时那天、今天不算、往前翻的首尾相接）；每个数的算法，各一条例子；心跳间隔（30 秒、正好 90 秒、91 秒、重复心跳、跨午夜）。
- 接口：总览和每天的学习的每个错误；家庭隔离；时区的读写和校验；注册带和不带时区。
- 数据库：两次并发心跳只加一次间隔；删除家庭后没有学习时长留下；导出包括时区和每一天。
- 页面：卡片和学习记录的每个状态（Storybook、视觉基准，白天和晚上，桌面和手机）；e2e 走一遍孩子学一会儿、家长看到分钟。
