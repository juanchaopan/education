# #47 空题库家庭框架验收

[#47](https://github.com/juanchaopan/education/issues/47) 验证空框架交付点：账号、儿童关联、恢复登录、家庭隔离、家长空面板和数据控制，以及没有 AI 密钥时页面的说明。对应 REQ-001、REQ-002、REQ-005、REQ-008、REQ-009；分期见 [产品需求的验收分期](../../product/requirements.md#验收分期)。

## 两个家庭的浏览器验收

`e2e/empty-framework.spec.ts` 在生产入口（构建好的页面和 API，正式题库为空，没有 `OPENAI_API_KEY`）上，用两个家庭在各自的浏览器里依次完成：

| 步骤           | 做法                                                                                                      | 检查                                                                                                                                             |
| -------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 家长登录       | 两个已验证家长用真实密码在登录页登录                                                                      | 显示家长账号；还没有关联的孩子                                                                                                                   |
| 孩子加入       | 家长生成注册 KEY，孩子在另一个浏览器用它注册，再用页面显示的家庭码、昵称和 PIN 登录。两个孩子用同一个昵称 | 两个孩子各自进入自己的空间，只靠家庭码区分                                                                                                       |
| 空题库和空进度 | 打开题库、家长的学习摘要和安排练习、孩子的练习                                                            | 题库显示“好问题，正在准备中”，接口返回空题目列表；学习摘要“还没有这位孩子的学习记录”，练习“题库还没有已发布的题目”，孩子没有练习                 |
| 无 AI 密钥     | 打开家长页的“外部 AI 授权”                                                                                | “AI 解题提示”和“语音转写”都显示“暂未启用：现在不会发送任何内容，孩子用题目提示继续。”                                                            |
| 跨家庭请求     | 第一个家长用自己的会话请求第二个家庭孩子的学习摘要、练习、安排练习和重置 PIN；除孩子编号外每个请求都有效  | 孩子列表只有自己的孩子；四个请求都返回 404，状态和内容与请求一个不存在的孩子完全相同，所以拒绝来自归属检查，不是请求本身无效；第二个孩子仍在登录 |
| 重置 PIN       | 第一个家长重置孩子的 PIN                                                                                  | 孩子的旧登录退出，旧 PIN 提示不正确，新 PIN 能登录；第二个孩子不受影响                                                                           |
| 重新登录       | 第二个家长退出后再登录；第二个孩子的浏览器清除 cookie 后用原来的家庭码、昵称和 PIN 登录                   | 账号和孩子都还在，不需要重新注册或新的 KEY                                                                                                       |
| 导出           | 第一个家长确认密码后下载家庭数据                                                                          | 文件里是自己的邮箱和一个孩子，不含第二个家庭的邮箱或孩子编号                                                                                     |
| 删除           | 第一个家长确认密码并输入“删除家庭”                                                                        | 页面显示家庭已删除；应用库没有这个家庭，删除清单记为完成；孩子的登录失效、原 PIN 不正确，家长原密码登录失败                                      |
| 另一家庭不变   | 回到第二个家庭                                                                                            | 家长仍在登录、孩子仍可管理且没有伪造记录；孩子仍在自己的空间                                                                                     |

桌面（Desktop Chrome）和手机（iPhone 13 视口）各跑一遍。测试只使用合成邮箱和随机家庭，结束时删除两个家庭和删除清单条目。建立有真实密码的已验证家长、在登录页登录的步骤放在共享的 `e2e/password-parent.ts`。

生产构建不含测试夹具：`e2e/catalog.spec.ts` 检查构建出的浏览器脚本里没有夹具题目和服务端判题规则；本验收确认生产入口的题目接口返回空列表。

## 没有 AI 密钥时

付费 AI 开关 `PAID_AI_ENABLED` 默认开启。一个服务只有同时满足开关开启、后端有 `OPENAI_API_KEY`、这个服务的资格开关（`OPENAI_TUTORING_ELIGIBLE` 或 `OPENAI_TRANSCRIPTION_ELIGIBLE`）为 `true` 时才算启用。这些配置在启动时读一次并检查，开关只接受 `true` 或 `false`，其他值让启动失败并写明是哪个变量；是否启用由 `apps/api/src/ai-provider-settings.ts` 按同一份配置判断，网关调用前和家长页用的是同一个判断。

| 情况                     | 网关                                                 | 家长页（授权接口的 `availability`）                                    |
| ------------------------ | ---------------------------------------------------- | ---------------------------------------------------------------------- |
| 开关开启、没有密钥       | 不发请求，回退原因 `missing-key`，孩子看到用提示继续 | 两项都是“暂未启用”，无论家长是否授权                                   |
| 开关关闭                 | 不发请求，回退原因 `disabled`                        | “暂未启用”                                                             |
| 有密钥、某项服务没有资格 | 这一项不发请求，回退原因 `ineligible`                | 这一项“暂未启用”，另一项按自己的资格                                   |
| 开关、密钥、资格都满足   | 还要家长授权和剩余预算，才会发请求                   | “已启用：只在已授权、额度够用时发送孩子提交的内容。”，预算另行显示状态 |

页面不区分不可用的原因：那是部署配置，家长只需要知道现在会不会发送。授权状态（未授权、已授权、已撤回）照常显示，授权本身不会让不可用的服务发出请求。正式题库为空，孩子还没有可以发起 AI 请求的题目；真实教学能力随题目验收。
