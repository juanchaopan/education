# #118 新版本发布后先保存草稿再刷新

状态：已实现，本机检查通过。需要隔离数据库的浏览器检查由 CI 运行。在真实 staging 上跨两次发布的验收，要等合并后的两次发布完成才能做，列在文末。做法依据 [ADR-0009 发布更新与草稿保护](../../adr/0009-account-security-spike.md#发布更新与草稿保护) 和 [ADR-0006](../../adr/0006-delivery-environments.md)。

## 做法

- **页面的版本**：`npm run build:staging` 带着 `RELEASE_SHA` 构建，Vite 插件把这个 SHA 写进页面的 `<meta name="education-release">`；`/version.json` 报的是同一个 SHA。版本名的格式（40 位十六进制）只在 `@education/contracts` 的 `releaseRevision` 里定义一次，服务端、构建和页面共用。staging 冒烟检查要求两者都等于这次的 SHA，并要求页面响应头是 `no-cache`。本地构建没有这个 meta，页面也就不检查版本。
- **什么时候检查**：页面可见时每 60 秒检查一次，在后台不检查；恢复可见、获得焦点、恢复网络时立刻检查。请求带 `cache: 'no-store'`。请求失败，或者回复里不是合法的版本名，都不刷新，按 1、2、4、8 分钟退避重试，最长间隔 15 分钟。版本相同时继续每 60 秒检查。
- **页面上哪些东西会被刷新影响**：
  - 课程短片：老师在讲话时（句与句之间的停顿也算）算“播放中”。孩子暂停了，或者某句话没放出来、在等孩子重听，不算播放中。
  - 草稿：未同步，或者冲突中保留着的编辑，算“未保存”；正在保存，算“保存中”。删除草稿失败时，页面再发一次删除，不会把孩子丢掉的草稿存回去。
  - 语音：正在录音、录音正在转文字，算“保存中”；转出来的文字孩子还没确认，算“未保存”。
  - 老师的回复还在路上，算“保存中”。
  - 页面发往服务器、还没回来的写请求，算“保存中”。
  - 家长新生成的注册 KEY 只显示一次，刷新会让它消失。KEY 在页面上时，以及重新读取 KEY 状态期间（读完后 KEY 还有效就会重新显示），算“只显示一次的内容”。家长点“刷新 KEY 状态”关掉它、离开这个页面，或者状态里已经没有这个有效的 KEY（被撤销、过期，或者状态读取失败、KEY 没有显示出来）时，就不再算。
- **发现新版本以后**：
  - 课程页上的短片正在播放时先不动，因为刷新会打断旁白，孩子还得重新点“开始”才有声音（维护者的要求）。孩子离开课程页，或者短片安静下来以后，才继续往下走。课程以外的页面不用等短片。
  - 有未保存的草稿就先保存。保存失败、离线或冲突时保留原输入，显示“更新已准备好，保存后将自动更新。”。之后每次检查都会再试一次保存；孩子自己点保存成功、或者到下一幕自动保存成功，也算数。正在保存的东西先等它完成。
  - 只显示一次的内容还在页面上时，再等它消失。这段时间不显示提示，也不需要保存什么。
  - 都处理完以后完整刷新。刷新不碰 cookie，所以登录还在。
- **每个版本只自动刷新一次**：
  - 刷新前把目标版本记进这个标签页的 sessionStorage，页面加载时读出来。如果服务端报的版本正是上次刷新时的目标，而页面还不是它，说明缓存没同步，或者回滚后拿到的还是旧页面。这时不再自动刷新，只显示“新版本还没准备好，过一会儿可以再试一次。”和“再试一次”按钮。
  - 如果页面加载时这个标签页的 sessionStorage 写不进去，页面从不自动刷新，只显示这个提示。孩子点“再试一次”后，等页面上没有挡住刷新的东西了，照样刷新。
  - 如果页面加载以后存储才写不进去，页面仍然刷新一次。刷新后的页面会发现存储写不进去，不再自动刷新，所以不会循环。
- **回滚**：服务端报的版本只要和页面不同，就按同样的流程处理。
- **旧资源不可用**：课程没法继续时（最常见的原因是课程文件随新版本没了），页面不再整页空白，而是显示“这道题暂时打不开”和“重新打开”。只有孩子点了才刷新；同时页面立刻检查一次版本。
- **界面**：更新提示用共享的 `Notice`、`Actions` 和 `Button` 组成，固定在页面底部，课程页也一样；课程打不开时用共享的 `EmptyState`。

## 未完成和范围外

- 普通表单（家长和孩子的登录、注册，家长空间里的各个表单）的输入不算未保存。填到一半时遇到更新，刷新后内容会丢。维护者决定作为后续事项处理。
- 草稿冲突时，更新会一直等孩子选择保留哪一份，期间显示“更新已准备好，保存后将自动更新。”。家长一直不关掉新 KEY 时，更新也一直等。
- KEY 状态重新读取失败时，页面上不显示 KEY，这时不再挡住刷新；如果正好发生更新，这个 KEY 原文就丢了，家长需要撤销后重新生成。
- 检查失败进入退避以后，退避期间获得焦点不会立刻检查，要等这一轮退避结束。
- 真实 staging 上的验收：合并后再等一次发布，在已打开的 staging 页面上确认会自动更新、登录还在、不会循环刷新；并核对 Vercel 删除旧资源后，课程文件加载失败时显示的重试。这两次发布由手动流程触发，本记录不声称已经完成。
