# 开放文字与绘图的结构化教学反馈

[#40](https://github.com/juanchaopan/education/issues/40) 让儿童主动提交一段文字或当前的绘图，得到结合当前步骤的中文反馈和可选的区域标记，对应 REQ-003、REQ-004、REQ-006、REQ-008。

## 流程

`POST /api/v1/problems/:id/:version/feedback`，请求体为 `stepId` 加 `text`、`image`（PNG 的 base64）中的至少一项，要求儿童会话、CSRF 和同源请求头。

1. 校验儿童会话；题目版本或步骤不存在时返回 404，不触达模型。
2. 先运行题目作者写的 `checkStep` 规则。结论为 `correct` 或 `needs-work` 且通过校验时直接返回，来源为 `rules`，不检查家长授权，不产生用量记录。
3. 规则不能判断时才调用模型：沿用 #38/#39 的网关，需要当前家长授权、预留额度、10 秒内开始有效响应，取消和超时会传到供应商请求。
4. 模型只收到题目作者为该步骤写的 `feedback.prompt`、儿童文字和一张 `detail: low` 的 PNG，不含历史作答、标准答案、昵称或家庭信息；不传工具；`store: false`。
5. 返回 `ready`（带来源和反馈）或 `fallback`（带原因）。反馈不记录作答、不改变进度或权限；作答与草稿的写入独立于 AI 成败。

## 限制

- 文字至多 500 字；步骤说明至多 1,200 字；请求体上限约 700 KB。
- 图像须为 PNG，不超过 512 KB，宽高在 64–1024 与 64–768 之间，只读文件头，不解码。浏览器端导出沿用 `exportInk`：先导出整张画板，过大时缩小一半。
- 模型输出上限 256 token。每次预留 US$0.002176，文字提示仍为 US$0.002112；每儿童每分钟 6 次、每家庭每分钟 18 次的限流为两类请求共用。

## 不可信输出的处理

模型被要求按严格 JSON schema 输出 `status`、`instruction`、`confidence`、`injection`、`highlight`。服务端再按下表处理：

| 情况                                                                              | 结果                                             |
| --------------------------------------------------------------------------------- | ------------------------------------------------ |
| 不是 JSON、字段多或少、状态未知、`instruction` 为空、过长或含标记、链接、控制字符 | 丢弃，返回 `fallback: unavailable`，仍按用量结算 |
| 置信度低于 0.6，或模型报告孩子的内容在试图改变规则                                | 返回「请确认」类的 `uncertain`，不扣记错误       |
| `highlight` 超出画板，或不在步骤声明的可标记区域内                                | 返回 `uncertain`，不带标记                       |
| `highlight` 但状态不是 `needs-work`                                               | 忽略标记                                         |
| 规则返回的步骤不一致、结论不明、含标记或区域越界                                  | 视为规则不能判断，交给模型                       |

反馈只包含儿童可读的文字和一个比例区域；网页用文本节点渲染，不执行 HTML，也没有任何字段能修改权限或进度。浏览器收到响应后再按共享 schema 检查一遍，画板另外校验区域边界。

## 前端

`requestTeachingFeedback` 发送前用同一个 schema 检查，不合规的请求不离开浏览器。`useTeachingFeedback` 复用 `createAiHelpRequest`：同一时间只有一个请求，超时、取消、失败、被服务端回退都以简短中文说明作答还在，之后选择提示继续，迟到的响应被忽略。`FeedbackRequestPanel` 提供「请 AI 老师看一看」和等待时的「不等了，用提示继续」；绘图反馈仍由画板在虚线框旁朗读。

## 自动化检查

- 领域：模型输出解析与降级、区域边界、规则结果校验、PNG 文件头。
- 服务与网关：规则优先、授权后才调用模型、受限上下文、结构化输出、图像不计入文字字节上限、输出上限与越界结算、未知题目与步骤。
- 路由：请求体限制、未知字段、同源与 JSON 头、未配置服务、错误消息。
- 前端：请求编码与分块、服务端回复校验、取消、状态机、面板各状态、模型文字作为纯文本显示。
- 数据库集成（`teaching-feedback.integration.ts`）：规则结论无需授权也不产生用量；无授权不触达供应商；授权后只向供应商发送步骤与提交内容；无法使用的回复仍结算用量。

## 未验证

- 没有真实 OpenAI 调用：提示词质量、`detail: low` 的图像 token 数、512 像素缩放后儿童笔迹是否仍可读、延迟都待首批真实题目接入时按 [ADR-0011](../../adr/0011-openai-tutoring-model-spike.md) 复测。超出 16,384 输入 token 的实际用量会被记为越界并停止本月后续调用。
- 题库为空，没有真实题目声明 `feedback` 与 `checkStep`；测试只用夹具。没有页面挂载画板与请求面板，面板只在 Storybook 和单元测试中展示，未在真实浏览器和移动设备上走通。
- 数据库集成测试需要隔离的 `education_test` 库；记录于此的是编写与类型检查结果，运行结果以 CI 为准。
