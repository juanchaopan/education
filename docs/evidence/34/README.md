# #34 作答与提示记录

依据 REQ-004、005、006 和 [ADR-0005](../../adr/0005-data-consistency.md)。接口按儿童会话和题目版本隔离，通过测试专用题目验证。真实题目的入口与逐题交互由 #49 接入。

## 逐题接入

- 服务端题目版本提供 `answering.checkCompletion`。这是本地同步判定，只检查完成整道题所需的证据。单步练习反馈仍由 `checkStep` 处理。能确定理解错误时返回 `incorrect`，证据不足时返回 `uncertain`。题目可以提交一个值、一个有序列表，或一组有名字的观察结果。
- 进入场景时用 `readAnswerRound` 取得本轮标识。通过 `requestHint` 请求题目配置的提示，收到回执后再展示对应的文字、语音或动画。帮助记录以轮次和提示标识去重，同一轮答错、证据不足、换设备或换作答 ID 都保留帮助记录。判定答对后开启新一轮。场景应把迟到的提示回执与当前轮次核对。
- 最终提交用 `prepareAttempt` 保存本次输入和关联的已保存草稿版本。网络故障时保留当前输入，并调用同一个 `submit()` 重试。收到 `uncertain` 后请孩子确认或换一种表达。收到轮次冲突后先刷新当前轮次，再请孩子确认下一步。
- #40 接入 AI 教学反馈时，反馈和权威作答保持分离。会实质帮助完成本题的后续 AI 提示应在展示前纳入服务端帮助记录。家长进度视图由 #35 接入，独立完成次数和提示后完成次数分别展示。

## 持久化与验证

`attempts` 保存作答 ID、轮次、结果和输入的带密钥摘要。请求正文仅用于内存中的规则检查。摘要使用已有服务端限流密钥及作答专用命名空间。轮换该密钥后，旧回执的重试会返回冲突，已提交的记录仍会去重。`help_events` 保存已请求的提示标识，`progress` 分别累计独立完成、提示后完成、确定错误、无法确定。

PostgreSQL 同一事务内写入作答、更新摘要并删除提交关联的草稿版本。重试只返回原回执，其他设备保存的新版本仍可恢复。提示、作答和草稿共用会话校验与题目锁。迁移为新增表，三张表启用行级安全；staging 加固同时撤销匿名和直接客户端访问权限。

隔离集成测试覆盖跨设备提示、提示与提交并发、相同作答并发、不同输入重用 ID、草稿清理失败回滚、不同儿童与题目版本、伪造结果与撤销会话。前端测试模拟回执丢失、提示冲突和回执 ID 错配。此次交付为 API 与数据接入层，真实场景的音画验收随 #49 执行。
