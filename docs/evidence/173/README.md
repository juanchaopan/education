# #173 探针证据：小兔从作者写的讲解清单里挑动画

- 问题：菜园题每一幕给模型一份作者写好的讲解清单（3–6 段，每段一句说明），模型能否按孩子的问题挑对一段，或在不合适时不挑；作答那一幕会不会连同讲解泄露答案；比只回文字慢多少、贵多少。
- 成功标准：挑对（含该不挑时不挑）≥ 85%；作答那一幕没有一条回答连同讲解直接给出答案；变慢的 p95 ≤ 1 秒。
- 日期：2026-11-10。只发送合成提问，不含任何真实儿童数据。

## 做法

- 模型与设置和应用一致：`gpt-6-luna`，流式 Responses API，`reasoning.effort: none`，`max_output_tokens: 256`，`service_tier: default`，`store: false`，10 秒超时。请求经过应用真实的 `createTutoringGateway`（`apps/api/src/ai/services/tutoring-gateway.ts`），授权与计量换成了不拦截的替身。
- 文字版（baseline）就是应用现有的 `feedbackTask`：材料是这一幕的作者步骤说明（`libs/problems/src/garden-balance.ts` 的 `gardenBalanceSteps`）加孩子的话。
- 讲解版（demo）在同一请求上只加两样：材料里加上这一幕的 `demos` 清单，说明里加一句挑选规则；结构化输出加一个 `demo` 字段，取值只能是这一幕清单里的 id 或 `null`（严格 JSON schema 的 `enum`）。
- 30 个问题（`spike/173/questions.ts`）覆盖七幕，含跑题 4 个、听不清 2 个、要答案 3 个。每个问题在调用前写好了可接受的选择。同一问题的两种请求先后交替，抵消服务商时延漂移。
- 共 60 次付费调用（讲解版 30 次、文字版 30 次），没有单独预热。费用按应用的单价常量 `usageCost`（输入 125、输出 500 纳美元/token）计算。

## 结果

| 指标                         | 讲解版                           | 文字版                            |
| ---------------------------- | -------------------------------- | --------------------------------- |
| 可用回复                     | 29/30                            | 30/30                             |
| 挑对（建议判定）             | 23/30 = 76.7%                    | —                                 |
| 挑对（按预设）               | 22/30 = 73.3%                    | —                                 |
| 完整回复耗时 p50 / p95 / max | 1541 / 2074 / 2689 ms            | 1312 / 1887 / 2329 ms             |
| 响应头到达 p50 / p95         | 481 / 823 ms                     | 484 / 712 ms                      |
| 同一问题两版相差 p50 / p95   | +177 / +770 ms（29 对）          | —                                 |
| 平均输入 / 输出 token        | 657 / 59                         | 404 / 53                          |
| 每次费用                     | US$0.000112（约 0.11 美元/千次） | US$0.000077（约 0.077 美元/千次） |

- 准确率：建议判定 76.7%，低于 85% 的标准。7 次错里有 4 次（#1、#11、#18、#29）是模型把孩子的提问当成看不懂的作答，改成只问一句澄清、不挑讲解；另有 6 次（#6、#7、#10、#13、#26、#27）讲解挑对了，文字却是反问，和动画不配合。原因在于讲解版沿用了作答反馈的说明（「看不懂时用 uncertain，只问一个澄清问题」）。
- 作答那一幕的泄露：讲解版 9 条回答连同讲解都没有说出或确认「九」，满足标准。作答那一幕挑中 `glow-groups` 7/9 次，有偏向清单第一项的迹象。对照的文字版在 #23 回答「对，右盘有3组、每组3根黄瓜……」，等于确认了孩子猜的答案。
- 耗时：讲解版 p95 比文字版多 187 ms，同一问题配对相差的 p95 为 770 ms，都在 1 秒以内。响应头到达时间相同，多出来的时间在于更长的输入和略多的输出。样本只有 29–30 个，p95 取的是第二慢的一次，只能看出量级。
- 费用：输入 token 多 63%，每次费用多约 45%，绝对值约每千次 0.11 美元。60 次调用合计约 US$0.0057。
- 清单约束：严格 schema 下没有出现清单外的 id。#9 的回复没能通过格式检查（原因无法从记录得知），应用会走降级提示。
- 应用自己的安全检查：#17 两版都标了 `injection: true`，应用会把文字换成通用澄清句；正式设计要决定这时讲解还放不放。

## 两段讲解原型

在真实的菜园舞台（`LessonStage` + `GardenScene`，同样的背景、道具和小兔）上做了两段可点的讲解，文字和讲解 id 用的是本次调用的真实结果：

- `demo-glow-groups.webm` / `.png`：作答那一幕，孩子问「太多了我数不清」，模型挑 `glow-groups`：三组黄瓜依次亮起，只圈不数。
- `demo-replay-weighing.webm` / `.png`：桥接那一幕，孩子问「我忘了一个苹果换几根黄瓜了」，模型挑 `replay-apple-cucumbers`：天平暂时回到那次称量，先只放一个苹果（歪），三根黄瓜出现后变平，再回到当前这一幕。

原型源码在 spike 分支的 `spike/173/proto/`。在仓库根目录运行 `npx vite --config spike/173/proto/vite.config.ts --configLoader runner`，打开 `http://127.0.0.1:6173/?demo=glow` 或 `?demo=replay`，点「播放讲解」。原型不显示片头，所以没有生成标题字体。
