# #19 双实例账号贯通验收

范围：REQ-002、REQ-007；使用 #17/#18 的真实注册和会话实现，不添加题目、邮件发送、儿童账号或公开诊断写入端点。本地隔离验证，不代表 Vercel、生产或中国大陆完整链路验收。

## 可重现命令与隔离

在仓库根目录，先 `npm ci` 并安装 Playwright Chromium，再执行 `npm run test:accounts`。需要 Node 24、Docker Compose v2、OpenSSL。已有本地 Chromium 时可临时设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`；CI 安装匹配的官方 Chromium。

运行器生成随机项目名、独立 PostgreSQL 密码、所有实例共享的认证限流密钥、一天有效的 localhost 证书；测试凭据不写入 Git 或报告。CA 公钥临时副本和 TLS 文件存于项目内的 `infra/.env.accounts-*`，由既有 Git/Docker `.env.*` 规则排除；CA 仍通过独立 BuildKit secret 挂载。该位置满足 Bake 文件读取边界，不增加额外主机文件授权。数据库是独立的 `education_accounts_test`，不接受外部 `DATABASE_URL`，不映射主机端口。只有 HTTPS 入口绑定主机回环地址，默认 8443 → A、8444 → B，可通过 `ACCOUNTS_PORT_A/B` 更换空闲端口。

这两个端口仅用于测试精确选实例；Origin 仍固定为 A 的 HTTPS 地址，未放宽同源校验。浏览器只在 A 操作页面，测试客户端通过 B 登录后共享同一个浏览器 cookie jar。自签名证书的忽略仅用于隔离 localhost 测试；镜像构建仍通过平台代理和临时 CA 挂载，保持 npm TLS 校验，运行镜像不包含平台 CA 或测试证书。

编排包含独立 `migrate` 服务；A/B 依赖其成功退出，不在应用启动时各自迁移。测试故意破坏初始迁移、修改隔离迁移记录、停止数据库；正常退出或测试失败时 finally 删除本项目容器、网络、测试卷和临时证书。Docker 构建缓存保留。强制终止运行器/宿主机时可能需要按本次随机项目名手动清理，勿使用全局 prune。

## 真实场景

1. 预先建立冲突表使迁移失败：普通启动被依赖条件阻止。仅测试中绕过依赖强启实例，存活 200、就绪 503、注册 503。删除测试冲突后，受控迁移成功；连续重复两次迁移不增加迁移记录。
2. 删除本版所需迁移的有效哈希标记时，两实例均就绪 503；恢复并加入模拟的较新迁移标记时均 200。检查的是所需迁移已应用，不要求它是最新一条；这不替代真实版本兼容与回滚演练。
3. A 注册、B 重复注册只留下一个家长；B 登录后 A 的真实页面显示同一待验证账号，刷新仍恢复。A 再登录轮换令牌后 B 拒绝旧 cookie；A 页面退出后 B 拒绝会话，数据库会话被删除。
4. 同一邮箱交替请求 A/B，前 10 次错误登录为统一 401；之后两个实例均为 429 并带 Retry-After，证明邮箱预算跨实例共享。
5. 页面填好注册资料后停止真实 PostgreSQL：两个实例存活仍 200，就绪与账号请求均 503；页面显示注册失败、保留邮箱和密码，不显示申请成功。恢复数据库后自动重新连接，就绪恢复 200；确认失败时未创建账号，再手动重试成功且只保存一个家长。
6. 验证临时证书目录被 Git 忽略，且实际运行镜像的 `/app/infra` 中不存在任何暂存的 CA/TLS 目录。

`/health/ready` 每次查询迁移记录，响应仅含 ready/unavailable 且 no-store；账号未启用、数据库连接失败或所需迁移未记入时返回 503。它信任受控 Drizzle 迁移记录，不是完整 schema 完整性扫描，也不证明邮件或 AI 正常。连接和 SQL 超时沿用账号池的 1 秒/3 秒限制；空闲连接的断开事件仅记录固定错误类别，不导致 HTTP 进程退出，不记录数据库地址、查询参数或异常堆栈。
