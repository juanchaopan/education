# 应用库和删除清单库统一放到 Neon

- 日期：2026-11-07
- 级别：L4 架构变了（数据库托管）；设计冲击 D0
- 来源：维护者：“staging 和生产的应用库、删除清单库统一放到 Neon（4 个免费项目）”

## 变了什么

之前 staging 应用库在 Supabase Free 项目 `telkaiyxprpetmqthyhn` 里，ADR-0008 把 Neon 列为没有选定的数据库候选，生产数据库没有确定。之后 staging 和生产的应用库、删除清单库共 4 个数据库，各用一个 Neon Free 项目，区域都是 Singapore，见 [ADR-0014](../adr/0014-neon-databases.md)。

staging 发布和每小时维护不再检查 Supabase 项目编号，按 `STAGING_DATABASE_HOST` 确认目标库，并要求清单库和应用库不在同一个主机上。

## 为什么

#44 要求删除清单放在应用库之外的独立数据库里。Supabase Free 每个账号最多 2 个免费项目，维护者账号已经用满，建不了清单库。维护者要求只用免费套餐，并把 4 个数据库放在同一个供应商；Neon Free 每个账号最多 100 个项目。

| 类别 | 内容                                                                                                                                                        |

| 需求 | 无；REQ-007、REQ-009 不变                                                                                                                                   |

| 代码 | `scripts/staging-release.mjs`、`staging-ledger-env.mjs`、`deploy-staging.mjs`、`cleanup-staging-mail.mjs` 及其测试；两个 staging 工作流；API 运行时代码不变 |
| 数据 | staging 只有合成账号，不迁移，新库上运行迁移；维护者重新注册测试账号。Supabase 项目是否暂停或删除由维护者决定                                               |

## 决定

- 4 个数据库各用一个 Neon Free 项目，区域都选 AWS Asia Pacific (Singapore)，和 Vercel 的 sin1 在一起。
- staging 目标库的检查改为不针对供应商的主机检查，不增加新的安全措施。
- 应用使用 Neon 直连地址和 `sslmode=verify-full`，证书变量留空。
- 生产的两个项目在 #52 准备发布时创建；#45 的独立备份不能只依赖 Neon 的恢复窗口。
