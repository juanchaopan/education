# 课堂流程清单与逐幕探究

- 日期：2026-11-12
- 级别：L2 需求变化；设计冲击 D2
- 来源：[#209](https://github.com/juanchaopan/education/issues/209)。维护者提出：手册、新题模板和公共题目页都默认同一种流程，语文阅读、解方程、高年级的逐步推导套用这个流程会别扭；菜园题的变化题先说出答案再提问，孩子的回答也没有记录。

## 变了什么

之前手册只有部件这一层：一道题选讲法和部件，课的骨架默认是一幕一幕动手发现、最后说出一个数、再做一道变化题。导入 PDF 时直接逐题选讲法和部件。

之后部件上面多了一层课堂流程。流程是一张清单，第一种是从菜园天平和彩铅配对提炼的「逐幕探究」；每道题由维护者先选流程，再选讲法、部件和背景。导入 PDF 时开始先问放进哪本书，新书再问封面，新科目先画科目图标、配底色。逐幕探究的变化题先猜、再动手、再说理由，最后揭晓，首答、理由和帮助分开记录。

## 为什么

- 不同类型的题，作答方式和判分方式不一样，一种骨架盖不住。
- 变化题先说出答案再提问，孩子答对多半只是复述，检验不出理解；回答没有记录，家长也看不到孩子能不能举一反三。
- 每幕的说明、旁白和结论分在服务端插件、网页台词稿和结论板三处，结论板、小兔的提问材料（#210）和自查卡要读同一份。

## 决定

- 定级 L2 + D2，拆成四份，另加家长摘要一份（维护者确认）。
- 变化题的顺序：先猜一个数作为首答 → 动手 → 说理由 → 揭晓；猜的数确认后只显示「记下了」，不说对错（维护者确认）。
- 说理由和最终作答一样开口说一句，麦克风自己打开；说不了话或连说两次判不出时，换成两排露珠点选（维护者确认）。
- 只用作者写的规则判；理由分说对、无法判定（不算错）、说反了（记为答错）（维护者确认）。
- 猜的数是首答；理由单独记一项；变化题有自己的 1–2 条萤火虫提示，作答时提问也算帮助；不存原话（维护者确认）。
- 揭晓以后，结论板在「假如」条后面接上它的结果（维护者确认，截图另行确认）。
- 新题模板加一幕最小的变化题（维护者确认）。
- 「一句话」形式的最终作答只写进手册，代码先只做整数（维护者确认）。
- 导入 PDF 时科目是新的，按网站视觉语言的图标规则画科目图标、配一组底色，出科目筹码和默认封面的截图给维护者确认，确认后加进科目表；科目表和默认封面由家长书架（#179）设计（维护者确认）。
- 每幕内容的统一声明放在 `libs/problems` 里浏览器可用的导出中；流程的代码名是 `scene-by-scene`；架构规则的说明从「答案只在服务器」改写成「判定规则只在服务器」（维护者同意的技术取舍）。
