# 课堂公共部件、全屏题目页与共用的绘景库

- 日期：2026-11-08
- 级别：L1 需求范围内的新功能；设计冲击 D2
- 来源：维护者：“我想搞一个背景图片库，让 OpenAI 一次性生成多张背景图片……每一道题目就任选一张图片作为背景”；“题目页面应该是要全屏的……上面有一个返回按钮”；“看一下 Spike 48 里面和……Staging 里面的这个题目有哪些界面元素是可以重用的……这样我用 /change 增加新的题目的话，它可以自动的去识别并应用这些公共代码”；以及菜园题旁白被跳过的缺陷 #129。

## 变了什么

之前每道题自己写短片推进、画面外壳、拖动和页面接线，菜园题是唯一的参考，新题照着复制；每道题单独生成一张背景；题目页显示在网站导航下面，孩子要靠浏览器的后退离开。

之后这些做成所有题目共用的部件，一道题只写台词、分镜规则、道具画法、判定规则和一份题目定义；背景和讲课角色从带标签的库里挑；题目页撑满屏幕，开始时请求全屏，左上角的返回按钮回到孩子来时的题库。逐题设计手册给出公共部件清单、新题模板和挑选规则，`/change` 加 PDF 题时按手册用上公共部件。

## 为什么

- #48 的三道原型和正式的菜园页各写了一遍同样的部件；接 #125、#126 时要复制几百行页面代码，同一件事出现几种写法。
- #129 的旁白缺陷出在逐句讲述里；只写在菜园题里时，每道题都要各修一次。
- 每题单独生成背景浪费生成次数，风格也不统一。
- 全屏后看不到浏览器的后退按钮，题目页需要自己的返回。

## 决定

- 定级 L1 + D2（维护者确认）。
- 公共部件放在网站的学习功能里，不单独做成 libs 包（维护者确认）。
- 题目页撑满屏幕，开始短片时请求浏览器全屏，返回时退出（维护者确认）。
- 讲课角色和背景一样建库（维护者确认）。
- 背景和角色在 Codex 里用 ImageGen 生成，不调用付费 API；第一批背景 12 张（低、中、高年级各 4 张）、角色 3 个（维护者在请求中指定背景的做法和数量；角色数量按每个年龄段一个）。
- #129 并入这个计划，排在 #125、#126 之前；原 #129 的「抽出公共代码」一步移到 #130。
