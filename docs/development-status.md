# 框架进度与后续工作

## 本阶段范围

已搭建：npm workspaces、Vite/React 中文应用外壳、空题库 API、家长空间空状态、PostgreSQL/Drizzle 初始迁移、类型与依赖边界检查、单元和真实数据库测试、Storybook 与 Playwright 功能检查、容器配置和 CI/审查文件。

尚未实现：家长注册/验证/恢复、儿童 KEY 兑换和登录、会话与家庭授权、学习记录、练习安排、草稿服务、家庭导出删除、AI/语音调用，以及每题专属页面。初始 schema 只包含 families、parents、children、registration_keys、drafts；尚不包含架构里规划的全部表。数据库约束不等于服务端家庭授权。

不能把本阶段称为完整产品或已完成账号验收。空题库不展示演示问题，不伪造学习进度。

## 交付前置条件

- 先实现并验证账号链路及家庭隔离，再接入儿童真实输入。
- 邮件服务、托管平台与 AI 资格未验证；大陆访问必须真实端到端测试。
- 付费 AI 配置默认开启；当前没有供应商调用，不产生模型费用。
- PR CI、审查配置在仓库有文件不等于 GitHub 设置已生效；GitHub API 当前被平台拒绝。未创建 PR、未修改分支保护或仓库设置。
- Claude 审查与云端协作需维护者自行配置 GitHub App、凭据及 ENABLE_CLAUDE_REVIEW=true；默认不运行付费审查。此开关与应用付费 AI 开关不同。
- 正式截图基准必须在固定官方 Playwright 镜像中建立和评审；本环境镜像下载被拒绝，当前无像素回归基准。
- 生产发布工作流留待实际平台确定；不会生成缺少真实部署目标的假发布步骤。架构仍要求 staging 隔离和生产手动发布。

## 建议开发顺序

1. 身份与家庭：邮箱注册/验证/恢复、会话、单次 KEY、儿童 PIN、限流、重置与撤销、越权/并发测试。
2. 题目扩展契约与进度：保持空正式题库，用隔离测试夹具验证版本、作答幂等、家长选题。
3. 草稿 7 天清理、恢复冲突、导出与家庭删除；明确备份和删除时限。
4. 供应商与部署 spike：大陆访问、邮件送达、AI 条款与后端调用、token 控制、中文语音兼容性。
5. 收到真实题目后逐题设计教学方式，验证错误定位、耐心提示与独立理解。

下一工作流为 roadmap：把上述工作拆成可评审的小任务，不将未完成能力写为已实现。
