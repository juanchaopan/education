# Spike #15：账号安全参数与儿童登录

- 状态：验证中；结论待维护者选择，正式账号尚未实现。维护者补充确认儿童持久登录、发布后更新页面，见下方修订。
- 问题：家庭码定位 + 昵称/6 位 PIN，在 10 家庭、3 儿童同时使用的试点中，如何确定可负担的哈希、令牌、会话和限流参数？
- 时间盒：45 分钟；2026-11-04 开始。范围由 issue #15 规定，维护者确认默认 6 位 PIN。
- 通过：比较至少 3 档 Argon2id；每档串行与 3 并发，预热后每组至少 30 次；给出 P50/P95/最大值、进程 RSS、环境与限制。选定档位本机哈希 P95 < 500ms，带两槽准入的 3 并发 P95 < 1s。明确家庭码不是凭据、同名隔离、低熵风险与恢复、过期/撤销、来源校验和跨实例限流规则。
- 失败：无可用哈希实现或候选均不达标；任何规则仍允许无 PIN 访问/跨家庭匹配；部署资源无数据时必须保留目标复测，不得声明上线可用。
- 不验证：真实邮件投递、正式 PostgreSQL 事务、Vercel 打包/冷启动、目标设备 UX、大陆性能、完整认证或生产部署；不建立真实账号、不收集真实 PIN。
- 形式：独立脚本；所有凭据均为合成夹具或进程内临时随机值。此分支不可合并；决策后仅 ADR 与证据通过独立 PR 合入。

32 MiB 两槽峰值进程 RSS 97.52–97.75 MiB；不含平台宿主、数据库或其他函数进程。64 MiB 三并发峰值 225.65 MiB。19 MiB 的 RSS 约 109 MiB 反而高于部分 32 MiB 组，属于本机分配器/线程与高水位结果，不能用这些值证明内存线性或配置的部署内存上限。

### 拟定默认参数

以下参数为设计提议；六位 PIN、昵称登录、单次 KEY、家长恢复，以及儿童默认持久登录和发布后刷新已获确认。持久 cookie 的具体期限是实现默认值，不能表述为维护者指定的天数。

| 项目         | 提议                                                                                                                                                                                                                                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 家庭定位码   | 12 位安全随机 Crockford Base32（60 bit），唯一约束、分组显示；**不是访问凭据**，不能据此列出孩子或显示家庭信息                                                                                                                                                                |
| 昵称         | 家庭内唯一，可跨家庭重复；NFKC、trim、Unicode lowercase 后唯一，1–12 个字母/数字 Unicode 码点，展示昵称与规范化字段分开                                                                                                                                                       |
| 登录         | 首次输入家庭码 → 昵称 + 6 位 PIN；儿童默认保持登录，后续访问由持久 cookie 恢复；无登录前孩子列表，家庭码/昵称不存在和 PIN 错误同一回复                                                                                                                                        |
| 儿童 PIN     | 6 位 ASCII 数字，允许前导 0，拒绝全相同和明显顺/逆序；提示“换一组不容易猜到的六位数字”，不用责备或惩罚文案                                                                                                                                                                    |
| PIN 离线保护 | 独立部署密钥 `PIN_PEPPER`，至少 32 随机字节，不进数据库/日志/仓库；HMAC-SHA256(版本、familyId、childId、PIN 的无歧义编码) 后 Argon2id；哈希记录 pepper 版本；缺密钥停止 PIN 注册/验证，不回退无 pepper                                                                        |
| pepper 轮换  | 短期保留受控旧版本，在成功登录后迁移；旧版本泄漏时撤销相关儿童会话并由家长重置；失去全部旧密钥只能重置，不能解密 PIN                                                                                                                                                          |
| 家长密码     | 15–128 Unicode 码点、最多 512 UTF-8 字节，允许空格、粘贴与密码管理器，不 trim/截断，不强制字符组合；本地常见密码拒绝清单，Argon2id 同一参数档                                                                                                                                 |
| 注册 KEY     | 16 位随机 Crockford Base32（80 bit），分 4 组；仅生成时显示，SHA-256 存储，24 小时、单次使用；每家庭最多 1 个未消费 KEY，重发撤销旧 KEY；只有已验证且近期重认证的家长可生成                                                                                                   |
| 会话         | 32 字节随机 opaque token，SHA-256 存储；家长空闲 12h / 绝对 7d；儿童取消 7 天强制退出，采用 180 天不活动期限、有效访问后自动顺延，无另设绝对 7 天期限；服务端检查撤销/凭据版本/期限；未验证家长只有 15 分钟受限会话，无 KEY/儿童/学习数据权限                                 |
| cookie       | HTTPS `__Host-education_session`，Secure / HttpOnly / SameSite=Lax / Path=/，不设 Domain；儿童 cookie 显式 Expires/Max-Age（180 天），活动时续期以便关闭浏览器后恢复；数据库期限同步更新；不把 PIN/会话放 localStorage，登录/提权换令牌，退出立即撤销；共享设备切换用户先退出 |
| 近期重认证   | 最近 5 分钟家长密码校验才可生成/撤销 KEY、重置孩子访问、导出/删除；不只依赖 cookie 年龄；密码恢复撤销全家庭会话和有效 KEY                                                                                                                                                     |
| 邮件令牌     | 验证 24h、密码重置 30min，均 32 随机字节、SHA-256 存储、单次使用；发新令牌撤销同用途旧令牌；重置申请通用回复，实际投递和额度由 #16 验证                                                                                                                                       |

儿童账号、家庭关联与进度没有 7 天期限；注册 KEY 仅首次注册用，cookie 到期不会要求家长重新发 KEY。长期不活动、退出、家长重置或清理浏览器 cookie 后才需原家庭码/昵称/PIN；正常部署不能改变凭据版本、清空会话或要求重新注册。持久登录不保证隐私模式或浏览器主动清理后仍有效。

PIN 约 20 bit，规则与 Argon2id 不能把它变成长密码。pepper 只防数据库单独泄漏，不能防应用与密钥一起泄漏；家长恢复、儿童权限最小化与严格在线限流不可省略。昵称/家庭码存本机仍有隐私代价，父母应能清除，正式 UX 待真实设备验证。

### 准入、枚举和跨实例

| 范围                  | 提议上限（所有参数待维护者采用）                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 儿童家庭码+规范化昵称 | 5 次/滚动 15 分钟，20 次/滚动 24 小时；每次允许的验证在哈希前预占，成功也计入；不依赖来源 IP，不永久封禁                                                 |
| 家长规范化邮箱        | 10 次/15 分钟，50 次/24h；恢复通道独立限流，不能绕过密码与邮件验证                                                                                       |
| 家庭                  | 全部认证合计 50 次/15 分钟、200 次/24h，避免单家庭攻击影响其他家庭                                                                                       |
| 来源                  | 30 次/15 分钟、200 次/24h；仅信任受控入口转发地址，IPv6 以 /64 聚合，验证共享出口误伤情况                                                                |
| 试点部署总量          | 100 次/15 分钟、500 次/24h；作为资源保险丝；未知账号同样计入来源与全局预算                                                                               |
| KEY                   | 生成每家庭 5 次/小时、20 次/日；兑换每 KEY 5 次/15 分钟，来源 10 次/15 分钟、50 次/日，再应用全局限制                                                    |
| 哈希并发              | 每进程最多 2 执行 + 4 等待；等待最多 750ms，满/超时立即 429 + Retry-After，无自动重试洪峰；进程间通过 PostgreSQL 总计 4 个租约限制，实例扩容不扩大总预算 |

所有窗口使用 PostgreSQL 服务端时间，在同一短事务中按固定锁顺序预占预算、取得租约；不能每实例独立计数。哈希在事务外执行，结束后释放租约；租约 30 秒，部署必须强制在 15 秒内终止执行，不能只用 Promise 超时后让原生任务继续运行并释放槽位。达不到硬终止条件时重新设计租约续期，不能声称严格全局并发。数据库不可用时认证返回 503，不跳过限流或授权。缺失/异常 Origin 拒绝写入，精确匹配服务端配置的同源 origin；不从 Host/任意代理头推导可信域名。

未知家庭/昵称/邮箱：准入后执行同档有效 dummy hash 验证，回复相同错误形状，不列出匹配账户；同样的键也执行限流。哈希相同成本不等于已证明网络时序不可枚举，数据库命中、缓存和成功响应仍需实际 HTTP 检查。限流键使用独立 HMAC 密钥伪名化，计数最多保留 25h；先检查来源/全局预算再建立账号桶，避免无限随机昵称造成数据库膨胀；不记 PIN、KEY、cookie、原始邮箱或完整请求体。

账号桶限流存在攻击者耗尽他人额度的拒绝服务风险；家长经独立验证通道重置 PIN、撤销旧会话并清除该孩子计数，不允许孩子/客户端清零；不在儿童页面加困难验证码。次数限制影响登录尝试，不影响已登录儿童反复学习或错误作答。

### 正式实现必须满足的事务和 HTTP 条件（本次未验证）

- KEY 有效性条件更新、同家庭昵称唯一约束、创建儿童与消费 KEY 在一个事务内完成；昵称冲突/数据库失败全部回滚，不烧掉 KEY。幂等请求 ID 绑定原请求内容，同一 KEY 重放不创建第二个孩子，也不因旧幂等键签发新会话；响应丢失后可用家庭码+昵称+PIN 登录。
- PIN/密码重置更新 credentialVersion 并撤销目标会话；每次授权校验版本/有效期/家庭。哈希验证后签发会话还要事务核对最新版本，防止重置与登录竞态留下新旧凭据会话。家长密码恢复增加家庭 epoch 并撤销全部家庭会话/KEY。
- 已登录写操作要求随机会话绑定 CSRF token（前端内存，通过自定义 header 发送）与精确 Origin；登录/注册也只接受 JSON + 固定自定义请求头，拒绝跨源 CORS 及表单简单请求，防登录 CSRF。GET/HEAD 不写业务数据。旧/缺失 Origin 浏览器不能静默放行，要在 #28/#47 真机验证。
- #17/#18/#21–26 用真实隔离 PostgreSQL/Fastify/浏览器证明并发兑换、所有限流桶原子预占、租约崩溃回收、重置/登录竞态、跨家庭授权、session fixation、退出、重认证和邮箱链路。不能把本探针的内存模型用作事务或完整认证证明。

## 维护者修订：记住登录与部署刷新

2026-11-04 用户明确要求：“their browser should remember the password so that they don't have to login every time”，以及发布新版本后刷新页面，不能总使用旧缓存。这取代先前儿童 24h 空闲/7d 绝对会话的提议；不改变家长敏感操作需要近期重认证，也不把本次澄清当作用户接受其他尚未确认参数。对探针增加一次最多 15 分钟的规则修订验证；不重复哈希基准。

- 用户体验：儿童首次登录后默认保持登录，关闭并重开浏览器、刷新页面、更新应用后继续原儿童账号；通过安全持久会话实现，不由应用保存原始 PIN。首次表单可正确使用密码管理器的 autocomplete；家长能退出或撤销设备会话。180 天是“不活动后需要再次登录”的技术默认值，有效访问不断顺延，不能当作学习时间/账号/进度期限。
- 更新触发：成功部署一个新 release 才更新页面，单纯 git push/创建 PR 不代表新版本上线。前端入口 HTML 用 Cache-Control: no-cache 重新验证；公开 /version.json 用 no-store，客户端 fetch cache:no-store；带内容哈希的 JS/CSS 可长期 immutable 缓存；私人 API 响应 no-store，不全站禁用正常静态资源缓存。
- 已打开页面：可见时每 60 秒、页面恢复可见/聚焦、网络恢复时检查 releaseId；同版本不刷新，不可达或返回无效数据时保留当前页面、退避重试，不循环刷新。不安装 cache-first service worker；若以后引入离线缓存，必须另行设计更新迁移。
- 新版本就绪：首次打开正常获取已部署 HTML；旧页面发现版本变化后先完成/确认草稿持久保存，再自动完整 reload；保存失败、离线或有未解决的版本冲突时保留原页面和输入，显示“更新已准备好，保存后将自动更新”，不能先刷新丢掉绘图。无未保存输入时直接更新，成功更新后仍用现有 cookie 恢复登录。
- 一次更新只尝试一次自动 reload，启动时比对当前 JS 构建 ID 与实际版本；若 CDN/版本文件不同步、旧 hashed chunk 已删除或新部署不可用，显示明确的重试状态，保留草稿与会话。版本文件/构建 ID 应由同一次部署生成，并在验收中模拟切换和回滚，不能靠不一致的轮询无限刷新。
- 正式实现分工：#18/#22/#23 实现持久 cookie、跨重启恢复和撤销；#20/#52 配置部署 ID 与缓存头；#33/#47/#51 验证草稿保护、已开页面更新、缓存命中和更新后仍登录。这些不是本次已经实现的正式功能，也不是已通过的浏览器/部署测试。

修订后的规则模型验证长期活跃会话跨越 7 天/一年而不输入 PIN、180 天不活动边界、退出/重置撤销；应用构建 ID 不作为会话失效依据。该内存模型不能证明真实浏览器持久 cookie、自动刷新或缓存行为，正式验收必须补浏览器关闭重开、真实缓存与双版本发布测试。
