# Spike #27：OpenAI 模型成本和可用性

问题：哪个能接收文字与绘图的 OpenAI 模型，以最低的实测用量成本，在 5 秒内给出适合儿童的有效中文提示？

- 时间盒：一轮模型对比，每个模型四个合成场景各三次；最多加一轮以排除运行故障。
- 判据：文字解释、含误区的推理、清晰图形和不确定图形均给出与题目相关的下一步或澄清问题。成功样本的首个有效中文句子 P95 不超过 5 秒。单次 10 秒上限；错误、超时、被截断、空回复和误判单列。
- 测量：服务端 HTTPS 请求至流中第一条完整中文句子（随后人工核验有效性）。记录首文字、首句、结束耗时与 API 用量。每种场景的三次样本按三并发执行，结果是小样本比较。
- 范围：仅合成输入，GitHub Actions runner 上的 Node.js 24 服务端脚本。目标部署和大陆设备全链路延迟、真实儿童输入、模型正式上线及地区资格不在本次实测范围。
- 运行：专用分支推送触发 GitHub Actions，读取已授权的 `SPIKE_OPENAI_API_KEY`。也可在已安全配置该变量的受支持环境运行 `node spikes/27-openai-models/benchmark.mjs`。
- 预算：标准模式，无工具、无额外历史、无自动重试，每次最多 128 输出 token。测试同一固定合成图像大小和一张图上限。取消样本不假定零计费。不会主动耗尽账户额度。

候选为 `gpt-5.4-nano`、`gpt-6-luna`、`gpt-4.1-mini`，分别覆盖廉价推理、当前高性价比和无推理延迟的基准。视觉输入用于理解儿童的绘图。图像生成不参与教学反馈比较。
